# План развития обвязки

> Статус: действует · Дата аудита: 2026-11-12 · Проверенное состояние: ветка `feat/monorepo-foundation`, коммит `0c6fe45`
> Для кого: агенты и люди, которые развивают сам шаблон.
> Правила, которым должно соответствовать любое изменение: [architecture.md](architecture.md). Номера вида З3 ссылаются на законы из её первого раздела.

## Где задачи

Задачи развития живут на доске `backlog/` — один файл на задачу (ADR 0007, перенесены задачей D6). Доска читается командой `pnpm backlog` (`next`, `start`, `resume`), протокол — в разделе «Начало сессии» в `AGENTS.md` и скиле `task-board`. Статус в файле не хранится, а вычисляется: ветка `task/<id>` — в работе; незакрытые `depends_on` или заполненное `needs_human` — ждёт человека (вместо пометки 👤); путь из `touches` попадает под `deny` из `tools/protected-paths.json` — нужен режим обслуживания (вместо пометки 🔒). Порядок задают `priority` и `depends_on`.

Часть A — дыры в гарантиях, часть B — качество и масштаб (по мере роста команды и кода), часть C — недостающие возможности (по потребности), часть D — параллельная работа агентов и распространение шаблона. Демо-домен намеренно мал, но шаблон содержит образец для областей, где сгенерированный код ошибается чаще всего: данные, доступ, окружение, состояния интерфейса. Каждая возможность приходит вместе с гейтом, который удерживает образец.

## Итог аудита

Скорость уже отличная. Слабое место в другом: несколько гейтов можно обойти, а несколько не ловят то, ради чего созданы. Для системы, смысл которой в том, что агент не может ослабить проверку, это главный долг.

Что сделано хорошо и должно сохраниться:

- Один вход `pnpm verify` с режимом `--json`, шаги идут параллельно.
- Contract-first: один контракт для фронта, бэка и OpenAPI, дрейф ловится гейтом.
- Границы модулей заданы правилами dependency-cruiser, а не договорённостью.
- Сообщения гейтов говорят агенту, что делать и чего не делать.
- Supply-chain настройки pnpm: строгий каталог, задержка свежих релизов, запрет install-скриптов.
- Единый список защищённых путей для хука и CI.

Замеры (macOS, 16 ядер, демо-домен): `pnpm verify` с кэшем 0.8–1.0 с. Без кэша: typecheck 0.4 с, unit 1.4 с, сборка 0.7 с, E2E 2.5 с, перф 5.2 с, мутации API 2.3 с при счёте 100% (66 мутантов). CI на GitHub в рамках аудита не запускался.

Все утверждения проверены чтением кода или прогоном; доказательства задач теперь живут в файлах доски. Там, где вывод опирается на документацию или вторичный источник, это сказано явно.
