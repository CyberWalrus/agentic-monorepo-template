# Изоляция integration-тестов на Postgres (c1.4)

Как integration-тесты API работают с настоящим Postgres параллельно и без взаимного влияния. Фича копирует этот паттерн со своими параметрами, а не придумывает свою схему. Хелпер: [apps/api/test/test-database.ts](../apps/api/test/test-database.ts).

## Схема: база на воркер из шаблона

```
контейнер postgres (один на прогон, имя agentic-pg-test-…)
├─ template_<key>   ← миграции применяются один раз, подключений 0
├─ w_<pid>_<rand>   ← база воркера A: CREATE DATABASE … TEMPLATE
└─ w_<pid>_<rand>   ← база воркера B: не видит данные A
```

- **Воркер — тестовый файл.** Vitest гоняет файлы параллельно (fork на файл), каждый файл получает свою базу из шаблона. Схема рассчитана на параллельные fork-воркеры — отключать `fileParallelism` для integration-файлов нельзя (файлы сериализуются, но их базы останутся изолированными). Чистка таблицы (`db.delete(...)`) в одном воркере не задевает соседа, поэтому локи вроде `SHARED_DATA_LOCK` на этом уровне не нужны — лок остаётся механикой E2E (снимет задача c1.5, изоляция E2E по рабочему пространству; задачи доски в проект из шаблона не едут, поэтому без ссылки).
- **Миграции один раз.** Владелец (воркер, заставший отсутствие живого экземпляра) стартует контейнер, применяет миграции к базе-шаблону и закрывает её подключение: клонирование `TEMPLATE` требует нуля подключений к шаблону.
- **Контейнер один на прогон.** Жизненный цикл ведёт refcount в файле состояния: последний закрывший воркер останавливает и удаляет контейнер. Ryuk-реапер testcontainers отключён (`TESTCONTAINERS_RYUK_DISABLED` в хелпере) — иначе он гасил бы контейнер через ~10 с после выхода создавшего процесса под живыми соседями.
- **Fingerprint от миграций.** Состояние экземпляра хранит хэш(образ + содержимое `migrations/**`): смена миграций → контейнер пересоздаётся, шаблон не протухает.
- **Координация** — mkdir-мьютекс + PID-файл в каталоге координации (`os.tmpdir()/agentic-pg-<hash пути репо>`, права 0700): два worktree не пересекаются (З9). Мёртвый или кривой лок (PID не существует, файл нечитаем) ломается следующим воркером. Удаление контейнера по id из state-файла сверяет имя контейнера: подменённый state не приводит к удалению чужого контейнера.

## Как использовать в фиче

```ts
import {
  createPostgresTestDatabase,
  POSTGRES_TEST_IMAGE,
  type PostgresTestDatabase,
} from '../test-database.ts';
import { migrateTaskDatabase, myMigrationsFolder } from '../../src/<module>/database.ts';

let database: PostgresTestDatabase | undefined;

beforeAll(async () => {
  database = await createPostgresTestDatabase({
    image: POSTGRES_TEST_IMAGE,
    migrationsFolder: myMigrationsFolder, // экспорт из database.ts модуля — один источник пути
    migrate: migrateTaskDatabase,
  });
}, 120_000); // таймаут на уровне файла: **/vitest.config.ts защищён

afterAll(async () => {
  if (database !== undefined) {
    await database.close(); // DROP DATABASE + refcount--; последний закрывший останавливает контейнер
  }
});
```

Образ `POSTGRES_TEST_IMAGE` закреплён по digest (решение c1.2: прогон воспроизводим). Новый модуль с собственной схемой миграций получает свой контейнер и свой шаблон — ключ экземпляра считается от образа и каталога миграций, экземпляры не конфликтуют.

## Диагностика

- **«Не удалось запустить контейнер Postgres…»** — нет Docker. Запусти Docker и повтори; тест не пропускается (`.skip` запрещён).
- **Остался контейнер после прерывания прогона** (воркера убили посреди работы): если state-файл в каталоге координации остался, следующий прогон **переиспользует** контейнер (ping + fingerprint), но refcount уже завышен — контейнер после прогона не остановится, останавливай вручную: `docker rm -f agentic-pg-test-…`. Без state-файла прогон уберёт мусор сам.
- **«Не дождались лока координации»** — идёт параллельный прогон того же worktree; дождись его окончания.

## Отклонённые альтернативы

- **PGlite** (Postgres в процессе, без Docker) — отклонён в c1.2/c1.4: неполный движок (расширения, блокировки, параллелизм); тесты шли бы против одного, production — против другого. Условие возврата: требование Docker стало узким местом локального цикла.
- **Контейнер на каждый тестовый файл** (паттерн c1.2) — проще, но каждый файл тянет свой контейнер и миграции. Условие возврата: координация общего контейнера стала обузой поддержки или integration-файлов стабильно ≤ 2 — решение за человеком в PR.
- **`globalSetup` для контейнера** — невозможен: `**/vitest.config.ts` защищённый путь (З6), контейнер стартует из тестового кода.
