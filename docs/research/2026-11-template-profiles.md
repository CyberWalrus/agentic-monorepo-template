# Опциональные части шаблона: что можно убрать и какой ценой

Задача e6. Дата: 2026-11-21. База: `main` @ `e05f8605`.

Вопрос задачи: где форма «web + api + Postgres + визуальные тесты + перф-бюджеты» зашита жёстко и что сломается при удалении каждой части. Позиция до исследования (файл задачи) — «гейты выводят состав из workspace + инструкция удаления», а не профили Copier. **Исследование позицию подтвердило** (таблица поломок ниже); ADR 0008 менять не нужно — минимализм «два вопроса» подтверждён, для workspace-гейтов нового ADR не требуется (это не смена архитектурного подхода, а закрытие дыр существующих гейтов).

## Метод

Чтение названных в задаче файлов + **прогоны, а не только чтение**: локальный `git clone` checkout @ `e05f8605` в `/tmp`, в копии по очереди удалялась одна часть, `pnpm install`, `pnpm verify --json` (fast-волна, 15 шагов), точечные прогоны slow-шагов и CI-команд (`pnpm bundle`, `turbo run build --filter=…`, `turbo run mutation --dry=json` и реальный, `vitest run --project visual`, `playwright test --project=visual --list`).

Стена «install падает» — тоже результат: она стоит **до** гейтов, и для продолжения эксперимента `e2e/package.json` правился вручную (удаление workspace-зависимости) — так же действует потребитель, вырезающий часть руками.

## Что должно краснеть, но молчит (дыры)

1. **Mutation-гейт выключается тихо (главная дыра, З2/З5).** `turbo run mutation` без единого пакета с задачей — exit 0, job `mutation` зелёный, `gate` зелёный. Удаление `apps/api` агентом сегодня не оставляет в PR ни одного красного сигнала о выключенном мутационном тестировании. Ловят только ночи: канарейки пишут в `apps/api/src/` (упадут) — но nightly не гейтит PR. Обязан краснеть: «в workspace нет ни одного пакета с задачей `mutation`» (и по той же логике `e2e`, `test`, `build`).
2. **Храповик test-count слепнет молча.** Запись базлайна для исчезнувшего отчёта пропускается без WARNING (`check-test-count.ts:244-246`), а сверка с merge-base не видит удаления, потому что сам файл базлайна не менялся. По духу того же файла («битый базлайн — WARNING: храповик не имеет права молча ослепнуть») отсутствующий отчёт из базлайна должен предупреждать.
3. **E2E в PR с `--affected`.** Пустой dry-граф = зелёный «docs-only» (`check-test-report.ts:324-330`); конвенция не различает «docs-only PR» от «e2e-пакет удалён». В merge queue/push (без `--affected`) пустой набор красный — там дыры нет.

## Варианты (из задачи) и решение

| Вариант                                                              | Вердикт    | Почему (факты прогонов)                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------------------------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Условные части Copier (вопросы + `_exclude` по ответам)              | **против** | каждый вопрос умножает комбинации, которые должна проверять канарейка копии (d8.3); `REQUIRED_IN_COPY` (`check-template-copy.ts:47-59`) жёстко требует оба приложения — любой профиль красит ночную канарейку до её переделки; ADR 0008 сознательно оставил два вопроса, качественной проверки N комбинаций копий нет |
| Отдельные ветки-профили                                              | **против** | divergence при `copier update`, каждое изменение гейта приходится повторять в каждой ветке-профиле; канарейка копии копирует одну форму                                                                                                                                                                               |
| **Гейты выводят состав из workspace + документ «как удалить часть»** | **за**     | прецедент уже в репо: docs-гейт сверяет `--filter` со workspace (`check-docs.ts:114`); knip уже ловит catalog-записи и knip.json-хинты; turbo громко падает на `--filter`/`bundle` — остаётся закрыть три тихие дыры из предыдущего раздела; форма остаётся одной, канарейка копии не усложняется                     |

Решение не меняет ADR 0008 (распределение шаблона — по-прежнему одна форма, два вопроса). Задачи на доску по каждой закрываемой дыре: **e20** (обязательные turbo-задачи присутствуют в workspace — красный при нуле), **e21** (test-count WARNING на отсутствующий отчёт базлайна), **e22** (документ «как удалить часть шаблона» — чек-лист из таблицы выше). e20 и e21 трогают deny-пути (`tools/verify-steps.ts`, `tools/check-test-count.ts`) — это задачи режима обслуживания, ведёт оператор (ADR 0009).

## Инструкция «как удалить часть» сегодня (черновик для e22)

- **web**: удалить `apps/web`, убрать `@repo/web` из `e2e/package.json` и `knip.json` (`workspaces`, e2e `ignoreDependencies`), убрать react-записи из `catalog:`, поправить README-команды; смириться с `--full`: bundle/bundle-delta/perf/visual/e2e CI-jobs потребуют перестройки CI (задача оператора, не ручная правка).
- **api**: то же симметрично (`@repo/api`, stryker/testcontainers/pg/drizzle из catalog, `docs/test-database-isolation.md`); **сегодня после этого mutation в CI зелёный молча — до e20 так делать нельзя**.
- **Postgres**: удалить `src/tasks/{database,postgres-repository,schema-sync*,schema}.ts`, `migrations/`, postgres-тесты, `drizzle.config.ts`, `db:*` scripts, deps и catalog-записи; проводку `server.ts` свести к `InMemoryTaskRepository`; docs-гейт красный на `docs/test-database-isolation.md` — файл удалить/переписать. API и без этого работает in-memory (`DATABASE_URL` не задан).
- **Визуальные тесты**: удалить `*.visual.ts`/`*.visual.test.tsx` и `visual-frame.tsx`; базлайны `__screenshots__` под deny — удалять только через режим обслуживания; CI visual job погасить отдельно (иначе «no tests found» красит).

## Что не проверялось

- Сценарий «удалены все пакеты с задачей `test`» (вплоть до зелёного/красного `test:report` без `--affected`) — за пределами четырёх удалений задачи; поведение чекера описано по коду (`check-test-report.ts:324-330`), не прогоном.
- Поведение merge queue (`merge_group`) — контур не включён (docs/research/2026-11-ci-timing.md: «0 прогонов»), выводы о нём — из кода ci.yml, не из прогонов.
- Docker-прогоны `pnpm visual` в копии — только host-проверка exit-кодов проектов (гвардия образа, З4/A8, блокирует host-запуск по построению); поведение CI visual job при нуле тестов подтверждено exit-кодом vitest-проекта и кодом `visual-inner.sh`, не полным прогоном в контейнере.
