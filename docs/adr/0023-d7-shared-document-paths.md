# ADR 0023: Мягкие пути D7 — общий документ объявляется в touches, но пересечением не считается

- Статус: предложено (принимается merge этого PR человеком)
- Дата: 2026-11-24
- Контекст: [ADR 0007](0007-task-board.md) (D7 — запрет захвата при пересечении `touches`; поправка 2026-11-23 — общие пути), [ADR 0009](0009-operator-delegation.md) (очерёдность операторских задач, «Пороги»), [architecture.md](../architecture.md) (3.11, раздел 4, З9), [реестр пропущенных дефектов](../escaped-defects.md), задачи e72 (`backlog/done/e72.md`; каталог `backlog/` исключён из копии шаблона, поэтому не ссылкой) и d7 (`backlog/done/d7.md`).

## Проблема

D7 запрещает захват задачи, если её `touches` пересекаются с `touches` любой задачи в работе. Причина запрета — d7 (`backlog/done/d7.md`): три и более конфликта слияния между задачами доски за 30 дней; среди четырёх событий — конфликт закона З5 в `docs/architecture.md` (a6, 2026-11-18) и конфликт в `AGENTS.md` (e1 и e13, 2026-11-20). Запрет оправдан там, где слияние нетривиально, — в коде. Для общего документа конфликт стоит одного слияния, а запрет отвечает очередью.

`docs/architecture.md` — незащищённый документ (класс `null`) с законами обвязки. Раздел 4 `architecture.md` требует обновлять его тем же PR, поэтому его объявляли в `touches` 16 открытых задач (main 77323543). После мержа любой из них следующий захват запирает остальные — независимо от того, какие разделы каждая правит. Замер независимого ревью 2026-11-24 03:20 MSK (задача e72): из 33 открытых задач вне работы D7 блокирует 25; держат очередь e35 — 15 задач через `docs/architecture.md` и e45 — 13 через условное замыкание гейт-контура.

Для реестра `docs/escaped-defects.md` такая очередь решена списком `SHARED_PATHS` ([поправка 2026-11-23 к ADR 0007](0007-task-board.md#поправка-2026-11-23-общие-пути-вне-пересечения-touches)): файл считается лежащим в `touches` любой задачи, объявлять его не нужно. Для `docs/architecture.md` это не подходит: реестр append-only, а правка законов обвязки обязана оставаться объявленной. Иначе задача меняет закон без записи в `touches`, и гейт `branch-scope` этого не видит (З2).

## Решение

Два вида общего пути. Оба списка — константы `tools/backlog-board.ts`; читает их один модуль: захват (`touchesOverlap` — `start`, `next`, `next --operator`) и гейт `branch-scope` (`fileInTouches`).

| Вид         | Список                                        | Объявлять в `touches` | Пересечения                               | `branch-scope`            |
| ----------- | --------------------------------------------- | --------------------- | ----------------------------------------- | ------------------------- |
| Общий путь  | `SHARED_PATHS` — `docs/escaped-defects.md`    | не нужно              | не создаёт ни с кем                       | разрешён любой задаче     |
| Мягкий путь | `SOFT_OVERLAP_PATHS` — `docs/architecture.md` | обязательно           | не создаёт только с другой мягкой записью | только если путь объявлен |

- **Счёт пересечений.** Пара двух мягких записей пересечением не считается — обе задачи объявили документ. Остальное считается как до этого ADR: мягкая запись не маскирует остальные пути, `docs/other.md` × `docs/other.md` — пересечение. Общие пути, как прежде, не пересекаются ни с кем.
- **Сравнение буквальное.** Мягкая запись — ровно путь из списка. Запись `каталог/**`, покрывающая мягкий путь, мягкой не считается: пара с ней пересекается. Широкий захват каталога — настоящий захват, правило не должно становиться способом его не объявлять.
- **Вторая сторона не меняется.** `fileInTouches` различает списки: общий путь разрешён любой задаче, мягкий — только объявившей. Гейт `branch-scope` по-прежнему читает `touches` из `main` и красит правку `docs/architecture.md` в дереве задачи, не объявившей этот путь.

### Критерий приёма пути в мягкий список

Все три условия вместе; пополняется только через ADR.

1. Класс защиты пути — не `deny`: конфликт в нём не задевает гейт-контур. Сторож в тестах — `protectionOf` каждого мягкого пути.
2. Путь обязана править задача по записанному правилу: документ — предмет каждой задачи некоторого класса, изъять его из `touches` нельзя.
3. Правка не обязана быть у каждой задачи репозитория и не append-only: иначе это общий путь (`SHARED_PATHS`), а не мягкий.

`AGENTS.md` (класс `review`) в мягкий список не входит. Правка инструкций меняет поведение каждого агента — её держат по одной, как правку гейта. Условие рассмотрения — отдельным ADR: замер из «Журнала» e72 покажет не менее трёх задач вне работы, запертых D7 только по `AGENTS.md`. На 2026-11-24 таких задач нет.

### Альтернативы

- **Расширить `SHARED_PATHS`.** Отклонено: путь разрешён любой задаче — правка законов прошла бы без объявления в `touches`, `branch-scope` её не увидит.
- **Изъять путь из `touches` задач.** Отклонено: документ — предмет каждой из них; гейт красил бы честную правку, задачи вынуждались бы занижать `touches`.
- **Считать пересечение только по классам `deny`/`review`.** Отклонено: вернуло бы реальные пересечения по продуктовому коду (класс `null`) — например e55 × e61, e62 × e54.
- **Убрать мягкую запись из счёта целиком, как общий путь.** Отклонено: освобождало бы и пару с покрывающим `каталог/**` — широкий захват каталога переставал бы пересекаться с задачами, правящими законы. Выбрано буквальное сравнение: освобождена только пара двух мягких записей. Условие возврата к фильтру — появится задача с `docs/**`, которой нужно идти одновременно с задачей по `docs/architecture.md`, и других общих файлов у них нет.

### Горячие строки документа

Очередь держит не только D7, но и строение файла — З9: строка, которую правит каждая задача, — дефект структуры. По замеру задачи e72 и main 9a4b7772: §5 — перечень ADR одной строкой (1546 знака), его правит каждая задача с ADR; строки таблицы 3.1 — по 360–364 знака, их правит каждая задача, меняющая время шага.

- **Выбор:** строки не трогать, очередь снять мягким путём. Конфликт в документе стоит одного слияния, а переформат горячей строки на лету дал бы конфликт каждой ветке в работе, которая её правит.
- **Альтернатива — устранить причину по З9:** перечень ADR — строка на ADR или отсылка к `docs/adr/`; числа 3.1 — производные (строятся из отчёта замеров, а не правятся руками). Числа 3.1 — отдельная задача: нужны генератор и проверка дрейфа, это новый гейт.
- **Условие перехода:** (а) после merge найден неверный текст, полученный автослиянием §5 или таблицы 3.1; либо (б) планово — docs-PR вне доски, когда ни одна ветка в работе не правит §5 (`git diff --name-only main...task/<id>` по веткам из `pnpm backlog list`).
- **Согласование с e65:** e65 зависит от e72 и правит тот же перечень — вставляет 0020 и 0022. Этот ADR дописан в конец перечня, после 0021: e65 правит середину строки и зачитывает уже обновлённый хвост. До перехода к списку перечень остаётся одной строкой.

## Условие возврата

1. Один случай, когда автослияние `docs/architecture.md` дало неверный текст закона и это найдено после merge: строка в реестре пропущенных дефектов, путь возвращается в счёт пересечений.
2. Доля пар задач в работе, конфликтующих в этом файле, за 30 дней выше порога. Порог называет человек в PR реализации: правила для него в ADR 0009 («Пороги») нет, а правило, дающее значение слабее текущего, — ослабление, его предлагает человек (З7).

Владельцу в PR вынесены два вопроса: сужение условия возврата строки «Очерёдность» ADR 0009 и значение порога.
