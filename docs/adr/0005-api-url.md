# ADR 0005: Адрес API — один origin через прокси web-сервера

- Статус: принято
- Дата: 2026-11-13
- Контекст: [roadmap A5](../roadmap.md) — параллельные агенты в нескольких worktree. Запечённый в сборку `VITE_API_URL` давал: разные порты → разные сборки → промахи кэша turbo между worktree; а без вывода портов из worktree браузер продолжал стучаться в чужой порт.

## Решения

| Область                | Решение                                                                                                                                                                                 | Почему                                                                                                                                                                                                                                      | Альтернатива и когда к ней вернуться                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Адрес API для браузера | Относительный `<origin>/rpc`: браузер ходит на тот же origin, что и страница                                                                                                            | Один origin: сборка web не зависит от адреса и порта API — `dist` идентичен во всех worktree, кэш сборки общий; CORS браузеру не нужен                                                                                                      | Передача адреса через SSR-payload — если API переедет на отдельный домен или появятся сторонние клиенты (не браузер)                                  |
| Адрес API для сервера  | `process.env.API_URL`, читается при старте процесса (SSR-рендер и прокси), не при сборке                                                                                                | Runtime-значение не попадает в бандл: серверная ветка `import.meta.env.SSR` выбрасывается минификатором                                                                                                                                     | `import.meta.env` на клиенте (запечывается) — никогда для адреса API                                                                                  |
| Механизм прокси        | `server.proxy` + `preview.proxy` для `/rpc` в `apps/web/vite.config.ts`, цель из env при старте процесса dev/preview                                                                    | Конфиг запуска, не код приложения; проверено эмпирически: и в `vite preview`, и в `vite dev` прокси перехватывает `/rpc` раньше SSR-обработчика TanStack Start (`POST /rpc/tasks/list` через origin web вернул ответ API, `/` остался HTML) | Server route `/rpc/$` в web (запасной вариант из обсуждения) — не потребовался; вернуть, если обновление Start начнёт перехватывать проксируемые пути |
| Что проксируется       | Только `/rpc`. `/health` и `/__test__/*` через web недоступны: фикстуры e2e, global setup и k6 ходят в API напрямую                                                                     | Тестовый API и внутренний эндпоинт не должны торчать из web-origin наружу; e2e-тест закрепляет «`/__test__/reset` через web → не 204»                                                                                                       | Расширение списка — только с ревью: каждый путь из прокси становится доступным из браузера                                                            |
| CORS                   | Удалён: `cors()` и `WEB_ORIGIN` убраны из API, браузерные запросы same-origin                                                                                                           | Прямые клиенты API (k6, фикстуры, OpenAPI-консьюмеры) не браузерные — им CORS не нужен; dead middleware не должен жить                                                                                                                      | Вернуть `cors()` с явным списком origin, если появится браузерный клиент вне web-origin                                                               |
| Production-топология   | Same-origin: `/rpc` маршрутизирует web-сервер (сейчас `vite preview`, после C3 — его production-сервер) или edge-прокси перед ним. API при этом может жить на любом порту той же машины | Топология не меняется при переезде с preview на production-сервер: прокси/маршрутизация `/rpc` остаётся свойством web-сервера                                                                                                               | Разделение доменов (api.example.com) — тогда возврат к передаче адреса через SSR и пересмотр CORS                                                     |

## Последствия

- Сборка web перестала зависеть от `VITE_API_URL`: переменная удалена из кода и из `env` задачи `dev` в `turbo.json`; `API_URL` добавлен в `env` задач `e2e`/`perf` (turbo передаёт её из окружения, конфиг Playwright отдаёт процессу preview) и в `env` задачи `dev`. `turbo env` значений не задаёт: скрипты `dev`/`start` web подставляют дефолт фиксированных портов (`${API_URL:-http://localhost:3001}`) — до вывода портов из worktree `pnpm dev` работает из коробки.
- Каждый запрос браузера к API идёт через лишний локальный хоп (web → API). Перф-бюджеты не менялись; замер после прокси лучше аудиторной линии (TTFB 5.5ms, LCP 28ms, сценарии 87.6/43.1ms против 6/32/95/49). Если сценарии покраснеют — сначала разбор, не поднятие порогов (З7).
- `pnpm dev` требует `API_URL` (его выставляет `turbo run dev` из `env` задачи; при ручном запуске — задать руками).
- Инвариант «сборка не зависит от адреса API» enforced сканом шага `bundle` (loopback-формы `localhost|127.0.0.1|0.0.0.0|[::1]` с портом в `dist/client/assets`) и канарейкой «адрес API запечён в бандл». Ограничение: не-loopback хост (например `https://api.internal`) скан не поймает — полное равенство двух `dist` не проверяется; расширяется, если появится потребность. «`/__test__` и `/health` не доступны через web-origin» — e2e-тест + канарейка «`/__test__` добавлен в прокси»; удаление прокси `/rpc` роняет канарейкой шаг `e2e` (З6).
