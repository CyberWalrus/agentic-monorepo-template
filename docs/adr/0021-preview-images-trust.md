# ADR 0021: Preview-образы PR в GHCR — граница доверия

- Статус: предложено (принимается merge этого PR человеком)
- Дата: 2026-11-22
- Контекст: задача c3.3, зависимость c3.2 ([ADR 0012](0012-production-server.md)). Preview-окружение на PR (человеку — одобрение визуальных изменений, агентам — исследовательское тестирование вне гейтов) решено разделом «Решение» задачи по ADR 0009: образ `pr-<номер>` в GHCR без SaaS (З12), живой URL — необязательный слой вне рамок. Новая элевация доверия: job, собирающий и публикующий образ, исполняет код PR и держит `packages: write` — публикация, перезапись и REST-удаление версий пакетов, привязанных к репозиторию. Каждая элевация доверия в репо оформлена ADR (0002 — гейты, 0013 — одобрение роста бандла, 0015 — визуальные базлайны, 0017 — remote cache); этот ADR закрывает долг.

## Решения

| Область            | Решение                                                                                                                                                                                          | Почему                                                                                                                                              | Альтернатива и когда к ней вернуться                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Размещение         | Отдельный `.github/workflows/preview.yml` на `pull_request` `[opened, synchronize, reopened, closed]`, свой concurrency `preview-<номер>`; ci.yml не тронут                                      | Preview — не гейт: вне `needs` у `gate`, не required check; событие `closed` не должно перезапускать гейт-контур                                    | Job в ci.yml с гардами на каждый job — если число workflow начнёт мешать чтению                                                                                    |
| Граница доверия    | Job `preview` исполняет код PR и держит job-level `contents: read` + `packages: write` + `pull-requests: write`; cleanup — `contents: read` + `packages: write`; workflow-level `contents: read` | Минимальный состав для build+push+comment+delete; радиус компромисса ограничен: версии preview-пакетов и текст комментария PR — не гейты, не `main` | Доверенная сборка из `main` (`workflow_run`/`pull_request_target`) — при внешних контрибьюторах через форки: сейчас preview для форков не собирается вовсе (гвард) |
| Форк-гвард         | `github.event.pull_request.head.repo.full_name == github.repository` на обоих job, включая cleanup                                                                                               | Критерий приёмки c3.3 «job не запускается для форков»: skipped, а не красный; жёсткая граница и так есть — форковый токен принудительно read-only   | `head.repo.fork == false` — эквивалент; равенство `full_name` дополнительно отсекает edge-случаи переноса                                                          |
| Комментарий        | Один на PR, upsert по маркеру `<!-- preview-env:<номер> -->`, обновление на каждый push; внутри — оба образа, общая docker-сеть, `PORT`/`API_URL`, ссылка на отчёт visual                        | Без upsert PR загрязняется комментарием на прогон; без `PORT` web-entry падает на старте (fail-closed, [ADR 0012](0012-production-server.md))       | Новый комментарий на каждый прогон — шум в PR                                                                                                                      |
| Cleanup            | REST DELETE версий с тегом `pr-<номер>` и не-тегированных (мусор от перезаписи тега на повторном push); 404 — успех                                                                              | Критерий «тег удаляется после merge/закрытия»; писатель у пакетов один — сам workflow, чужих не-тегированных версий нет                             | Только тегированные — версии копятся вечно                                                                                                                         |
| Видимость пакетов  | Public; выставляет человек один раз при первом пуше (github-setup.md п. 9); в приватных копиях проекта — private + `docker login` с PAT у каждого запускающего                                   | Одно человеческое действие против PAT каждому запускающему (З12); код PR публичного шаблона и так публичен, production-секретов в образах нет       | Private по умолчанию + PAT в комментарии — если public окажется избыточным у потребителя шаблона                                                                   |
| Кэш сборки         | buildx `type=gha` с per-image scopes (`preview-api`/`preview-web`), `timeout-minutes: 25`/`5`                                                                                                    | Холодный `pnpm install` в контейнере — минуты (журнал c3.2); без кэша — полная сборка на каждый push                                                | Только локальный кэш раннера — если gha-кэш станет точкой сбоев                                                                                                    |
| Инструменты сборки | Обычный `docker buildx` CLI без сторонних docker-actions                                                                                                                                         | Ни одного нового action: SHA-пиннинг (b6) иRenovate-нагрузка не растут, buildx предустановлен на раннерах                                           | `docker/build-push-action` — при потребности в provenance/attestation                                                                                              |

## Что отвергнуто

- **`pull_request_target` для preview.** Исполнение PR-кода в доверенном контексте — анти-паттерн [ADR 0002](0002-gate-integrity.md); preview не нуждается в доверии к PR, и политика §3 github-setup.md не расширяется без повода.
- **Preview как required check или в `needs` у `gate`.** Красная сборка образа не должна блокировать merge (З5/З6: гейт требует шаг в verify, канарейку и бюджет времени); визуальный дифф человек смотрит по отчёту CI, а не по живому окружению (раздел «Решение» задачи c3.3).
- **Общий preview-кластер.** Закрыто разделом «Решение» задачи: окружение на PR изолировано по построению (З9); кластер — отдельная инфраструктура с собственными секретами.

## Последствия

- Остаточный риск: коллаборатор, пушащий same-repo PR, исполняет свой код в job `preview` с `packages: write` до ревью — может перезаписать/удалить версии `pr-<номер>` и изменить текст комментария своего PR. Гейты, `main` и чужие теги не затрагиваются; правка самого workflow в `main` идёт через `gate-change-approved`. Принимается как цена «образ из того, что деплоится» ([ADR 0012](0012-production-server.md)); условие возврата — внешние контрибьюторы через форки: тогда доверенная сборка (`workflow_run`) с публикацией из `main`.
- Время гейт-контура не меняется (ci.yml не тронут, job вне `gate`); за контуром preview следит телеметрия CI (c9.4, architecture.md §3.13) — «замедление считается дефектом» (architecture.md §4 п. 4).
- Одно человеческое действие после первого пуша (Public, github-setup.md п. 9); до него команда запуска из комментария не работает — ожидаемое состояние первого PR.
- Живой URL — необязательный слой вне рамок задачи: отдельная задача, когда человек добавит в github-setup.md имя переменной секрета провайдера.
