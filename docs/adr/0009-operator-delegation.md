# ADR 0009: Оператор — действия человека, делегированные агенту через computer use

- Статус: принято (внедрено: сам ADR — merge #36; команды доски `next`/`start --operator`, проверки префиксов `needs_human` и doctor-проверка файла режима обслуживания — D13, merge #59, 2026-11-17); поправка 2026-11-23 — ограничение «одна операторская задача за раз» снято (строки «Очерёдность» и «Захват», раздел «Поправка 2026-11-23»): условие возврата строки «Очерёдность» наступило — после B7 (#114) и D7 (#149) пересечения `touches` исключает сам захват; по прямому поручению владельца (чат 2026-11-23, дословно: «одну операторскую задачу за раз убери это ограничение»)
- Дата: 2026-11-15
- Контекст: 2026-11-15 доска остановилась — свободных задач ноль: 18 открытых задач требуют режима обслуживания, ещё 9 ждут выбора варианта человеком (`needs_human`). Один человек не успевает быть и тем, кто выбирает, и тем, кто включает режим обслуживания, и тем, кто принимает PR. Поручение человека в сессии 2026-11-15: «выбери варианты; задачи, для которых я нужен, пусть агенты делают через computer use; агенты дальше должны делать задачи без вопросов». Этот ADR меняет то, как исполняется принцип 2 из [vision.md](../vision.md) («гейт меняет только человек отдельным осознанным действием») и строка «Задачи с режимом обслуживания» [ADR 0007](0007-task-board.md), и принимает компромисс с известным риском ([architecture.md](../architecture.md), раздел 5).

## Пороги: правила вместо вопроса

Порог ставит оператор по правилу, человек видит число и замер в PR. Ослабление существующего порога правилом не покрывается: если правило даёт значение слабее текущего порога или правила для бюджета нет, это ослабление — его предлагает и выполняет только человек (З7).

| Порог                                            | Правило                                                                                                                                                 | Прецедент                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Покрытие нового пакета или проекта               | Каждая метрика: фактическое значение, округлённое вниз до целого, минус 2 процентных пункта                                                             | З7: «порог стоит рядом с фактическим значением»                            |
| Мутационный счёт, `break`                        | Фактический счёт, округлённый вниз, минус 5 процентных пунктов; дальше порог двигает только храповик вверх                                              | Задача B2.4; на малых выборках один мутант весит больше процентного пункта |
| Абсолютный потолок времени (`perf-budgets.json`) | При смене способа запуска или хранилища: медиана CI-замера × 3, округлить вверх до 10 мс. Замер прикладывается к PR. Без такой смены потолок не трогают | [ADR 0006](0006-perf-strategy.md), «Абсолютные потолки»: запас около 3×    |
| Детерминированные метрики (запросы, байты)       | От смены хранилища или способа запуска не зависят. Если изменились — это регрессия, чинится код                                                         | [ADR 0006](0006-perf-strategy.md), уровень 1                               |
| Карантин нестабильного теста                     | Срок 14 дней без продления; в карантине одновременно не больше трёх тестов; тест `@critical` в карантин не попадает                                     | Задача B4.4                                                                |

## Что отвергнуто

- **Оператор ставит label и сливает PR сам.** Убирает человека из цепочки полностью, но вместе с ним — единственную проверку, которую агент не может пройти своим действием. Противоречит З1 и З2 и самой цели шаблона.
- **Убрать защищённые пути из `deny` для задач обвязки.** Ослабляет границу для всех сессий ради редкого режима; отклонено ещё в ADR 0004.
- **Оставить как есть.** 27 из 44 открытых задач ждут одного человека; очередь растёт быстрее, чем разбирается.

## Последствия

- Для операторской сессии контур L0 перестаёт быть границей: формула ADR 0004 «хранитель замка не выписывает себе ключ» больше не выполняется на L0 и сохраняется только на приёмке PR. Это осознанный компромисс.
- Тихое окно ADR 0004 остаётся: забытый `settings.local.json` выключает хуки и песочницу в worktree задачи. Смягчение — файл живёт только в worktree задачи, а время включения и выключения записано в журнале; проверку «в рабочих деревьях нет файла режима обслуживания» добавляет в `pnpm backlog doctor` задача D13.
- Приёмка PR становится единственным местом, где человек видит изменение гейта. Раздел «Изменения гейтов» в PR оператора обязателен и содержит находки ревьюеров.
- Обычные сессии этим ADR не затронуты: агент, которому мешает гейт, чинит код или останавливается и объясняет.
- Условие пересмотра: первый случай, когда PR оператора меняет защищённый путь вне `touches` своей задачи, оставляет режим обслуживания включённым после открытия PR или когда оператор выполнил любое действие приёмки PR (approve, label, merge).

## Поправка 2026-11-23: очерёдность операторских задач

Основание — прямое поручение владельца (чат 2026-11-23, дословно: «одну операторскую задачу за раз убери это ограничение»). Условие возврата строки «Очерёдность» («после B7») наступило: после B7 (#114) и D7 (#149) пересечения `touches` исключает сам захват. Работа идёт вне доски, файла задачи нет — журнал ведётся здесь.

### Журнал

- 2026-11-23, решено. Ограничение «одна операторская задача за раз» снято: строки «Очерёдность» и «Захват» переписаны; `next --operator` больше не отказывает при ведущейся задаче, а перечисляет ведущиеся операторские задачи с их `touches` и предлагает первую свободную кандидатку, не пересекающуюся с задачами в работе; если пересекаются все — отказ с перечнем, с чем именно. «Один гейт — один PR» сохранён.
- Развилка «отсекать кандидатов по каким задачам». Выбрано — по всем задачам в работе, а не только по операторским: `commandStart` (D7) не различает, кто ведёт пересекающуюся задачу, иначе `next --operator` предлагал бы задачу, которую `start` отвергнет. Альтернатива — фильтр только по операторским. Условие возврата — если D7 начнёт считать пересечение только с операторскими.
- Развилка «проверка открытых PR через gh в `next --operator`».
