# ADR 0009: Оператор — действия человека, делегированные агенту через computer use

- Статус: предложено (принимается merge этого PR человеком)
- Дата: 2026-11-15
- Контекст: 2026-11-15 доска остановилась — свободных задач ноль: 18 открытых задач требуют режима обслуживания, ещё 9 ждут выбора варианта человеком (`needs_human`). Один человек не успевает быть и тем, кто выбирает, и тем, кто включает режим обслуживания, и тем, кто принимает PR. Поручение человека в сессии 2026-11-15: «выбери варианты; задачи, для которых я нужен, пусть агенты делают через computer use; агенты дальше должны делать задачи без вопросов». Этот ADR меняет то, как исполняется принцип 2 из [vision.md](../vision.md) («гейт меняет только человек отдельным осознанным действием») и строка «Задачи с режимом обслуживания» [ADR 0007](0007-task-board.md), и принимает компромисс с известным риском ([architecture.md](../architecture.md), раздел 5).

## Решения

| Область                       | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Почему                                                                                                                                                                                                            | Альтернатива и когда к ней вернуться                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Роль                          | **Оператор** — сессия агента с computer use, которую человек запустил словами «ты оператор» (или назвал id задачи режима обслуживания). Обычная сессия оператором не становится: правила «не менять защищённые пути» и «не обходить песочницу» для неё действуют без изменений                                                                                                                                                                                                             | «Отдельное осознанное действие человека» остаётся, но сжимается с «включить режим, назвать id, выключить режим» до одной фразы при запуске. Вопросов посреди работы не остаётся                                   | Вернуть «режим включает только человек» — если счётчик C9.3 покажет, что оператор менял гейт вне своей задачи                                                              |
| Что делает оператор           | 1) включает и выключает режим обслуживания; 2) захватывает и ведёт задачи режима обслуживания; 3) выполняет локальные ручные действия задач с `needs_human: оператор: …` (настройки клиента, вход в CLI через уже открытую сессию браузера); 4) ставит пороги и бюджеты по правилам из раздела «Пороги» этого ADR                                                                                                                                                                          | Это всё, что на 2026-11-15 требовало человека и при этом проверяемо: результат лежит в диффе PR                                                                                                                   | —                                                                                                                                                                          |
| Что остаётся человеку         | Запуск операторской сессии. Приёмка PR: approve, label `gate-change-approved`, merge. Одобрение визуальных базлайнов. Ввод паролей, токенов, секретов, кодов подтверждения; создание аккаунтов и платных ресурсов. `pnpm backlog release`. Оператор этих действий не выполняет ни через команду, ни через интерфейс — даже если браузер человека уже авторизован                                                                                                                           | Приёмка PR — последняя независимая проверка изменения гейта (З1, З2): хранитель замка может получить ключ от L0, но не подписывает себе пропуск в `main`. Остальное — действия, которые нельзя проверить по диффу | Делегировать label — только отдельным ADR и только вместе с независимым детерминированным одобрением (второй мейнтейнер или правило, которое агент не может выполнить сам) |
| Развилки в задачах            | Выбор варианта не оставляют вопросом. Агент, который пишет задачу или план, записывает в файл задачи раздел «Решение»: что выбрано, почему, альтернатива и условие возврата — как в ADR. Человек возражает в PR. Если вариант зависит от факта, которого ещё нет, задача называет вариант по умолчанию и запасной с проверяемым условием переключения                                                                                                                                      | Задача с открытым вопросом блокирует цепочку до ответа; записанное решение ревьюится тем же PR, что и раньше, но не останавливает работу. Архитектурный разворот по-прежнему идёт через ADR                       | —                                                                                                                                                                          |
| Поле `needs_human`            | Три допустимых вида. `оператор: <действие>` — берёт операторская сессия. `отложено: <проверяемое условие>` — задача не начинается, пока условие не наступило; блокировку снимает PR, приложивший доказательство. Любой другой текст — действие из строки «Что остаётся человеку». Вопрос «какой вариант выбрать» в поле не пишут                                                                                                                                                           | Поле блокирует `start` для всех, поэтому в нём должно стоять только то, что действительно нельзя сделать обычному агенту                                                                                          | Отдельное поле `operator` — если D13 покажет, что префикса мало                                                                                                            |
| Захват до D13                 | Оператор захватывает задачу тем же действием, что и `start`: `git branch task/<id> main`, затем `git worktree add ../<каталог-репозитория>-task-<id> task/<id>`. Отказ первой команды («ветка существует») — задача занята. Дальше как обычно: `pnpm backlog close <id>` сразу после захвата, журнал, PR                                                                                                                                                                                   | Захват остаётся атомарным созданием ветки (ADR 0007). Отказ `start` — подсказка, а не граница (З3): граница — CI                                                                                                  | `pnpm backlog start --operator` и `next --operator` — задача D13; после неё ручные команды из инструкций убираются                                                         |
| Режим обслуживания оператором | Порядок: 1) захватить задачу, получить worktree; 2) через интерфейс хоста создать `.claude/settings.local.json` с `{"disableAllHooks": true, "sandbox": {"enabled": false}}` **в worktree задачи**, а не в основном checkout; 3) открыть новую сессию клиента в этом worktree и работать по разделу 4 `architecture.md`; 4) до открытия PR удалить файл и убедиться, что его нет; 5) записать в «Журнал» задачи время включения и выключения. В клиенте без хуков проекта шаги 2 и 4 пусты | Файл в worktree задачи не выключает защиту в основном checkout и в чужих worktree и исчезает вместе с worktree. Запись в журнале делает тихое окно ADR 0004 видимым                                               | Режим обслуживания по областям (задача B9) — открывать не всё, а пути из `touches` задачи                                                                                  |
| Очерёдность                   | Одновременно работает одна операторская сессия и одна задача режима обслуживания; один гейт — один PR. | Проверка перед PR             | Оператор сам запускает то, что в режиме обслуживания выключено: `pnpm verify` после каждого шага, `pnpm verify --full` и `pnpm canaries` в конце; канарейка красная до изменения и зелёная после. Дифф гейта до PR получают `architecture-reviewer`, `sanity-reviewer` и `security-reviewer`; их находки и ответы на них — в теле PR, в разделе «Изменения гейтов»                                                                                                                         | Человек принимает изменение гейта по PR, не наблюдая сессию: всё, что он видел бы в режиме обслуживания, должно быть в PR                                                                                         | —                                                                                                                                                                          |
| Computer use                  | Только там, где нет команды: файл режима обслуживания, окна авторизации CLI, настройки клиента. Страницу, которая требует пароль или код, оператор не проходит: записывает в журнал «нужен вход человека» и продолжает остальное                                                                                                                                                                                                                                                           | Дорого и недетерминированно; каждое действие через интерфейс — вне всех гейтов                                                                                                                                    | —                                                                                                                                                                          |

## Пороги: правила вместо вопроса

Порог ставит оператор по правилу, человек видит число и замер в PR. Ослабление существующего порога правилом не покрывается: его по-прежнему предлагает человек (З7).

| Порог                                            | Правило                                                                                                                                                 | Прецедент                                                                  |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Покрытие нового пакета или проекта               | Каждая метрика: фактическое значение, округлённое вниз до целого, минус 2 процентных пункта                                                             | З7: «порог стоит рядом с фактическим значением»                            |
| Мутационный счёт, `break`                        | Фактический счёт, округлённый вниз, минус 5 процентных пунктов; дальше порог двигает только храповик вверх                                              | Задача B2.4; на малых выборках один мутант весит больше процентного пункта |
| Абсолютный потолок времени (`perf-budgets.json`) | При смене способа запуска или хранилища: медиана CI-замера × 3, округлить вверх до 10 мс. Замер прикладывается к PR. Без такой смены потолок не трогают | [ADR 0006](0006-perf-strategy.md), «Абсолютные потолки»: запас около 3×    |
| Детерминированные метрики (запросы, байты)       | От смены хранилища или способа запуска не зависят. Если изменились — это регрессия, чинится код                                                         | [ADR 0006](0006-perf-strategy.md), уровень 1                               |
| Карантин нестабильного теста                     | Срок 14 дней без продления; в карантине одновременно не больше трёх тестов; тест `@critical` в карантин не попадает                                     | Задача B4.4                                                                |

## Что отвергнуто

- **Оператор ставит label и сливает PR сам.** Убирает человека из цепочки полностью, но вместе с ним — единственную проверку, которую агент не может пройти своим действием. Противоречит З1 и З2 и самой цели шаблона.
- **Убрать защищённые пути из `deny` для задач обвязки.** Ослабляет границу для всех сессий ради редкого режима; отклонено ещё в ADR 0004.
- **Оставить как есть.** 27 из 44 открытых задач ждут одного человека; очередь растёт быстрее, чем разбирается.

## Последствия

- Для операторской сессии контур L0 перестаёт быть границей: формула ADR 0004 «хранитель замка не выписывает себе ключ» больше не выполняется на L0 и сохраняется только на приёмке PR. Это осознанный компромисс.
- Тихое окно ADR 0004 остаётся: забытый `settings.local.json` выключает хуки и песочницу в worktree задачи. Смягчение — файл живёт только в worktree задачи, а время включения и выключения записано в журнале; проверку «в рабочих деревьях нет файла режима обслуживания» добавляет в `pnpm backlog doctor` задача D13.
- Приёмка PR становится единственным местом, где человек видит изменение гейта. Раздел «Изменения гейтов» в PR оператора обязателен и содержит находки ревьюеров.
- Обычные сессии этим ADR не затронуты: агент, которому мешает гейт, чинит код или останавливается и объясняет.
- Условие пересмотра: первый случай, когда PR оператора меняет защищённый путь вне `touches` своей задачи или оставляет режим обслуживания включённым после открытия PR.
