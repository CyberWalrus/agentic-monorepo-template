# ADR 0012: Production-сервер и деплой — Node-entry без Nitro, образы на alpine

- Статус: принято
- Дата: 2026-11-16
- Контекст: задача C3.2 — web запускался через `vite preview`, production-способа запуска не было ни у человека, ни у агентов; образов не было. Развилка «Node или Nitro» закрыта разделом «Решение» задачи (делегирована агенту, ADR 0009): Node без Nitro. Сборка образов в CI — отдельная задача C3.3, перевод E2E/перфа на production-entry — C3.4.

## Решения: модель запуска

| Область            | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Почему                                                                                                                                                                                                                                                                                                                                                                                                    | Альтернатива и когда к ней вернуться                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Сервер web         | Тонкий Node-entry `apps/web/server.ts`: раздаёт статику `dist/client`, проксирует `/rpc` на `API_URL`, отдаёт остальное fetch-обработчику серверной сборки TanStack Start (`dist/server/server.js` экспортирует `{ default: { fetch: Request → Response } }`, версия 1.169.4 — сверено с бандлом и документацией перед реализацией, как требовало «Решение» задачи)                                                                                                                                                                                                                                                                 | Одна модель запуска с api (`@hono/node-server`); прокси и readiness — явный код под тестами; без Nitro — без слоя сборки и без смены раскладки артефактов                                                                                                                                                                                                                                                 | Nitro с пресетом `node-server` (запасной вариант задачи не понадобился) — при цели деплоя не на Node (serverless, edge) |
| Фабрика и проводка | `createWebServerApp({ apiUrl, staticRoot, handler, proxyFetch, compressedBodies })` в `src/server-app.ts` под unit-тестами; корневой `server.ts` — только проводка. Entry лежит в корне пакета, не в `src/`: плагин TanStack резервирует `src/server.ts` как свой entry-слот                                                                                                                                                                                                                                                                                                                                                        | Логика тестируется без сети (инъекция `proxyFetch`), без серверной сборки (инъекция `handler`) и с наблюдаемым кэшем сжатия (инъекция `compressedBodies`) — образец `createApp` api; dev-поведение плагина не меняется                                                                                                                                                                                    | —                                                                                                                       |
| Прокси `/rpc`      | Собственный: тело буферизуется с потолком 1 MiB (свыше — 413), hop-by-hop заголовки и `content-length` снимаются в обе стороны, таймаут 30 с, ошибка сети → 502 без внутренностей, `redirect: manual`. Host запроса к API undici пересобирает из цели (в dev vite с `changeOrigin: false` сохранял клиентский Host — поведение осознанно иное). Только `/rpc`, как в dev/preview (ADR 0005)                                                                                                                                                                                                                                         | Инъекция fetch для тестов: `hono/proxy` не принимает подменный fetch; `serve-static` из `@hono/node-server` резолвит `root` от `process.cwd()` — оба ломают тестируемость                                                                                                                                                                                                                                 | `hono/proxy` — если понадобится потоковое проксирование больших тел                                                     |
| Статика            | Только GET/HEAD; whitelist content-type по расширению; `Cache-Control: immutable` для `/assets/*` (хешированные имена клиентской сборки); gzip для текстовых типов сборки при `Accept-Encoding: gzip` (сжатая копия кэшируется на жизнь приложения с ключом по каноническому пути файла — варианты percent-кодирования одного URL дают одну запись, поэтому потолка на кэш не нужно: файлов в dist/client конечное число, корень пишет только сборка; `Vary: accept-encoding` в обеих ветках; уже сжатые форматы — png/webp/woff2/wasm/ico — мимо); traversal (битый percent-encoding, null-byte, вылет за корень) → SSR-обработчик | Раздаём только то, что положил `vite build`; неизвестное расширение — не статика; корень пишет только сборка, симлинки не раздаются; wire-байты гейтов обязаны совпадать со старой preview-механикой — C3.4 поймал, что без gzip детерминированные перф-метрики уезжают втрое (ADR 0009: сдвиг — регрессия, чинится код); ключ кэша по сырому pathname клиента отвергнут ревью PR #140 как memory/CPU-DoS | CDN перед origin при реальном деплое — immutable-заголовки остаются контрактом                                          |
| Readiness          | api — `/health` (был); web — `/healthz`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Readiness — свойство процесса: слушает ли порт. Имя `/health` у web сломало бы e2e-инвариант [AC-2] «API /health не торчит из web-origin: проксируется только /rpc» (ADR 0005)                                                                                                                                                                                                                            | Единое имя — только вместе с пересмотром e2e-инварианта                                                                 |
| HOST и порт        | `HOST` в окружении обоих приложений: дефолт `127.0.0.1` (URL гейтов — 127.0.0.1, ADR 0005), в контейнере `0.0.0.0` из ENV образа. `PORT` обязателен без дефолта (З9). Невалидное окружение — отказ при старте (fail-closed, C3.0)                                                                                                                                                                                                                                                                                                                                                                                                   | Локальный сервер не вылезает на все интерфейсы по умолчанию; контейнер обязан слушать 0.0.0.0 и заявленный порт                                                                                                                                                                                                                                                                                           | —                                                                                                                       |
| Завершение         | SIGTERM/SIGINT → `server.close()`: активные запросы доигрывают                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `docker stop` шлёт SIGTERM; принудительный таймаут — дело оркестратора (`docker stop -t`)                                                                                                                                                                                                                                                                                                                 | —                                                                                                                       |

## Решения: образы

| Область            | Решение                                                                                                                                                                                                    | Почему                                                                                                                                                                                                                                                                             | Альтернатива и когда к ней вернуться                                                                                   |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| База               | `node:26.13.0-alpine` — минор закреплён (нижняя граница `engines`), alpine-патчи плывут                                                                                                                    | Небольшой образ при знакомом Node                                                                                                                                                                                                                                                  | Digest-пин — если понадобится полная воспроизводимость сборки                                                          |
| pnpm в образе      | `npm install -g pnpm@12.21.0` — дословно `packageManager` из package.json                                                                                                                                  | corepack в Node ≥25 не входит; floating `latest` против культуры закрепления версий                                                                                                                                                                                                | corepack — если политика Node снова включит его в дистрибутив                                                          |
| Сборка             | Multi-stage: манифесты workspace → `pnpm install --frozen-lockfile` → (`vite build` для web) → `pnpm deploy --filter @repo/<app> --prod` → рантайм копирует только deploy-каталог                          | Слой зависимостей переживает правки исходников; deploy прунит devDeps и workspace; `dist` собирается внутри образа                                                                                                                                                                 | —                                                                                                                      |
| Состав пакета      | `files` в package.json: api — `src` без `*.test.ts`; web — `dist`, `server.ts` и серверные модули из `src` (`lib/env.ts`, `server-app.ts`)                                                                 | Deploy пакует по packlist: без перечисления рантайм-импорты entry не попали бы в образ (нашёл ревью плана)                                                                                                                                                                         | —                                                                                                                      |
| TS-workspace в api | После deploy контракт выносится из `node_modules`: `packages/contracts` — реальный каталог, `node_modules/@repo/contracts` — симлинк на него, его прод-зависимости — симлинк в `.pnpm`-хранилище контракта | Node не стриппит типы внутри `node_modules` (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`), а deploy пакует workspace-пакеты именно туда; в pnpm-workspace та же раскладка через симлинки, потому dev работает. web обходится без этого — контракт влинен в серверную сборку vite | Компиляция api в JS при сборке образа — если ограничение Node снимут или в рантайме появится второй TS-workspace-пакет |
| Рантайм            | non-root (`USER node`), `HEALTHCHECK` busybox-wget на readiness-эндпоинт, `EXPOSE 3000`                                                                                                                    | Стандарт контейнеров; оркестратору достаточно readiness                                                                                                                                                                                                                            | —                                                                                                                      |
| Контекст           | `.dockerignore` в корне: исходники и манифесты, без node_modules/dist/reports/секретов                                                                                                                     | Контекст мал, в образ не попадают локальные артефакты                                                                                                                                                                                                                              | —                                                                                                                      |

## Последствия

- Проверялось то, что деплоится: локальный smoke — `pnpm deploy --filter @repo/web --prod` и запуск `node <out>/server.ts` (SSR, прокси `/rpc`, статика, `/healthz`, fail-closed), затем `docker build` обоих образов + `docker run` + readiness. C3.4 довёл это до конца: E2E, перф и визуальные тесты поднимают приложения тем же production-entry (e2e webServer — `pnpm --filter @repo/web start:prod`, PORT и API_URL через env, readiness `/healthz`); `"start": "vite preview"` в `apps/web/package.json` остаётся только для интерактивной разработки. CI-сборка образов — C3.3.
- `vite preview` остаётся в текстах только как dev-механика (vite.config.ts, скрипт `start` для интерактивной разработки, исторические ADR) — не как способ production-запуска и не как способ запуска тестов: README описывает `pnpm --filter @repo/web start:prod`.
- Bump pnpm требует синхронной правки всех четырёх мест, где версия продублирована строкой `npm install -g`: двух Dockerfile (builder-стадия), «Быстрый старт» README и строка «pnpm в образе» этого ADR — каждое равно `packageManager` из package.json. Сверки «документы = packageManager» тестом нет (e64): если расхождение вернётся, гейт заводится отдельной операторской задачей.
- Серверная сборка импортируется без типов — `@ts-expect-error` с причиной у импорта: контракт `{ fetch }` зафиксирован этим ADR; если TanStack начнёт поставлять декларации, suppression снимается.
- Тело прокси буферизуется целиком с потолком 1 MiB (413): для RPC JSON это норма; большие payload-ы (загрузки файлов) потребуют потокового проксирования — см. строку «Прокси /rpc».
- Известный риск окна C3.2→C3.4: связка «реальный артефакт `dist/server/server.js` ↔ рантайм-гард `isStartEntry`» до перевода e2e на production-entry проверялась только ручным smoke; bump TanStack Start может сменить форму экспорта — гард честно уронит старт со внятной ошибкой. Окно закрыто C3.4: e2e webServer стартует production-entry, так что рантайм-гард стоит на пути каждого гейт-прогона (`pnpm verify --full`, `pnpm visual`, CI).
