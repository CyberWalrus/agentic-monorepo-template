## Прогон D2: три клиента (2026-11-14)

Одинаковый сценарий в клоне шаблона на `d4f861a`, вне основного репозитория: ветка → `git worktree add` вне репо → правка в `apps/api/src` → `pnpm install` → `pnpm verify` → коммит. ZCode — рабочая сессия агента; Claude Code 2.1.267 (`claude -p`, skip-permissions) и Codex 0.39.0 (`codex exec`) — headless.

Выводы.

- Решение «Рабочее место» подтверждено для основного клиента: ZCode-агент создаёт ветку, worktree вне workspace и проходит гейты сам.
- Оба клиента, дошедшие до шагов, не пытались обходить ограничения и вели отчёт по шагам; Lefthook в Claude Code отклонил коммит fail-closed.
- Найден пробел защиты: `prepare` ставит хуки только при `[ -d .git ]`, а в worktree `.git` — файл. Захвачено задачей D11.
- Для Claude Code полный сценарий требует двух настроек рабочего места: allowlist записи на каталог worktrees и предсказуемый store-dir pnpm; для Codex — ручного `codex login`. До этого таблица «клиент × шаг» неполна по этим двум клиентам.

Примечания к пополнению.

- **Область действия импорта скилов:** симлинки на уровне пользователя — скилы проекта видны всем workspace на хосте, включая чужие проекты; источник один — канонический checkout, правки из task-веток появляются только после merge. Симлинк создан вручную: UI-путь Settings → Skills → Import не кликался, эквивалентность режима Symlink заявлена по документации, не прогоном UI. Если рекомендуемой настройкой сделать симлинк-импорт — отдельная задача на правку `AGENTS.md`/документации.
- **Codex:** отказ не в учётных данных, а в сети: auth-сервер отклоняет authorize по региону сети хоста, поэтому и refresh токена получает `403`. Вход и/или восстановление сетевого пути — за человеком; `codex login status` при этом показывает «Logged in» по устаревшему `auth.json` — статусу входа доверять нельзя.
- **Claude Code:** allowlist-настройка — рабочий способ дать агенту каталог worktrees (постоянное безопасное значение требует стабильного корня worktrees — сейчас каталоги создаются рядом с репозиторием с именем задачи; кандидат в новые задачи). Оставшийся блокер install — capability песочницы `file-write-flock`: pnpm в песочнице вдобавок не видит `~/.npmrc` (store резолвился в соседний `.pnpm-store`, вне песочницы — глобальный), поэтому настройка store-dir сама по себе install не чинит. Диагноз 2026-11-14 «pnpm выбрал соседний store» уточнён: блокирует операция блокировки, а не путь store.
- **Решение «Рабочее место» не меняется:** ZCode проходит сценарий целиком; Claude Code — с настройкой allowlist, до install; Codex — до авторизации.

## Решения

| Область                       | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Почему                                                                                                                                                                                                                                                                                                                              | Альтернатива и когда к ней вернуться                                                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Единица                       | Одна задача → одна ветка `task/<id>` → один worktree → один агент → один PR                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Два агента в одной задаче правят одни файлы; задача больше одного PR плохо ревьюится (architecture.md, раздел 4)                                                                                                                                                                                                                    | Несколько агентов на одну задачу — только через оркестратор конкретного клиента, поверх этой схемы                                                        |
| Где лежат задачи              | Каталог `backlog/`, один файл на задачу: `backlog/<id>.md`. Закрытые — в `backlog/done/`. Имя `tasks` не используется: так называется демо-домен                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Общий файл со всеми задачами правит каждый PR — это «горячий» файл (З9). Файлы читает любой клиент без сети и без SaaS (З12)                                                                                                                                                                                                        | GitHub Issues — если появится команда, которой нужны обсуждения и уведомления; файлы тогда остаются источником для агентов                                |
| Идентификатор                 | `id` — имя файла. Дочерние задачи получают id от родителя (`d12.1`). Общего счётчика нет                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Два PR с одним id дают конфликт добавления одного файла — его ловит сам git, а не гейт после merge                                                                                                                                                                                                                                  | —                                                                                                                                                         |
| Поля задачи                   | Front matter: `title`, `type` (`research`, `decompose`, `change`), `priority`, `depends_on` (список id), `touches` (литеральные пути и `каталог/**`; для `research` и `decompose` может быть пустым), `needs_human` (что должно случиться, чтобы задача открылась: `оператор: …`, `отложено: …` или `человек: …` — дополнено [ADR 0009](0009-operator-delegation.md)). Тело: проблема с доказательством, что сделать, критерии приёмки, журнал                                                                                                                                                                                | Минимум, по которому задачу можно выбрать детерминированно. Произвольные glob-ы не разрешены: их пересечение нельзя посчитать точно                                                                                                                                                                                                 | —                                                                                                                                                         |
| Откуда читается доска         | Из ссылки `main`, а не из рабочего дерева. Блокирующие поля (`depends_on`, `needs_human`, `touches`) тоже берутся из `main`. Если remote доступен, команда сначала обновляет `main`; если нет — печатает возраст данных. Задача, добавленная в ветке, появляется на доске только после merge                                                                                                                                                                                                                                                                                                                                  | У каждого worktree своё рабочее дерево: иначе у каждого агента была бы своя доска, а ветка могла бы сама снять с себя блокировку или захватить задачу из чужого непроверенного PR (З2)                                                                                                                                              | —                                                                                                                                                         |
| Статус                        | В файле не хранится, вычисляется: файл в `backlog/done/` — закрыта; есть ветка `task/<id>` — в работе; есть незакрытые `depends_on` или `needs_human` — заблокирована; путь из `touches` попадает под `deny` из `tools/protected-paths.json` — нужен режим обслуживания; иначе свободна                                                                                                                                                                                                                                                                                                                                       | Хранимый статус расходится с действительностью и требует записи в `main` (З10). Пометка 🔒 вычисляется из того же списка, что и защита путей                                                                                                                                                                                        | Поле `status` в файле — никогда: это второй источник правды                                                                                               |
| Захват                        | Создание локальной ветки `task/<id>` от `main` в общем хранилище ссылок клона: второй агент на той же машине получает отказ git. В remote ветка попадает обычным push, когда появляются коммиты                                                                                                                                                                                                                                                                                                                                                                                                                               | Атомарность даёт блокировка ссылки в git. Не нужен демон, сервер очереди и сеть                                                                                                                                                                                                                                                     | Захват через push новой ветки с уникальным коммитом — когда агенты появятся на второй машине или в облаке; тогда же решать, как он уживается с `pre-push` |
| Задачи с режимом обслуживания | `next` их не выдаёт, а перечисляет человеку. Начинает такую задачу только человек: включает режим обслуживания и называет id. Дополнено [ADR 0009](0009-operator-delegation.md) (2026-11-15): эти действия человек может поручить операторской сессии, приёмка PR остаётся человеку                                                                                                                                                                                                                                                                                                                                           | Агент не может менять защищённые пути и не должен искать обход; в ZCode его остановил бы только CI                                                                                                                                                                                                                                  | —                                                                                                                                                         |
| Брошенный захват              | Автоматического перехвата нет. `list` показывает возраст последнего коммита ветки, есть ли у неё worktree, и отдельно — закрытые задачи, от которых остались ветка или worktree. Освобождает задачу человек: `release` требует интерактивного терминала и переименовывает ветку в `abandoned/<id>`, а не удаляет                                                                                                                                                                                                                                                                                                              | Нельзя отличить упавшую сессию от медленной без демона; ошибочный перехват даёт двух агентов в одной задаче. Переименование обратимо                                                                                                                                                                                                | Перехват по порогу времени — если брошенных задач станет больше, чем человек успевает разбирать                                                           |
| Что можно параллельно         | Последовательность задаёт `depends_on`. Пересечение `touches` с задачами в работе запрещает захват (D7, #149): `next` и `next --operator` такие задачи не выдаёт, `start` отказывает под замком и откатывает ветку; общие пути (`SHARED_PATHS`) не пересекаются ни с кем, мягкие (`SOFT_OVERLAP_PATHS`) — только друг с другом ([ADR 0023](0023-d7-shared-document-paths.md))                                                                                                                                                                                                                                                 | До B7 общие реестры правила каждая фича: жёсткий запрет остановил бы почти всё или приучил бы занижать `touches`. ## Поправка 2026-11-23: общие пути вне пересечения touches

Основание — прямое поручение владельца (2026-11-23, элемент `d7tail`: «`docs/escaped-defects.md` — общий хвост вне пересечения `touches`»). Правило реестра пропущенных дефектов (`AGENTS.md`, «Всегда»; [escaped-defects.md](../escaped-defects.md)) обязывает каждое исправление нести строку тем же PR, поэтому путь входил в `touches` каждой задачи-исправления, и запрет при пересечении (D7, #149) выстраивал их в очередь, хотя реестр append-only и конфликты в нём тривиальны. Файл, который правит каждая задача, — дефект структуры ([architecture.md](../architecture.md), З9): из режима `touches` изъят путь, а не правило реестра. Работа идёт вне доски, файла задачи нет — журнал ведётся здесь; строка за этот дефект — в реестре.

### Решение

- Общий путь — одна константа `SHARED_PATHS` в `tools/backlog-board.ts`, её читают обе стороны: `touchesOverlap` не считает такие записи пересечением (захват, `next`, `next --operator`), `fileInTouches` разрешает такой файл любой задаче независимо от `touches` (гейт `branch-scope`). Задачам больше не нужно указывать путь в `touches`; указанный не мешает.
- Развилка «вывести реестр из-под правила „строка тем же PR“». Отклонено: правило держит метрику escaped defects, а без изъятия пути задачи вынуждало бы занижать `touches` — тогда `branch-scope` красит честную правку реестра; ровно этот риск записан в строке «Что можно параллельно». Условие возврата — если реестр перестанет быть append-only (правка чужих строк): путь убирают из `SHARED_PATHS`.
- Развилка «чем считается общий путь». Выбрано буквальное совпадение записи с константой: «каталог/**», покрывающий общий путь, общим не считается — такой захват пересекается с задачами по остальным файлам каталога. Альтернатива — glob-семантика. Условие возврата — появится общий каталог целиком.
- Развилка «вести журнал в файле задачи». Отклонено: работа вне доски по прямому поручению, файл задачи не заводится (как у поправки [ADR 0009](0009-operator-delegation.md)). Условие возврата — у элемента появится файл задачи: журнал переносится в его «Журнал».
- Список пополняется только через ADR: путь в нём разрешён любой задаче. Кандидатов нет. Объявленный общий документ (`docs/architecture.md`) в него не берут — ему нужен мягкий список: [поправка 2026-11-24](#поправка-2026-11-24-мягкие-пути-объявленные-в-touches).

## Поправка 2026-11-24: мягкие пути, объявленные в touches

Основание — задача [e72](../../backlog/done/e72.md): D7 выстраивал в очередь из одной задачи все задачи обвязки, объявлявшие `docs/architecture.md` (16 открытых задач на main 77323543). Документ — не append-only реестр: правка законов обязана оставаться объявленной, поэтому в `SHARED_PATHS` он не входит. Решение, альтернативы и условие возврата — [ADR 0023](0023-d7-shared-document-paths.md); журнал и замер очереди — в файле задачи.

### Решение

- Мягкий путь — вторая константа, `SOFT_OVERLAP_PATHS` в `tools/backlog-board.ts` (сейчас `docs/architecture.md`). Пара двух мягких записей пересечением не считается (`touchesOverlap`: захват, `next`, `next --operator`). `fileInTouches` его не разрешает: гейт `branch-scope` красит правку документа в дереве задачи, не объявившей его.
- Сравнение буквальное: запись `каталог/**`, покрывающая мягкий путь, мягкой не считается. Общий путь, как прежде, не пересекается ни с кем.
- Развилка «убрать мягкую запись из счёта целиком, как общий путь». Отклонено: освобождало бы и пару с `docs/**`. Условие возврата — в ADR 0023, «Альтернативы».
- Список пополняется только через ADR. Кандидатов нет.

## Что отвергнуто

- **Оркестратор как основа** (ведущая сессия раздаёт задачи субагентам или сессиям). Механизм у каждого клиента свой, перенести его между ZCode, Claude Code и Codex нельзя. Доска не мешает оркестратору: он может вызывать те же команды.
- **Готовые инструменты.** Спецификация [tasks.md](https://github.com/tasksmd/tasks.md) и форк [Backlog.md с захватами](https://github.com/lunetics/Backlog.md) решают ту же задачу, но на 2026-11-14 это проекты одного автора без подтверждённого применения. Условие возврата: один из форматов поддержат сами клиенты.
- **Сервер очереди с арендой.** Противоречит З12 и не нужен, пока агенты работают в одном клоне.
- **Закрытие задачи удалением файла** (как сейчас в roadmap). Вместе с файлом пропадает журнал, опечатка в `depends_on` неотличима от закрытой задачи без истории git, а случайное удаление чужой задачи молча её закрывает.

## Последствия

- Захват виден только внутри одного клона. Агент на другой машине или в облаке чужих захватов не видит — этот случай не поддерживается до появления второго слоя.
- Доска обновляется с опозданием на merge: задачи из декомпозиции нельзя взять, пока человек не слил её PR. Это намеренно — декомпозицию сначала ревьюят.
- Настоящую параллельность ограничивают общие файлы. Для продуктовых фич это реестры (`router.ts`, barrel-файлы, `openapi.json`) — задача B7. Для задач самой обвязки это `AGENTS.md`, `tools/verify-steps.ts`, `ci.yml`, `tools/protected-paths.json`, `CODEOWNERS`, `.claude/settings.json`: такие задачи идут по очереди, что совпадает с правилом «один гейт на один PR». `docs/architecture.md` (статусы законов) с 2026-11-24 — мягкий путь: его объявляют в `touches`, но очереди он не создаёт ([ADR 0023](0023-d7-shared-document-paths.md)).
- В ZCode нет контура L0: формат после правки и `verify` перед завершением агент запускает сам, по инструкции. Гарантией остаются Lefthook и CI. Адаптер хуков для ZCode — задача C10; как новый контур он потребует своего ADR.
- Хук `Stop` Claude Code считает `*.md` документацией и `verify` не запускает: сломанную доску после декомпозиции покажет только CI, пока `backlog/**` не причислен к коду (входит в D3).
- Команды и проверка лежат в `tools/` — защищённый путь, внедрение требует режима обслуживания.
