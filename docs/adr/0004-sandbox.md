# ADR 0004: Песочница Bash-агента на уровне ОС

- Статус: принято (внедрено 2026-11-13, roadmap A2 пункт 4 — последняя закрытая часть A2)
- Дата: 2026-11-13
- Контекст: [architecture.md](../architecture.md) (З4, З10), задача A2, [ADR 0003](0003-result-based-protection.md), задача e70 (амендмент 2026-11-24 — «`pnpm install` из песочницы»)

## Проблема

Хуки агента (ADR 0003) — подсказка и проверка по результату внутри процесса агента. Сознательный обход они не останавливают (заявленное исключение — перезапись state тем же uid). Границей для сознательного обхода оставалась только L3 (CI из доверенной базы), а запрет записи в защищённые пути не был встроен в сам инструмент (З4): хук может не успеть, агент может работать в хосте без хуков проекта (ZCode, класс C10). Нужен запрет на уровне ОС: Seatbelt на macOS, bubblewrap на Linux.

## `pnpm install` из песочницы (амендмент e70, 2026-11-24)

**Граница:** `pnpm install` из песочечного Bash в этом репозитории не работает и не поддерживается. Зависимости ставит старт сессии агента (вне песочницы командного инструмента) либо человек в своём терминале. Доказательства и команды прогонов — `docs/research/2026-11-sandbox-pnpm-install.md` (в проект из шаблона не едет, поэтому без ссылки).

Почему гранта `~/Library/pnpm/store` мало (pnpm 12.21.0, Claude Code 2.1.330, живые прогоны):

1. **Блокировки хранилища лежат вне хранилища.** pnpm держит их в `/tmp/pnpm-store-operation-locks-<uid>` (на macOS — `/private/tmp/…`; при `$XDG_RUNTIME_DIR`, доступном только владельцу, — там). Установка падает на первом шаге — `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK … Operation not permitted (os error 1)` — в том числе когда `node_modules` уже соответствует lockfile.
2. **Открытие каталога блокировок установку не чинит.** pnpm отказывается от общего хранилища («packages cannot be hard linked from it into this project»), создаёт проектный `.pnpm-store`, начинает импорт пакетов и падает с `Operation not permitted`: первый отказ — `.vscode/launch.json` пакета `docker-modem` (этого пути нет в `denyWrite`, его защищает сам Claude Code); прямыми пробами подтверждены отказы на вложённых `.gitignore`, `.eslintignore`, `.prettierignore` — собственный `denyWrite`. Побочно остаются проектный store и недособранный `node_modules`.

**Решение:** `allowWrite` не расширять — каталог блокировок в гранте заменяет быстрый чистый отказ медленным падением с побочными эффектами. Альтернатива — расширить `allowWrite` каталогом блокировок — отклонена: без варианта A находки 3 задачи b8 (`backlog/done/b8.md`: развести `denyWrite` и `deny` правилом исключений для глобов, совпадающих с файлами пакетов) и пока Claude Code защищает пути файлов пакетов установку она не завершает. Условие возврата: вариант A принят и песочница Claude Code не запрещает файлов пакетов — тогда расширить `allowWrite` каталогом блокировок синхронно со строкой «Запись» и повторить живую установку по методике research-документа. Сеть `allowedDomains: [registry.npmjs.org]` оставлена как есть: гейт `sandbox` держит её точным множеством, сужение — отдельное решение.

**`pnpm preflight` в песочнице** остаётся красным на проверке `node_modules` — сверить не удалось, а слепая проверка обязана шуметь (З4), — но называет причину и выход, а не «дрейф lockfile»: код `ERR_PNPM_STORE_DIR_OPEN_OPERATION_LOCK` вместе с «Operation not permitted» в stderr даёт «песочница агента не даёт pnpm открыть блокировку хранилища … → исправь: pnpm install --frozen-lockfile вне песочницы агента — в своём терминале»; та же ошибка без запрета песочницы и любой иной код ошибки pnpm попадает в сообщение как есть (`packages/preflight/src/checks.ts`, канарейка — `packages/preflight/src/checks.test.ts`, шаг `test`). Уровень `error` оставлен: понизить до предупреждения — значит зелёный preflight на непроверенном `node_modules`.

## Доверенная граница

Песочница — граница против **процессов агента**: сознательная команда не пишет в защищённые пути файловой операцией и не выходит из песочницы (strict, без исключений команд). Заявленные остатки, где границей остаётся ADR 0003 (снимок, detect-and-revert) + L3:

- **docker.sock**: демон работает вне песочницы и пишет в хост (`docker run -v` доносит до защищённых путей). Сокет сужен до docker.sock ровно потому, что `pnpm visual` требует Docker; ssh-agent и прочие сокеты закрыты. Отменить изменение может снимок; закоммиченное останавливает L3.
- **Запись самого каталога-записи** (`mv tools tools.bak`): глоб `tools/**` не покрывает запись каталога; переименование меняет старые пути и ловится снимком.

За границей: сам хост вне песочницы (человек), коммиты (gate-integrity, ADR 0002), перезапись state контура (ADR 0003 — тихое исключение). Модель ADR 0003 (L0 — случайный обход, L3 — сознательный) ужесточается: значительная часть сознательных обходов останавливается на L0.

## Режим обслуживания: известное тихое окно

Пока `settings.local.json` существует: хуки выключены (включая `SessionStart` — напомнить о нём технически нечем) и песочница отключена. Границей остаётся CI (label-flow) и ревью. Человек удаляет файл после работы — чек-лист в [AGENTS.md, раздел «Claude Code»](../../AGENTS.md#claude-code). Одноразовая альтернатива для одиночной команды: `claude --settings '{"sandbox":{"enabled":false}}'` — файл не создаётся, забыть невозможно.

## Откат

`sandbox.enabled: false` или удаление блока — labeled PR (файл в `deny`). Гейт `sandbox` падает вместе с блоком и напомнит либо восстановить, либо убрать проверку тем же PR.
