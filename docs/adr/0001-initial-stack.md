# ADR 0001: Стек первой реализации

- Статус: принято
- Дата: 2026-11-01
- Контекст: [vision](../vision.md), [исследование стека](../research/2026-11-tech-stack.md)

## Решения

| Область                 | Решение                                                                                                                                  | Почему                                                                                                                                                | Альтернатива и когда к ней вернуться                            |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Тулчейн                 | Oxlint, Oxfmt, Vitest, Vite 8 подключены напрямую, оркестрация через Turborepo                                                           | Те же инструменты, что внутри Vite+, но без нового слоя абстракции, которому месяц. Turborepo даёт `--affected`, кэш и self-hosted remote cache       | Vite+ (`vp`), когда у него появится remote cache и устоится API |
| Пакетный менеджер       | pnpm 12 (Rust), catalogs в strict-режиме, `minimumReleaseAge`, `allowBuilds`                                                             | Скорость, единые версии для 50 человек, supply-chain защита по умолчанию                                                                              | pnpm 11: lockfile совместим, откат — смена `packageManager`     |
| Язык                    | TypeScript 7 (нативный)                                                                                                                  | typecheck всего репо за доли секунды                                                                                                                  | —                                                               |
| TS API для инструментов | `packageExtensions` подкладывает `@typescript/typescript6` только dependency-cruiser и Stryker                                           | У TS 7 нет JS API до 7.1                                                                                                                              | Убрать после выхода TS 7.1                                      |
| Frontend                | TanStack Start + TanStack Query, без Nitro (`vite preview` / server entry)                                                               | Vite-нативный, type-safe роутинг. Nitro всё ещё RC                                                                                                    | Next.js 16, если понадобятся RSC или CMS-экосистема             |
| Серверное состояние     | TanStack Query: оптимистичные обновления в кэше, инвалидация после последней мутации                                                     | Повторный `router.invalidate()` присоединяется к уже идущему loader-запросу («donor flight» в router-core), и быстрые мутации видят устаревшие данные | —                                                               |
| Backend                 | Hono + oRPC (contract-first), Node 26 запускает TS напрямую                                                                              | Контракт в `packages/contracts` — единый источник правды для фронта, бэка и OpenAPI. Сборка бэкенда не нужна                                          | Fastify / NestJS, если понадобятся их экосистемы                |
| Хранилище               | In-memory репозиторий за интерфейсом                                                                                                     | Демо-домен, цель — обвязка                                                                                                                            | Postgres + Drizzle следующим шагом                              |
| Скриншоты               | Vitest `toMatchScreenshot` (компоненты) + Playwright `toHaveScreenshot` WebP (страницы), только в Docker-образе Playwright `linux/amd64` | Детерминизм: те же шрифты и архитектура, что в CI. Базлайны без суффикса платформы                                                                    | Argos как слой ревью диффов, когда их станет много              |
| Перф                    | Playwright: TTFB/LCP/CLS и время сценариев с CPU-троттлингом x4; бюджет бандла; k6 smoke для API                                         | Детерминированно и без SaaS                                                                                                                           | Lighthouse CI, CodSpeed                                         |
| Качество тестов         | StrykerJS (incremental, perTest)                                                                                                         | Coverage не показывает, ловят ли тесты ошибки                                                                                                         | —                                                               |
| Границы                 | dependency-cruiser (+ Oxlint `import/no-cycle`)                                                                                          | Правила с обратными ссылками (`features/$1`), проверка в CI и pre-push                                                                                | Turborepo boundaries, когда выйдут из experimental              |
| Агенты                  | AGENTS.md (стандарт AAIF) + `.claude/` (хуки, скилы, ревьюеры) + Playwright Test Agents с политикой «без fixme»                          | Хуки исполняются гарантированно, инструкции — нет                                                                                                     | —                                                               |

## Последствия

- Обновление Playwright требует перегенерации Test Agents и повторного применения политики (см. CLAUDE.md).
- Скриншот-тесты локально требуют Docker.
- Пороги перфа откалиброваны на машине разработчика. После первых прогонов в CI их нужно перекалибровать (это делает человек).
