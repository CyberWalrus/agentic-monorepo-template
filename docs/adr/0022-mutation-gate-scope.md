# ADR 0022: Граница мутационного гейта — чекеры, preflight и e2e-инфраструктура не мутируются

- Статус: принято (2026-11-23, merge #167)
- Дата: 2026-11-23
- Контекст: [ADR 0009](0009-operator-delegation.md) (правило стартовых порогов), [ADR 0014](0014-tools-protection-classes.md) (классы защиты `tools/`), [ADR 0002](0002-gate-integrity.md) (изменение гейтов), [ADR 0020](0020-e2e-workspace-isolation.md) (workspace-изоляция e2e), [architecture.md](../architecture.md) З6 (канарейка и бюджет у каждого гейта) и З7 (мутационные пороги — храповик), [escaped-defects.md](../escaped-defects.md) (обратная связь «дефект → гейт или записанная невозможность»), задача d18; смежная слепая зона web `.tsx` — задача b2.2 (журнал в `backlog/done/b2.2.md`). Задача b2.2, подключившая StrykerJS к web и контрактам, mutate-списки на обвязку сознательно не расширяла; решение «не распространяем» до этого ADR нигде не зафиксировано — выбор каждый раз воспроизводился бы заново.

## Проблема

Мутационный гейт существует в трёх конфигах — `apps/api/stryker.config.json` (mutate `src/**/*.ts` без тестов и `server.ts`, break 75), `apps/web/stryker.conf.json` (`src/**/*.ts` без тестов и `routeTree.gen.ts`, break 67), `packages/contracts/stryker.conf.json` (`src/**/*.ts` без тестов и `index.ts`, break 80); задачу `mutation` определяют только эти три пакета (`pnpm mutation` = `turbo run mutation`). Деревья самой гейт-инфраструктуры не мутируются нигде: `tools/` (~18,2 тыс. строк `.ts` вне тестов, замер `find tools -name '*.ts' -not -path '*/test/*' -not -name '*.test.ts' | xargs wc -l`), `packages/preflight` (573 строки вне тестов), e2e-инфраструктура (`e2e/fixtures.ts` — workspace-изоляция и `uniqueTitle`, 158 строк; `e2e/global-setup.ts` — токен прогона, 45 строк; гейт трассировки `e2e/features/traceability/traceability.spec.ts`, 167 строк). Их дефекты тихо ослабляют весь гейт-контур: гейт, который перестал ловить, зелёный на плохом коде.

При этом слепые зоны мутаций описаны в репозитории разрозненно: web `.tsx` — в [architecture.md](../architecture.md) §2.4 и статусных пометках законов, обвязка — нигде. Единой записи «что мутационно не проверяется и почему» нет, и нет условия, при котором решение пересматривается.

## Решение

**Мутационный гейт остаётся на трёх деревьях с node-тестами — `apps/api`, `apps/web` (`*.ts`), `packages/contracts`; на чекеры `tools/`, хуки, `packages/preflight` и e2e-инфраструктуру он не распространяется.** Существующие исключения внутри списков держат тот же принцип «мутируется только логика, проверяемая в node-проекте»: `server.ts` — проводка без логики ([architecture.md](../architecture.md) §2.3), `index.ts` контрактов — re-export, `routeTree.gen.ts` — генерируется.

Слепые зоны мутаций — единая точка входа; при появлении нового дерева без мутаций в эту таблицу добавляется строка с причиной.

| Слепая зона                                                                             | Почему не мутируется                                                                                                                                                                                                                                                                                                                                                                                                                                            | Чем держится вместо мутаций                                                                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Чекеры `tools/` и хуки (`tools/hooks/`, 905 строк — тонкие адаптеры, логика в `tools/`) | Полная мутация ~18 тыс. строк дорога (оценка в «Отвергнутом варианте»); перенос ядер в мутируемый пакет — массовая правка deny-путей ([ADR 0014](0014-tools-protection-classes.md))                                                                                                                                                                                                                                                                             | Ядра прогоняются юнитами `tools/test/` (54 файла) end-to-end на подставных деревьях с утверждением шага/сообщения/exit-кода; проводка verify держат 44 канарейки `tools/gate-canaries.ts` (известный bad-change → красный шаг, проверка по результату — З3); проводка хуков — wiring-канарейки на `test:hooks` |
| `packages/preflight`                                                                    | Ядро (`checks.ts`) чистое с DI-швом `RunCommand`, мутации были бы дёшевы, но ценность мала: каждый сценарий проверки уже утверждает своё сообщение с командой исправления, а дефект preflight виден немедленно — preflight запускается первым в каждой сессии и его вердикты читает человек                                                                                                                                                                     | `checks.test.ts` (строгий фейк-раннер, каждое сообщение с командой исправления) и `cli.test.ts` (реальный spawn); ежедневное использование как дымовая проверка                                                                                                                                                |
| E2E-инфраструктура (`fixtures.ts`, `global-setup.ts`, гейт трассировки)                 | Это тестовая инфраструктура, проверяемая самим прогоном: сломанная фикстура не проходит тихо — роняет сценарии, которые она обслуживает (сломанный workspace-заголовок лишает сценарии изоляции, count-чеки краснеют — [ADR 0020](0020-e2e-workspace-isolation.md); гейт трассировки сверяет число объявлений тестов с числом распознанных тегов — дрейф regex красит прогон)                                                                                   | Сам прогон `pnpm e2e` / `pnpm verify --full`; внутренние дрейф-чеки `traceability.spec.ts`; расхождение «смержена — доска не знает» ловит `pnpm backlog doctor`                                                                                                                                                |
| Web `.tsx` (компоненты и хуки фич)                                                      | StrykerJS не поддерживает browser mode Vitest — мутациями проверяется только то, что тестируется в node-проекте (задача b2.2; [architecture.md](../architecture.md) §2.4)                                                                                                                                                                                                                                                                                       | Поведенческие browser-тесты (Vitest browser mode) и визуальный контур ([ADR 0015](0015-visual-baselines-approval.md), условие перехода на Argos — [ADR 0019](0019-argos-adoption-trigger.md)); целевое правило §2.4 — логика в модулях `*.ts` без React                                                        |
| `packages/ui` (презентационные компоненты, всё `.tsx`)                                  | StrykerJS не поддерживает browser mode Vitest, а node-тестируемой логики в пакете нет (в отличие от web): активация мутанта идёт через `process.env` рантайма мутированного кода (`@stryker-mutator/instrumenter`, syntax-helpers), которого в Chromium-iframe browser mode нет — и vitest-runner, и command runner дают ложных «выживших»; проверено экспериментом b15: 53/53 мутантов «выжили» при зелёном начальном прогоне (журнал в `backlog/done/b15.md`) | Поведенческие browser-тесты (Vitest browser mode) и визуальный контур ([ADR 0015](0015-visual-baselines-approval.md)); целевое правило то же, что §2.4 — поведенческая логика в модулях `*.ts` без React                                                                                                       |

**Компенсирующий контур `packages/ui` — порог покрытия (e59, 2026-11-24).** Раз мутации для ui невозможны, единственный автоматический барьер против регрессии презентационных компонентов — покрытие unit-проекта: `@vitest/coverage-v8` снимает данные в browser mode (Chromium через `@vitest/browser-playwright`), порог стоит в `packages/ui/vitest.config.ts` (deny) — lines 98, branches 94, functions 98, statements 98, то есть факт 100 / 96.29 / 100 / 100 вниз до целого минус 2 п.п. по правилу [ADR 0009](0009-operator-delegation.md). Считает и красит шаг `test` verify: покрытие включает флаг `--coverage` в скрипте `test` пакета, одних `thresholds` в конфиге для этого мало. Контур слабее мутаций: покрытие показывает, что код исполнялся, а не что утверждения сильные, — оно держит удаление тестов и потерю веток, но пропускает ослабление ассертов. Поэтому правило «поведенческая логика в модулях `*.ts` без React» остаётся целевым, а возврат к мутациям описан в «Условии возврата».

## Отвергнутый вариант: вынести чистые ядра чекеров в мутируемый пакет

Вариант рассмотрел и отклонил по сумме цены и ценности; оба слагаемых — оценки (точный замер требует конфига Stryker для `tools/`, а его создание само стоит в deny — [ADR 0014](0014-tools-protection-classes.md)), поэтому записаны как оценки, не замеры:

- **Цена переноса.** Шов «чистое ядро / main» у чекеров уже есть там, где он был нужен (`check-perf-trend(.main).ts`, `check-mutation-ratchet(.main).ts`, `telemetry-report(.main).ts`, `gate-approval-core.ts`, `visual-approval-core.ts`) — извлекать нечего, осталось бы _перенести_ файлы в отдельный пакет. Каждый перенос — правка deny-путей: окно режима обслуживания оператора на живом гейт-контуре, ревью CODEOWNERS, `gate-change-approved` ([ADR 0002](0002-gate-integrity.md)); массовый перенос размораживает защиту контура ради защиты от дефектов контура.
- **Цена прогона.** Тесты ядер — интеграционные: 34 из 54 файлов `tools/test/` спавнят процессы (`git`, `node`, `vitest` на временных клонах), per-file таймауты 30–60 с (прецедент: флак `test:hooks` на дефолтных 5 с — строка 2026-11-13 в [escaped-defects.md](../escaped-defects.md)). Stryker исполняет затронутые тесты на каждого мутанта: при характерной для TS плотности ~1 мутант на 10–20 строк 18 тыс. строк дают порядка 1–2 тыс. мутантов и часы на полный прогон — против 50 с полного прогона трёх текущих пакетов без incremental (замер b2.2; повторно 14 с).
- **Ценность ограничена.** Мутации добавляют ценность там, где ассерты слабые. У чекеров это место закрыто дважды: фикстуры `tools/test/` прогоняют чекер end-to-end и утверждают результат (шаг, сообщение, exit-код), а канарейки подают известный bad-change в живой `verify` и утверждают красный шаг — «гейт ловит» проверяется по результату (З3), ослабление фикстуры при живом чекере канарейка замечает. Выжившие мутанты концентрировались бы в клее: разбор аргументов, форматирование отчётов, проводка exit-кодов — наименьшая ценность при наибольшей цене.

## Условие возврата

- **Триггер — escaped defect (по данным, образец стиля [ADR 0019](0019-argos-adoption-trigger.md)):** строка в [escaped-defects.md](../escaped-defects.md), где дефект чекера/хука/preflight/e2e-инфраструктуры прошёл юниты (`tools/test/` или тесты preflight/e2e) и канарейки и найден после merge. Каждая такая строка переоткрывает этот ADR: заводится узкий mutate-контур с конкретного файла — Stryker (vitest-runner), mutate = ядро этого файла, стартовый порог по правилу [ADR 0009](0009-operator-delegation.md) (факт, округлённый вниз, минус 5 п.п.), канарейка по З6. Контур расширяется по храповику З7, а не «весь `tools/` сразу». Ведёт оператор — все пути под deny ([ADR 0014](0014-tools-protection-classes.md)).
- **Технический триггер для browser-деревьев (web `.tsx`, `packages/ui`):** поддержка browser-mode раннера в StrykerJS (или эквивалентного мутатора браузерных тестов, не зависящего от `process.env` рантайма мутированного кода) переоткрывает строки таблицы web `.tsx` и `packages/ui`; до того опция технически недоступна и правилу §2.4 «логика в `*.ts`» это не изменение.

- **Возврат к мутациям в `packages/ui` — задача b19** (до триггера `needs_human: отложено:`): когда срабатывает технический триггер выше, мутационный контур для ui заводится по плану b15 (конфиг Stryker, скрипт `mutation`, ночная сборка, храповик) поверх компенсирующего порога покрытия — порог при этом не снимается: мутации добавляются к барьеру, а снять или понизить порог может только человек (З7). Второй вход в b19 — ADR о выносе поведенческой логики ui из `.tsx` в node-тестируемые модули `*.ts`: такая логика уходит из browser-покрытия в мутации, и порог пересматривается тем же PR (понижение — решение человека).
