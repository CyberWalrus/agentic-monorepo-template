# ADR 0006: Перф-стратегия — два уровня вместо абсолютных потолков

- Статус: принято (решения человека 2026-11-14, реализация PR-1..PR-3 A6)
- Дата: 2026-11-14
- Контекст: [roadmap A6](../roadmap.md) — десятикратная регрессия времени проходит абсолютные потолки (LCP 64 мс CI при потолке 1500), а бюджет бандла стоит вплотную (149.8/160 КБ total, 125.6/130 КБ крупнейший чанк). Пороги времени калиброваны под машину разработчика и шумят на общих раннерах. Решения приняты человеком по пакету вариантов с последствиями (2026-11-14); реализация — три PR: детерминированные метрики, дельта-гейт бандла (свой ADR в своём PR), nightly-сравнение.

## Решения

| Область                         | Решение                                                                                                                                                                                                                                                                                      | Почему                                                                                                                                                                                                           | Альтернатива и когда к ней вернуться                                                                                                   |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Уровень 1 (PR)                  | Детерминированные метрики в perf-тесте: wire-байты JS/CSS, число запросов (все и `/rpc`) на холодную загрузку, число `/rpc`-запросов и long tasks на сценарий при CPU×4, LCP под Fast 3G                                                                                                     | Без шума: запросы и байты идентичны между прогонами (проверено двукратным прогоном), ловят те же регрессии, что времена, без статистики. Пороги — факт CI + запас, стартуют щедро и затягиваются храповиком (З7) | Инструментирующие сервисы (CodSpeed) — необязательный слой для микробенчмарков, не ядро (З12)                                          |
| Уровень 2 (nightly)             | Медианное сравнение с базой = **последний зелёный nightly** (артефакт `perf-baseline` с SHA прогона), не merge-base — у ночного прогона на main его нет (решение человека)                                                                                                                   | Не требует второй сборки; красный прогон базу не двигает. При регрессии — issue с диапазоном `baseline-SHA..head-SHA`, владелец из CODEOWNERS, дедуп по открытому issue с label `perf-regression`                | Сравнение с merge-base в PR — удвоение времени каждого PR и шум на общих раннерах; вернуться, если ночной канал окажется недостаточным |
| Отступление от критерия roadmap | Задержку 200 мс в обработчике **в PR не ловит ни одна метрика** (95+200 < 600): детерминированные метрики не видят времени, потолки слишком щедры. Временнóй канал — только nightly-сравнение. Записано как **решение человека**                                                             | Временнóй гейт в PR требует чередования база/кандидат (10+ прогонов) — дорого и шумно; PR-гейт ловит структурные регрессии (вес, запросы), ночной — временнúе                                                    | Временнóй дельта-гейт в PR — вернуть, если ночной канал пропустит регрессию, замеченную человеком                                      |
| Канарейки                       | +30 КБ кода и лишний `/rpc`-запрос роняют PR-гейт (шаги `bundle` и `perf`); 200 мс роняет nightly-сравнение (job `perf-canary`, инверсия: красное сравнение = job зелёный); 20 прогонов без изменений — ноль ложных                                                                          | Каждое «готово, когда» из roadmap покрыто своим уровнем                                                                                                                                                          | —                                                                                                                                      |
| Ночные допуски                  | Запросы — точное совпадение; байты — с допуском `maxPrGrowthKb` (одобренный человеком рост не создаёт ночной issue); время — max(абсолютный floor, %), калибровка 20-прогонной валидацией; long tasks — медиана + допуск 1; метрика отсутствует в кандидате или базе — красный (fail-closed) | Нулевой допуск по байтам превратил бы каждое одобренное изменение в ночной шум (ревью sanity)                                                                                                                    | —                                                                                                                                      |
| Абсолютные потолки              | Предложение по цифрам CI-раннера (2026-11-13): TTFB 13.2 → **40 мс**, LCP 64 → **200 мс**, CLS 0 → **0.05** (без изменения), create-task 109.6 → **300 мс**, toggle-task 79.4 → **240 мс**; финальные числа ставит человек своим PR                                                          | Запас ~3× ловит как регрессию, так и деградацию опыта (З7: порог поднимает только человек)                                                                                                                       | Оставить текущие 400/1500/600/400 — десятикратная регрессия пройдёт                                                                    |
| Сеть в замерах                  | LCP замеряется и без троттлинга (преемственность фактов), и под Fast 3G через CDP `Network.emulateNetworkConditions` — начинает зависеть от веса страницы (roadmap п.5); троттлинг CDP — машинно-независимый (факт 360/356 мс на двух прогонах)                                              | Вес страницы становится видимым во временнóй метрике, а не только в байтах                                                                                                                                       | Полный профиль «Slow 4G» — если Fast 3G окажется слишком щедрым к весу                                                                 |

## Последствия

- perf-шаг в PR ловит структурные регрессии (новый файл на критическом пути, лишний запрос, вес чанка); временнúе — nightly. Разрыв по 200 мс в обработчике — осознанный, закрыт job `perf-canary` в nightly.
- Пороги детерминированных метрик стартуют с локальных фактов с запасом (страница: запросы ≤ 6 при факте 5, `/rpc` ≤ 0 — SSR отдаёт данные в HTML, и клиентский fetch = регрессия гидратации; сценарии: `/rpc` ≤ 10 при факте 10, long tasks ≤ 10 при локальном факте 0 — CI-раннер медленнее, порог затянется храповиком после фактов).
- Дельта-гейт бандла (5 КБ gzip от merge-base) и его доверенное одобрение — предмет отдельного ADR в PR-2 (заголовок gate-integrity.yml требует отдельного ADR на расширение доверенного workflow); `perf` выходит из канареечного вайтлиста З6 (канарейка «лишний `/rpc`-запрос»).
- Замеры детерминированных метрик идут по холодной загрузке в свежем контексте: тёплый кэш отдаёт пустые `encodedDataLength` и ломает детерминизм.
- Общий модуль `tools/perf-metrics.ts` — единственный источник ключей/схемы отчёта для perf-теста и тренд-чекера.
