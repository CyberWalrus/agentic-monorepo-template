# ADR 0015: Доверенный workflow одобрения визуальных базлайнов

- Статус: предложено (принимается merge этого PR человеком)
- Дата: 2026-11-19
- Контекст: [ADR 0002](0002-gate-integrity.md) (доверенные workflow, З2), [ADR 0013](0013-bundle-delta-gate.md) (доверенное одобрение по API-фактам), [ADR 0004](0004-sandbox.md), [ADR 0009](0009-operator-delegation.md), задача b3.1, [architecture.md](../architecture.md) §3.6, [github-setup.md](../github-setup.md) п. 3

## Проблема

Базлайны визуальных тестов обновляет только человек локально через Docker ([ADR 0005](0005-api-url.md), З4/A8). На машине без Docker агент не видит визуальный дифф до merge и не может довести визуальную правку до зелёного; базлайны стоят барьером между «код готов» и «PR готов».

## Принцип

Источник истины снимков — один: CI в образе Playwright. Человек одобряет результат, а не производит его: job `visual` при диффе перегенерирует снимки в том же образе и выкладывает их артефактом; мейнтейнер одобряет командой в PR; доверенный workflow коммитит снимки в ветку PR. «Отдельное осознанное действие человека» (З1/З2) сохранено — это команда одобрения в ленте PR, рядом с диффом (З11).

## Решение

| Область           | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                              | Почему                                                                                                                                                                                                                                           | Альтернатива и когда вернуться                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Одобрение         | Команда мейнтейнера в комментарии PR: ровно одна строка `/approve-visual <40-символьный sha>`. Workflow валидирует: автор — глобальный владелец CODEOWNERS (переиспользуется `tools/gate-approval-core.ts`, второй проверки не пишется), SHA совпадает с текущим head, комментарий новее последнего push (прокси — min `started_at` check-run'ов, как в gate-integrity). Само одобрение остаётся за человеком и оператору не делегируется (ADR 0009) | Одобрение остаётся в ленте PR рядом с диффом (З11); SHA закрывает подмену снимков пушем между просмотром и одобрением; свежесть — как у label-одобрений (ADR 0002/0013)                                                                          | `workflow_dispatch` с номером PR: проще по правам, но одобрение не видно в PR, номер и SHA вводятся руками; вернуться, если issue_comment-политика GitHub ужесточится |
| Сбор снимков      | Job `visual` при диффе: тихая вторая фаза в том же job — `VISUAL_UPDATE=1 PLAYWRIGHT_UPDATE_MODE=changed` перезаписывает только разошедшиеся базлайны; `git status` отдаёт канонические пути; артефакт `visual-actuals` = manifest.json (headSha + список) + png по путям репозитория                                                                                                                                                                | Оба раннера пишут базлайны по каноническим путям (vitest — шаблон в vitest.config, Playwright — `snapshotPathTemplate`), поэтому «что перегенерировано» читается напрямую из git, без парсинга отчётов                                           | Парсинг attachments из test-results: хрупкое восстановление канонических путей из имён директорий                                                                     |
| Коммит            | Доверенный workflow `.github/workflows/visual-approve.yml` (issue_comment, определение из дефолтной ветки): скачивает артефакт прогона CI на одобренном SHA, проверяет манифест и пути (только `__screenshots__/*.png`, без traversal и symlink), коммитит снимки в head-ветку PR и диспатчит `ci.yml` на ветку                                                                                                                                      | Артефакт едет в собственную ветку PR (недоверенную по определению), merge по-прежнему требует ревью и зелёного gate; GITHUB_TOKEN push события не рождает, поэтому CI диспатчится явно — иначе required-check'и на новом SHA никогда не появятся | Коммит от имени приложения: у репозитория нет App; PAT в секреты не кладём                                                                                            |
| Доверие артефакту | Артефакт производит код PR (visual job его исполняет), поэтому: манифест обязан совпасть с одобренным SHA; пути — только канонические базлайны; symlinks из архива удаляются; checkout head — только git-операции, ни один скрипт дерева PR не исполняется                                                                                                                                                                                           | Коммит в собственную ветку PR не расширяет границу merge; санитизация закрывает хищение файлов раннера через symlink и traversal                                                                                                                 | Подпись артефакта — избыточно при комбинации SHA-привязки и whitelist путей                                                                                           |
| Политика          | Новый доверенный workflow добавляется в политику `docs/github-setup.md` п. 3 в интерфейсе GitHub — человек; PR содержит правку документа с инструкцией                                                                                                                                                                                                                                                                                               | Расширение набора доверенных workflow — решение уровня гейтов (З1/З2); до правки политики человек коммит не получит, workflow честно упадёт на push (fail-closed)                                                                                | —                                                                                                                                                                     |

## Что этот ADR не решает

- Одобрение визуальных диффов оператором или агентом — не делегируется (ADR 0009, «Что остаётся человеку»).
- Скриншот-базлайны остаются под `deny` (`**/__screenshots__/**`): агент, как и раньше, не пишет их руками — пишет CI по команде человека.

## Отвергнутые варианты

- **Статус-кво** (человек гоняет Docker локально): воспроизводит «машина человека» как часть контура качества и блокирует агентов без Docker.
- **`workflow_dispatch` + номер PR**: одобрение вне ленты PR; ввод руками; не привязан к SHA в комментарии.
- **Коммит базлайнов прямо из job `visual`**: visual job исполняет код PR и не может быть доверенным публикатором (З2).

## Условие возврата

- Инцидент: коммит базлайнов в ветку, не являющуюся head-веткой одобренного PR, или вне `__screenshots__` — workflow удаляется, источник снимков возвращается к локальному Docker.
- Двукратный ложный коммит из-за недетерминированного рендера между фазами (снимки «плавают» в CI) — пересмотреть схему двух фаз (одна фаза с диффом из артефакта первой).

## Реализация

- b3.1 (оператор): `tools/visual-ci.sh` (двухфазный job), `tools/visual-approval-core.ts` + `tools/check-visual-approval.ts` (валидация команды), `.github/workflows/visual-approve.yml`, проводка артефакта в `ci.yml` (+ `workflow_dispatch`), канарейка проводки и фикстурные тесты валидатора, `docs/github-setup.md` п. 3. Классы защиты новых файлов — `deny` тем же PR (гейт check-tool-class), `KNOWN_GATES` дополнен.
- Человек после мёржа: добавить `visual-approve.yml` в политику (github-setup.md п. 3), протестировать команду на реальном визуальном диффе.
