# ADR 0017: Каталог миграций — гейт «схема совпадает с миграциями» и expand/contract

- Статус: предложено (принимается merge этого PR человеком)
- Дата: 2026-11-20
- Контекст: задача c1.3 (зависимость c1.2 — постоянное хранилище за Drizzle). Схема Postgres — второй источник правды о форме данных рядом с `packages/contracts`: контракт виден клиентам, схема — базе. Без гейта она разъезжается с миграциями: колонка, удалённая из схемы, но живая в базе, typecheck не ловит (drizzle читает только объявленные колонки), интеграционные тесты — только при обращении к ней.

## Чек-лист операторского PR (проводка гейта, ADR 0014)

Все пути — `deny`, обычной сессии недоступны; делается одним маленьким PR по образцу `openapi`:

1. `tools/verify-steps.ts` (fast, после `openapi`): `{ name: 'schema', command: 'pnpm', args: ['--filter', '@repo/api', 'db:check'] }`.
2. `verify-budgets.json`: бюджет шага `schema` (файловая проверка ~1–2 с).
3. `tools/protected-paths.json`: `review` += `apps/api/src/tasks/migrations/**`.
4. `CODEOWNERS` (+ `docs/CODEOWNERS`, шаблон): путь каталога миграций → владелец.
5. Канарейка шага в `tools/gate-canaries.ts` (тест `tools/test/`): правка `schema.ts` без миграции обязана красить шаг `schema`.

До пункта 1 гейт enforcement-ится шагом `test` (unit+integration в `turbo test`), краснота и смысл те же.

## Что отвергнуто

- **`drizzle-kit push` в быстрой волне.** Требует живой базы на каждый verify; сверка с нуля и так стоит в Postgres-наборе, где контейнер общий на прогон.
- **Сверка только по снапшотам (без integration-волны).** Ручной SQL меняет базу мимо снапшотов: файловая волна слепа к нему по построению — именно её слепое пятно закрывает `pushSchema` на применённых с нуля миграциях.
- **Гонка миграций при параллельном старте реплик — в этом гейте.** Это рантайм-блокировка (advisory lock), не гейт дрейфа: выделена в задачу c1.6.
- **Сжатие (DROP) запрещать кодом гейта.** Сжатие легитимно — но отдельным шагом после выката; машина не отличит его от ошибки надёжнее человека, поэтому правило — процессное, а `DROP` в диффе красит гейт как любую правку без миграции.

## Последствия

- Дрейф «схема ↔ миграции» ловится в каждой быстрой волне verify в обе стороны; data-only миграции остаются возможными и видимыми человеку (warning + review-класс каталога).
- `apps/api` получил второй источник правды о форме данных с гейтом согласованности: контракт (`packages/contracts`) ↔ схема (`schema.ts`) ↔ база (миграции с нуля).
- Каталог миграций задокументирован для копирования в новые модули: README — образец дисциплины для следующего хранилища (C1.5 и далее).
