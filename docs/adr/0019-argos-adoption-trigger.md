# ADR 0019: Условие подключения Argos

- Статус: принято
- Дата: 2026-11-21
- Контекст: [ADR 0001](0001-initial-stack.md) (Argos — «слой ревью диффов, когда их станет много», условие не записано), [ADR 0015](0015-visual-baselines-approval.md) (доверенный workflow одобрения базлайнов), [ADR 0009](0009-operator-delegation.md) (что остаётся человеку), [ADR 0002](0002-gate-integrity.md) (изменение гейтов), [architecture.md](../architecture.md) §3.6, исследование стека в `docs/research/2026-11-tech-stack.md` (в проект из шаблона не едет, поэтому без ссылки; цены и возможности Argos), задача b3.4

## Проблема

ADR 0001 называет Argos альтернативой самодельному визуальному конвейеру, но формулировка «когда диффов станет много» не измерима: триггер нельзя проверить по данным, а цена перехода и судьба базлайнов не записаны. Пока «много/мало» решается на глаз, переход либо случается слишком рано (SaaS и внешний получатель данных вместо работающего конвейера), либо слишком поздно (очередь одобрений тормозит PR).

## Принцип

Условие срабатывания считается по данным, которые GitHub уже собирает: история прогонов job `visual` (ci.yml) и прогонов доверенного workflow `visual-approve.yml` ([ADR 0015](0015-visual-baselines-approval.md)). Новых счётчиков, ночных джоб и телеметрии не заводится — замер это несколько команд `gh api`, исполняемых руками за минуты.

## Решение

Переходим на Argos, когда сработал хотя бы один из двух триггеров.

| Триггер           | Метрика                                                                                                                                                                         | Порог                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Частота диффов    | Дифф-события: неуспешные прогоны job `visual` из-за отличия снимков (в этом прогоне выложен дифф-отчёт/артефакт `visual-actuals`; перезапуск того же прогона не дублирует)      | ≥ 50 за скользящие 7 дней, подтверждённые вторым замером неделю спустя — одиночный массовый рефактор UI триггером не считается       |
| Очередь одобрения | Медиана времени от `completed_at` job `visual` с диффом до `created_at` комментария `/approve-visual <sha>` (прокси времени комментария — `createdAt` прогона `visual-approve`) | > 24 ч на скользящем окне 30 дней при ≥ 5 одобрениях в окне; меньше пяти — выборка не показательна, триггер не считается сработавшим |

### Замер

```bash
# Триггер 1: дифф-события за период — неуспешные job visual по прогонам CI
gh api "repos/CyberWalrus/agentic-monorepo-template/actions/runs?workflow=ci.yml&created=>=YYYY-MM-DD&per_page=100" \
  --paginate --jq '.workflow_runs[].id' | while read -r id; do
  gh api "repos/CyberWalrus/agentic-monorepo-template/actions/runs/$id/jobs" \
    --jq '.jobs[] | select(.name == "visual" and .conclusion == "failure") | .id'
done

# Триггер 2: одобренные диффы; каждый успешный visual-approve = одна команда одобрения
gh run list --repo CyberWalrus/agentic-monorepo-template --workflow visual-approve.yml \
  --json createdAt,conclusion --jq '[.[] | select(.conclusion == "success")]'
# задержка одобрения: sha берётся из тела комментария /approve-visual <40-символьный sha>,
# для него — completed_at job visual (jobs API того же прогона CI по head_sha), затем разность с createdAt прогона visual-approve
```

Рецепты проверены 2026-11-21 против `CyberWalrus/agentic-monorepo-template` по всей истории CI (656 прогонов ci.yml): фильтр job `visual` по имени и `conclusion`, списки прогонов `visual-approve.yml` и поиск по `head_sha` работают; неуспешных job `visual` — 4 за всю историю, успешных одобрений — 0. Оба триггера далеко от порогов, замер разумно делать не чаще раза в месяц.

### Что происходит при срабатывании

- Результат замера (числа, окно, команды) прикладывается в файл задачи; без него задача не берётся — доказательство срабатывания обязательна.
- На доску ставится задача типа `decompose` «Подключение Argos»: её `touches` — `.github/**`, `tools/visual-ci.sh`, `tools/visual-approval-core.ts`, `tools/check-visual-approval.ts`, `tools/verify.ts`, `pnpm-workspace.yaml` — попадает в защищённые пути, поэтому задача режима обслуживания и ведёт её оператор ([ADR 0009](0009-operator-delegation.md)); в PR подключения — раздел «Изменения гейтов», ревью CODEOWNERS и label `gate-change-approved` ([ADR 0002](0002-gate-integrity.md)).

## Цена перехода (когда триггер сработал)

- Деньги и аккаунт: Hobby бесплатно до 5 000 скриншотов в месяц, Pro — $100 в месяц фиксировано (35 000 скриншотов, без ограничения участников); на старте хватает Hobby. Аккаунт и `ARGOS_TOKEN` в секретах Actions — действия человека ([ADR 0009](0009-operator-delegation.md)).
- Зависимость: `@argos-ci/core`, версия только в `catalog:` ([pnpm-workspace.yaml](../../pnpm-workspace.yaml)); supply-chain: снимки уезжают во внешний сервис — новый получатель данных, который раньше был только артефактом GitHub.
- Замена контура доверия: удаляются двухфазный `tools/visual-ci.sh`, валидатор `tools/visual-approval-core.ts` + `tools/check-visual-approval.ts` и `.github/workflows/visual-approve.yml` — всё из `deny` ([ADR 0014](0014-tools-protection-classes.md)); их возвращает revert PR, файлы живут в git-истории.
- Гейт по З5: шаг отчёта Argos добавляется одновременно в `tools/verify.ts`, job в ci.yml и `needs` у job `gate`; блокирует merge статус Argos. Среда снятия снимков остаётся прежней — Docker-образ Playwright `linux/amd64` с версией из каталога: Argos берёт на себя ревью и хранение, а не детерминизм; без закреплённого образа диффы «поплывут» уже на стороне Argos.
- Одобрение диффа остаётся действием человека: место действия меняется с ленты PR на UI Argos, в «Что остаётся человеку» [ADR 0009](0009-operator-delegation.md) строка про `/approve-visual` заменяется строкой про одобрение в Argos — тем же PR подключения.

## Что происходит с базлайнами

- До перехода источник истины — файлы `**/__screenshots__/**` в git: локально их обновляет человек после просмотра диффа, в CI создаёт доверенный workflow по команде человека ([ADR 0015](0015-visual-baselines-approval.md)).
- При переходе источник истины — стор Argos: файлы базлайнов удаляются из репозитория (git-история сохраняется, откат — возврат файлов revert-ом); `deny`-запись `**/__screenshots__/**` снимается тем же PR подключения — ослабление deny требует режима обслуживания и `gate-change-approved`; локальный `pnpm visual` остаётся генератором actuals для ручного триажа, обновление локальных базлайнов исчезает за ненадобностью.
- Ограничение [ADR 0015](0015-visual-baselines-approval.md) «удалённые базлайны второй фазой не покрываются» уходит вместе с контуром: у Argos базлайны общие для всех веток.

## Что этот ADR не решает

- Сам процесс подключения — его распишет задача при срабатывании триггера.
- Выбор между Argos и Chromatic зафиксирован в исследовании стека (`docs/research/2026-11-tech-stack.md`, в проект из шаблона не едет, поэтому без ссылки): Argos — MCP, CLI с `--json`, скилы и цена; revisit только при заметном изменении рынка.

## Отвергнутые варианты

- **Автоматический счётчик в nightly** (issue при срабатывании): `.github/**` — защищённый путь, а ручной замер занимает минуты; автоматика окупится, только если замеры станут частыми. Вернуться, если ручные замеры перестали делать.
- **Порог «любой дифф старше N дней»**: один забытый PR красил бы триггер; медиана по окну с минимальной выборкой устойчивее к единичным задержкам.
- **Перейти заранее, до срабатывания**: SaaS, аккаунт, секрет и внешний получатель данных без измеренной причины; аргумент «диффов пока мало» на дату ADR проверяем нулём.

## Условие возврата

- Argos стал узким местом (сервис лежит, тариф перестал устраивать, снимки больше нельзя отдавать наружу) — revert PR подключения восстанавливает прежний контур из git-истории; [ADR 0015](0015-visual-baselines-approval.md) с ним возвращается.
- Диффы снова стали редкими при оплаченном Pro — вопрос «оставлять ли $100 в месяц» выносится человеку; автоматического отката нет.
