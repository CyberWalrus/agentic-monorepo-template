# Доска задач (ADR 0007)

Один человек запускает несколько агентов и говорит каждому «продолжай по плану». Доска — файлы `backlog/<id>.md`; статус не хранится, а вычисляется: файл в `backlog/done/` — закрыта; есть ветка `task/<id>` — в работе; есть незакрытые `depends_on` или `needs_human` — заблокирована; путь из `touches` под `deny` из `tools/protected-paths.json` — нужен режим обслуживания; иначе свободна.

## Команды

| Команда                     | Кто вызывает   | Что делает                                                               |
| --------------------------- | -------------- | ------------------------------------------------------------------------ |
| `pnpm backlog list`         | агент          | доска со статусами; брошенные ветки и worktree                           |
| `pnpm backlog next`         | агент          | в worktree задачи — её состояние; иначе первая свободная                 |
| `pnpm backlog start <id>`   | агент          | захват веткой `task/<id>` от `main` + worktree рядом с репозиторием      |
| `pnpm backlog close <id>`   | агент          | закрыть задачу: перенос файла в `done/`; «Журнал» — итогом того же PR    |
| `pnpm backlog resume <id>`  | агент          | продолжить брошенную по прямому поручению человека                       |
| `pnpm backlog release <id>` | человек        | переименовать ветку в `abandoned/<id>`; требует интерактивного терминала |
| `pnpm backlog doctor`       | агент, nightly | расхождения «смержена — доска не знает»; расхождения красят nightly      |

Захват — атомарное создание ветки: два одновременных `start` одной задачи дают отказ второму («занято, возьми другую» — это не ошибка, возьми следующую через `pnpm backlog next`).

## Типы задач

- `research` — когда нельзя написать проверяемые критерии приёмки или выбор зависит от факта вне репозитория. Результат: ADR, файл в `docs/research/` или новые задачи. Журнал результатом не считается.
- `decompose` — задача не помещается в один PR или для неё нельзя назвать `touches`. Результат: файлы задач с `depends_on` и `touches`. Изменение контракта API — всегда отдельная задача, от которой зависят остальные.
- `change` — обычная фича/правка, скил `feature-workflow`.

## Правила

- Доска читается из ссылки `main`, не из рабочего дерева. Задача, добавленная в ветке, появляется на доске только после merge.
- `touches` — литеральные пути и `каталог/**`; произвольные glob-ы запрещены: их пересечение нельзя посчитать точно.
- Пересечение `touches` с задачами в работе не запрещает захват: `next` ставит такие задачи в конец и предупреждает.
- Чужую задачу в работе не брать и не перехватывать. Автоматического перехвата брошенных задач нет: освобождает человек через `release`.
- Задачу с режимом обслуживания агент не начинает: она требует правки защищённых путей. `next` перечисляет такие задачи человеку.
- На ветке `task/<id>` среди файлов доски меняется только свой файл; правки чужих задач — отдельный PR (`backlog/**` под review-защитой и CODEOWNERS).
- Прогресс задачи — её ветка (коммиты и дифф показывает `resume`/`next`). В разделе «Журнал» файла — то, чего нет в диффе: что решено и что дальше. План задачи и пакеты решений человека тоже живут в «Журнале» или в ADR — не в `/tmp` и не в памяти клиента: память агента хранит указатель на задачу, а не её состояние (ADR 0007, «Планы и пакеты решений»).
- Файл задачи переносится в `backlog/done/` сразу после захвата (`pnpm backlog close <id>` — гейт docs красит ветку `task/<id>`, пока файл открыт), «Журнал» дополняется до merge. Для работы вне доски по задаче с доски перенос делает PR, называющий `<id>` в теле. Расхождения «смержена, но открыта» перечисляет `pnpm backlog doctor` (ADR 0007, «Замыкание задачи»).
- Работа вне доски (прямое поручение человека) — в ветке с любым именем, кроме `task/*`.

## Проверка

Доску проверяет шаг `docs` (`tools/check-docs.ts`): схема front matter (`title`, `type`, `priority`, списки `depends_on` и `touches` в строку через запятую, `needs_human`), ссылки зависимостей, циклы, грамматика `touches` и правило «свой файл на своей ветке». Битая доска красит `docs:check` — канарейка в `tools/gate-canaries.ts` держит чекер живым.
