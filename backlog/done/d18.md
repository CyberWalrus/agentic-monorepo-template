# D18. ADR: мутационное покрытие гейт-инфраструктуры

**Проблема.** Логика гейтов (tools/check-*.ts и хуки, ~18 тыс. строк без тест-файлов), packages/preflight и e2e-инфраструктура (fixtures.ts — workspace-изоляция/uniqueTitle; гейт трассировки traceability.spec.ts) не мутируются нигде: ни один mutate-список трёх конфигов эти деревья не включает (перепроверено find/grep). Их дефекты тихо ослабляют сам гейт-контур; покрытие — unit-тесты test:hooks (54 файла tools/test/) и канарейки. Перепроверка аудита: решение «мутационный гейт на hooks-код не распространяется» не зафиксировано нигде как принятое.

## Что сделать

- ADR: либо вынести чистые функции чекеров в мутируемый пакет с vitest-раннером (оценка цены прогона против ценности), либо письменно зафиксировать «мутационный гейт на чекеры/хуки не распространяется, потому что …» с условием возврата.
- Заодно связать в одну запись слепую зону web .tsx (B2.2) — сейчас она в architecture.md:116 и roadmap, без единой точки входа по «что мутационно не проверяется и почему».

## Критерии приёмки

- ADR в docs/adr/ принят: выбранная опция, отклонённая, условие возврата записаны.
- architecture.md З7 ссылается на ADR; слепая зона web .tsx упомянута со ссылкой на B2.2.

## Решение

Задача research: выбор между двумя опциями — результат ADR, не код. Вводные: дефекты чекеров частично ловят 44 канарейки и фикстуры tools/test/; полная мутация tools/ (~18k строк) дорогая. Условие возврата: escaped defect в чекере, прошедший unit-тесты и канарейки, — переоткрыть ADR и завести mutate-контур.
