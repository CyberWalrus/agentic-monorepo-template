# D14. Правило ветки доски в гейте docs противоречит ADR 0007 для декомпозиций

**Проблема.** `boardBranchRule` в `tools/check-docs.ts` флагует **все** файлы в `git diff main...HEAD -- backlog/`, включая новые. Но ADR 0007 («Доска обновляется с опозданием на merge»: «задачи из декомпозиции нельзя взять, пока человек не слил её PR») и собственный docstring правила («среди **существующих** файлов доски меняется только свой») предполагают, что PR декомпозиции добавляет новые файлы задач на ветке `task/<id>`. D8 — первая декомпозиция после появления гейта (PR #28): её PR красный, все будущие декомпозиции будут красными. Правило работы: найти finding 2026-11-15 в журнале d8.

Задача ведёт оператор: `touches` — `tools/**`.

## Что сделать

- Сравнивать с базой только **существующие в `main`** файлы доски: правка или удаление чужого существующего файла задачи — красные; новые файлы доски разрешены (их защищают review-класс `backlog/**` в CODEOWNERS и ревью декомпозиции в PR — ADR 0007).
- Канарейку гейта docs (`tools/test/`) дополнить случаем «чужой существующий файл всё ещё красит» — чтобы фикс не выбил защиту.
- Проверить на живом PR декомпозиции (ветка `task/d8` с файлами d8.1–d8.7 ждёт этого фикса — см. журнал d8).

## Критерии приёмки

- PR декомпозиции d8 проходит шаг `docs` на ветке `task/d8`; правка чужого **существующего** файла задачи на ветке `task/<id>` по-прежнему красная (канарейка ловит).
- `pnpm verify --full` зелёный.
