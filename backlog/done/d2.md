# D2. Проверка трёх клиентов вживую

**Проблема.** Решения ADR 0007 опираются на документацию ZCode, а не на прогон; Codex не проверялся вообще. Не известно: может ли агент создать ветку и worktree сам; работает ли он в worktree вне каталога workspace; срабатывает ли Lefthook на его коммитах; как подключаются скилы проекта.

## Что сделать

В каждом из трёх клиентов (ZCode, Claude Code, Codex) попросить агента: создать ветку, создать worktree командой `git worktree add`, сделать в нём правку в `apps/`, выполнить `pnpm install` и `pnpm verify`, закоммитить. Записать, какой шаг прошёл, какой нет и почему. В ZCode отдельно — импортировать `.claude/skills` через настройки (симлинк) и проверить, что скил вызывается.

## Решение (2026-11-15)

Выбор делегирован человеком агенту в сессии 2026-11-15; принимается merge PR с этой правкой (ADR 0009).

- **Решение «Рабочее место» из ADR 0007 подтверждено:** основной клиент (ZCode) проходит сценарий целиком, включая worktree вне workspace. Замена на «worktree создаёт клиент» не нужна; для Claude Code команда `start` уже объясняет, как открыть worktree средствами клиента.
- **Оставшийся прогон ведёт оператор** (ADR 0009): настройки записи Claude Code и вход в Codex — локальные действия через интерфейс хоста.
- **Без вопроса человеку.** Если окно входа Codex требует пароль или код подтверждения, оператор его не проходит: в ячейку таблицы пишется «нужен вход человека», а задача закрывается с тем, что удалось проверить. То же для настройки, которую клиент отказывается менять без подтверждения человека.

## Критерии приёмки

- Таблица «клиент × шаг» в ADR 0007 дополнена по Claude Code и Codex: в каждой ячейке результат прогона либо явная причина «нужен вход человека».
- Проверка импорта `.claude/skills` в ZCode через настройки и вызов скила записаны в ту же таблицу.
