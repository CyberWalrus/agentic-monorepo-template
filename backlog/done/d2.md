# D2. Проверка трёх клиентов вживую

**Проблема.** Решения ADR 0007 опираются на документацию ZCode, а не на прогон; Codex не проверялся вообще. Не известно: может ли агент создать ветку и worktree сам; работает ли он в worktree вне каталога workspace; срабатывает ли Lefthook на его коммитах; как подключаются скилы проекта.

## Что сделать

В каждом из трёх клиентов (ZCode, Claude Code, Codex) попросить агента: создать ветку, создать worktree командой `git worktree add`, сделать в нём правку в `apps/`, выполнить `pnpm install` и `pnpm verify`, закоммитить. Записать, какой шаг прошёл, какой нет и почему. В ZCode отдельно — импортировать `.claude/skills` через настройки (симлинк) и проверить, что скил вызывается.

## Решение (2026-11-15)

Выбор делегирован человеком агенту в сессии 2026-11-15; принимается merge PR с этой правкой (ADR 0009).

- **Решение «Рабочее место» из ADR 0007 подтверждено:** основной клиент (ZCode) проходит сценарий целиком, включая worktree вне workspace. Замена на «worktree создаёт клиент» не нужна; для Claude Code команда `start` уже объясняет, как открыть worktree средствами клиента.
- **Оставшийся прогон ведёт оператор** (ADR 0009): настройки записи Claude Code и вход в Codex — локальные действия через интерфейс хоста.
- **Без вопроса человеку.** Если окно входа Codex требует пароль или код подтверждения, оператор его не проходит: в ячейку таблицы пишется «нужен вход человека», а задача закрывается с тем, что удалось проверить. То же для настройки, которую клиент отказывается менять без подтверждения человека.

## Критерии приёмки

- Таблица «клиент × шаг» в ADR 0007 дополнена по Claude Code и Codex: в каждой ячейке результат прогона либо явная причина «нужен вход человека».
- Проверка импорта `.claude/skills` в ZCode через настройки и вызов скила записаны в ту же таблицу.

## Журнал

- 2026-11-14, ZCode-сессия (прямое поручение): прогон выполнен, таблица «клиент × шаг» в ADR 0007 (раздел «Прогон D2»). ZCode — сценарий целиком; Claude Code — до настройки записи (worktree вне cwd требует `--add-dir`; дальше pnpm store под песочницей); Codex — не стартовал, 401 при refresh токена, нужен ручной `codex login`. Скилы проекта: в списке скилов сессии `.claude/skills` отсутствуют (подтверждает ADR), проверка импорта через настройки и вызов скила — при следующем заходе вместе с повторным прогоном. Побочный наход — задача D11: `prepare` не ставит Lefthook при установке изнутри worktree.
- 2026-11-15: «Рабочее место» подтверждено (раздел «Решение»); оставшийся прогон передан оператору, `needs_human` переведён в вид `оператор: …` (ADR 0009).
- 2026-11-21, ZCode-сессия (оператор, ADR 0009): захват `pnpm backlog start d2 --operator` (ветка `task/d2`, worktree `agentic-monorepo-template-task-d2`), файл перенесён в `backlog/done/`. План прошёл план-ревью (verdict approve); блокеры учтены: прогоны клиентов Claude Code и Codex — в одноразовых клонах вне основного репозитория, ветки `scratch/<client>-d2` без префикса `task/`, ветка и worktree удаляются после каждого прогона (защита доски от фантомного захвата, ADR 0007 «Статус» + «Работа вне доски»). База прогона — HEAD `main` `94ba5739` (уже с мерджем D11), ячейки таблицы датируются: поведение шага «Коммит» может отличаться от прогона 2026-11-14 на `d4f861a`. Живым фактом: `prepare` при `pnpm backlog close` в этом worktree поставил Lefthook (`prepare: sync hooks: ✔️`) — `[ -e .git ]` ловит gitfile, правка D11 подтверждена (коммит `d056edbd` прошёл хуки `secrets`, `format`).
- 2026-11-21, шаг «Скилы проекта» (ZCode): механизм по документации — пользовательский каталог `~/.zcode/skills/<имя>/SKILL.md`; UI Settings → Skills → «Import» в режиме Symlink создаёт ссылку на каталог скила внешнего клиента. Оператор создал симлинки всех шести скилов проекта (`task-board`, `feature-workflow`, `writing-tests`, `api-contract-change`, `visual-diff-triage`, `perf-regression`) из `~/.zcode/skills` в канонический checkout — результат идентичен «Import → Global → Symlink». Область действия: уровень пользователя, скилы видны всем workspace на хосте, включая чужие проекты; источник один — канонический checkout, правки из task-веток появляются только после merge (часть исследовательского результата). Проверка вызова живьём: в текущей сессии, запущенной ДО импорта, вызов скила `task-board` по имени сработал, контент прочитан через симлинк (`Base directory: /Users/andreypakhomov/.zcode/skills/task-board` в выводе инструмента) — перезапуск сессии не понадобился. Видимость в списке скилов: в индексе этой сессии скилов проекта нет (подтверждает запись 2026-11-14), для новых сессий ожидается по документации; headless-режима у ZCode нет (только GUI `ZCode.app`), отдельная GUI-сессия не потребовалась — критерий «вызов скила» покрыт живым тестом.
- 2026-11-21, шаг «Codex»: живой тест авторизации `codex exec` (0.39.0 — тот же релиз, что в базовом прогоне) воспроизвёл отказ, теперь с точной причиной: refresh токена — `Failed to refresh token: 403 Forbidden` (в 2026-11-14 был 401 без деталей). При этом `codex login status` отвечает «Logged in using ChatGPT» (stale `auth.json` от 2026-07-10) — статус входа не проверяет живость токена. Прогон OAuth-входа оператором через браузерную сессию: точный authorize-URL извлечён из лога программно (первая навигация — моя ошибка ручной транскрипции URL, исказившая параметры OAuth; исправлено локальным редиректором 302 с чтением файла), auth-сервер ответил `403 {"error":{"code":"unsupported_country_region_territory"}}` ДО формы входа — гео-блок сети хоста для OpenAI-авторизации; этой же причиной объясняется отказ refresh. Пароль или код не запрашивались, учётные данные не вводились; блокирует сеть, не учётные данные. Ячейка «Авторизация»: «нужен вход человека» (восстановить сетевой путь до auth.openai.com и выполнить вход); остальные шаги — не дошёл, как и в базовом прогоне.
