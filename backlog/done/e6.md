# E6. Опциональные части шаблона: что можно убрать и какой ценой

**Проблема.** Шаблон предлагает одну форму проекта: web + api + Postgres + визуальные тесты + перф-бюджеты. Copier задаёт два вопроса — имя проекта и владелец (ADR 0008). Проекту только с API, только с web или без базы данных придётся удалять части руками, и неизвестно, что при этом сломается: форма зашита в нескольких местах обвязки. Универсальность шаблона сейчас не проверена ничем.

## Что выяснить

- Где форма зашита жёстко. Проверить как минимум: `tools/verify-steps.ts` (список шагов), `.github/workflows/ci.yml` (job и их зависимости, `gate`), `.dependency-cruiser.cjs` (правила по именам каталогов), пути отчётов в `tools/check-test-report.ts` и `test-count-baseline.json`, `perf-budgets.json`, `tools/check-bundle.ts`, `tools/ports.ts`, `e2e/playwright.config.ts`, `tools/protected-paths.json`.
- Проверить прогоном, а не чтением: в копии репозитория удалить по очереди `apps/web`, `apps/api`, слой Postgres, визуальные тесты — и записать, какие гейты краснеют и почему. Таблица «что убрали × что сломалось».
- Какие гейты должны терпеть отсутствие пакета, а какие обязаны краснеть (удаление `apps/api` агентом не должно тихо выключать мутационные тесты — З2, З5).
- Варианты: условные части Copier (вопросы и `_exclude` по ответам); гейты, которые выводят список пакетов из workspace, плюс документ «как удалить часть»; отдельные ветки-профили.

## Предварительная позиция

Рекомендация до исследования — «гейты выводят состав из workspace + инструкция удаления», а не профили Copier: каждый вопрос Copier умножает число комбинаций, которые должна проверять канарейка копии (D8.3), а ADR 0008 сознательно оставил два вопроса. Исследование должно подтвердить или опровергнуть это таблицей поломок.

## Результат

`docs/research/2026-11-template-profiles.md` с таблицей; если вывод меняет ADR 0008 — новый ADR; задачи на доску по каждой жёсткой зависимости, которую решено снять, с `touches` и критериями.

## Журнал

- 2026-11-15: заведена по итогам аудита (запрос: система должна быть универсальнее и адаптивнее).
- 2026-11-21: исследование сделано прогонами, не только чтением: в четырёх локальных копиях @ `e05f8605` удалены по очереди `apps/web`, `apps/api`, слой Postgres, визуальные тесты; таблица «что убрали × что сломалось» — в docs/research/2026-11-template-profiles.md.
- Выбрано (развилка из задачи, «Варианты»): **«гейты выводят состав из workspace + документ удаления»**, профили Copier и ветки-профили отклонены. Почему: главная дыра не «форму тяжело убрать», а «убирается тихо» — `turbo run mutation` без пакетов с задачей даёт exit 0 (job mutation в CI зелёный, мутационное тестирование выключено без единого красного сигнала — З2/З5); плюс test-count слепнет без WARNING; профили же умножают комбинации канарейки копии (d8.3) и ломают `REQUIRED_IN_COPY` (check-template-copy.ts:47-59), ADR 0008 сознательно держит два вопроса. Альтернатива (профили) — вернуть, если у потребителей накопится устойчивый спрос на формы, а гейты состава уже будут сняты; условие возврата записано в research-документе.
- ADR 0008 не меняется: минимализм «два вопроса» подтверждён; workspace-гейты — закрытие дыр существующего контура, не архитектурная развилка.
- Задачи на доску по каждой снятой жёсткой зависимости: e20 (гейт «обязательные turbo-задачи присутствуют в workspace», high, режим обслуживания), e21 (test-count WARNING на отсутствующий отчёт базлайна, medium, режим обслуживания), e22 (docs/removal.md «как удалить часть шаблона», medium, depends_on e20).
- Результат: docs/research/2026-11-template-profiles.md; дальнейшее — merge e20–e22.
