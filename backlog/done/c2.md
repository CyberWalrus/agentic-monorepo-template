# C2. Аутентификация и политика доступа как часть контракта

**Проблема.** Ошибки доступа (чтение чужого ресурса по id) типичны для сгенерированного кода, а ревьюер-LLM их не гарантирует. Шаблону нужен образец: политика доступа объявляется в контракте и проверяется гейтом, а не договорённостью. Задача декомпозируется: метаданные, middleware и табличные тесты — отдельные задачи.

## Что сделать

- Каждая процедура контракта объявляет политику доступа в метаданных. Гейт: тест перебирает контракт и падает на процедуре без политики.
- Авторизация выполняется в middleware oRPC, актор приходит через контекст.
- Табличные тесты: для каждой процедуры с владельцем есть случай «чужой ресурс, отказ».

## Подводные камни

- oRPC 2 находится в бете (`2.0.0-beta.50`). До стабильного релиза не мигрировать, но метаданные проектировать так, чтобы миграция затронула только пакет контрактов.

## Критерии приёмки декомпозиции

- Файлы задач с `depends_on` и `touches`; канарейка направления: процедура без политики доступа красит гейт.
