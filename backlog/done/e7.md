# E7. Реестр пропущенных дефектов

**Проблема.** `docs/vision.md` называет метрикой системы escaped defects — дефекты, прошедшие все гейты и найденные после merge. Метрика не собирается: такие случаи уже были, но записаны в журналах отдельных задач и сообщениях коммитов, и общий вопрос «какой гейт должен был это поймать и появился ли он» никто не задаёт. Без реестра нельзя ответить, становится ли обвязка лучше.

## Что сделать

- Файл `docs/escaped-defects.md`: таблица «дата · что прошло · как обнаружено · какой контур должен был поймать · чем закрыто (задача, PR) · появился ли гейт или канарейка».
- Заполнить известными случаями, каждый сверить по истории git и файлам `backlog/done/`:
  - переменная `VIDEO` не доходила до Playwright через Turborepo (задача A4);
  - хуки Lefthook не ставились в worktree (задача D11);
  - задачи C5 и C8 закрыты в коде, но остались открытыми на доске (PR #27);
  - флак в `test:hooks` (PR #12);
  - дубль `backlog/d14.md` при файле в `backlog/done/` (PR #42).
- Правило в `AGENTS.md`, раздел «Всегда»: PR, который чинит дефект, прошедший гейты, добавляет строку в реестр и либо гейт, либо запись «гейт невозможен, потому что…».
- Реестр — dev-документ шаблона: в проект из шаблона едет пустая таблица с заголовком (согласовать с таблицей классов владения ADR 0008).

## Решение (2026-11-15)

- **Файл в репозитории, а не issues с label.** Почему: агент читает файл без сети; запись ревьюится тем же PR, что и исправление.
- Альтернатива: label `escaped-defect` на issues и подсчёт через API. Отклонена до C9.4 — в песочнице Claude Code нет доступа к GitHub API.
- Условие возврата: появилась телеметрия C9.4 — тогда реестр формируется из неё, файл остаётся отчётом.

## Критерии приёмки

- В реестре не меньше пяти сверенных случаев со ссылками на PR или задачи.
- Правило есть в `AGENTS.md`; `pnpm verify` зелёный.

## Журнал

- 2026-11-15: заведена по итогам аудита. Список случаев — из памяти аудита, перед записью каждый сверить: номера PR и задач могли быть названы неточно.
- 2026-11-21 (выполнение): все пять случаев сверены с историей git и `backlog/done/`, неточностей в номерах не нашли: A4 — PR #1 (`b5661dff`, подтверждение в `docs/architecture.md`, 3.2) и `turbo.json` `env` задачи `e2e`; D11 — PR #30 (`7223e286`), фикс `[ -e .git ]` в `prepare`, канарейка D12 — PR #31 (`49bcc7df`, `tools/check-hook-install.ts`); C5/C8 — слиты #24 (`141eaae`) и #25 (`2df7b41`), закрыты гигиеной PR #27 (`02784deb`); флак `test:hooks` — PR #12 (`fa896acd`), позже учёт флаков B4.4 (PR #101); дубль `d14` — PR #42 (`1b9b6d98`), проверка дубля id живёт в гейте docs с PR #20. Дата строки реестра — дата фикса из git.
- 2026-11-21 (выполнение): реестр `docs/escaped-defects.md` (таблица из шести колонок, пять строк), правило в `AGENTS.md` («Всегда»: строка тем же PR, что и исправление, + гейт/канарейка либо «гейт невозможен, потому что …»), строка класса владения в ADR 0008 (тот же PR — правило ADR 0008).
- 2026-11-21 (выполнение): развилка «пустая таблица в копии» закрыта вариантом «едет как есть, класс проект (да, один раз)». Почему: разный контент для шаблона и копии требует `_exclude` в `copier.yml` плюс правки `FORBIDDEN_IN_COPY` в `tools/check-template-copy.ts` — оба пути `deny` (ADR 0014), а исключение матчит путь назначения и убило бы рендер скелета в тот же `docs/escaped-defects.md` (проба D8.2). Альтернатива — режим обслуживания и перенос живого реестра в уже исключённый путь с рендером скелета в `docs/`: два разных пути одного реестра в шаблоне и копии, ломает ссылки из `AGENTS.md`. Условие возврата: появится телеметрия C9.4 — реестр формируется из неё, файл остаётся отчётом; либо оператор в режиме обслуживания оформит исключение+скелет. Записано и в строке ADR 0008, и в разделе «Копия из шаблона» реестра.
- 2026-11-21 (выполнение): `pnpm verify` PASS (18 шагов; формат markdown держит oxfmt — прогнан `pnpm format`). `pnpm verify --full` — перед PR.
