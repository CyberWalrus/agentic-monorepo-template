# E73. Визуальный тест «error banner after a failed toggle» — гонка после e54

**Проблема.** e54 (PR #203, мерж `227d75f7`, 2026-11-24 00:52 UTC) перенесла откат неудачного toggle в `onError` мутации (`apps/web/src/features/tasks/use-tasks.ts`). Визуальный тест `e2e/features/tasks/tasks.visual.ts` кликал чекбокс через `locator.check()`: Playwright после клика ждёт отмеченного состояния, а откат теперь успевает вернуть галочку раньше — «Clicking the checkbox did not change its state». В PR #203 джоба `visual` прошла (одна выборка из вероятностного исхода); после мержа красны прогон CI на самом main (`45300657047`: `visual` → `gate`) и PR #198 (два прогона подряд), на PR #202, #205, #208 — зелёная. Поезд слияния не мог смержить PR #198: у гейт-PR красные чеки не терпимы. Дефект прошёл все гейты — строка в `docs/escaped-defects.md` тем же PR.

## Что сделать

1. В тесте — `click()` вместо `check()`: тест утверждает баннер `role="alert"`, а не состояние галочки после отката.
2. Строка в `docs/escaped-defects.md`.
3. Проверка: прогон джобы `visual` в CI на PR исправления — зелёная, в том числе на повторных прогонах.

## Критерии приёмки

- `visual` зелёная на PR исправления (все попытки).
- После обновления веток PR #198, #202, #205, #208 джоба `visual` на них зелёная без реранов.

## Решение

Выбрано менять тест, а не продукт: продукт после e54 работает как задумано (точечный откат от текущего состояния кэша), недетерминизм внёс сам тест утверждением, которого у него нет в предметной проверке. Альтернатива — вернуть откат в старый медленный путь — отклонена: она откатывает e54. Условие возврата: если появятся другие тесты, где `check()` обязателен по смыслу (утверждается именно отмеченное состояние), для них нужен отдельный разбор, а не это правило.

**Гейт или канарейка не появились, потому что** дефект — гонка в самом тесте, а не в продукте: воспроизводимость зависит от таймингов раннера, детерминированной канарейки на «`check()` после быстрого отката» не построить. Контур, который должен был поймать, — повторный прогон джобы `visual` перед мержем; он остаётся ручным (`gh run rerun --failed`), так как разовый прогон — одна выборка.

Задача исполнена владельцем запуска конвейера руками, вне доски: поезд стоял на красном `visual`, а все три дорожки были заняты.

## Журнал

- 2026-11-24 05:40 MSK — дефект найден владельцем запуска конвейера: PR #198 два прогона подряд красный в `visual` (`locator.check: Clicking the checkbox did not change its state`), на main после мержа #203 — прогон `45300657047` красный в той же джобе. Сопоставление с диффом e54: откат перенесён в `onError` мутации. Исправление — `click()` вместо `check()`, строка реестра добавлена.
