# C2.3. Табличные тесты «чужой ресурс — отказ»

**Проблема.** Точечные тесты доступа пишутся наугад; нужна таблица, покрывающая каждую процедуру с владельцем.

## Что сделать

- Для каждой процедуры с политикой «владелец» есть случай «чужой ресурс, отказ» и «свой ресурс, успех» — генерируются перебором контракта, а не пишутся руками.
- Таблица «процедура × случай» видна в отчёте тестов: пустая строка красит набор.

## Критерии приёмки

- Канарейка: удаление проверки владельца из любой доменной процедуры красит табличный тест без его ручной правки.

## Журнал

- 2026-11-17, план (до кода, на ревью architecture-reviewer и sanity-reviewer):
  - **Что и зачем.** Табличный тест доступа: каждая процедура с политикой `owner` получает пару случаев «чужой ресурс — отказ (FORBIDDEN)» и «свой ресурс — успех», сгенерированную перебором. Пустая строка (owner-процедура без строки сценария) и лишняя строка (сценарий не owner-процедуры) красят набор. Канарейка-свойство: сломанная owner-проверка мидлвари красит таблицу без правки теста.
  - **Домен получает владельцев** (по записи «дальше» из журнала C2.2): колонка `owner_id` (nullable) + миграция; `TaskRepository += ownerOf(id) → string|null`, `remove(id) → Task|undefined`; `create` принимает ownerId и пишет туда `context.actor?.id ?? null`; адаптер `ownerOf(input)` в `createApp` заменяет заглушку `async () => null` (условие возврата C2.2 выполнено): незнакомая форма input → null (fail-closed, как решено в C2.2).
  - **Первая owner-процедура — новая `tasks.remove`** (DELETE /tasks/{id}, output void, политика `owner`), а не перевод существующей `toggle`: перевод toggle ломает анонимный toggle веба и критический E2E AC-2 (актора в демо нет), а web/e2e — вне `touches` задачи. `remove` вебом не используется → внешние слои не трогаются. Альтернатива «только тест-инфраструктура без owner-процедуры» отклонена: таблица пуста, канарейка-AC вакуумна; `touches` (contracts + api) подтверждает контрактную правку. Условие возврата: с появлением аутентификации существующие публичные процедуры пересматриваются (задача о ней появится на доске отдельно).
  - **`TaskSchema` не расширяется**: владение — серверные данные политики, не поле вывода API; иначе обязательное поле ломает литералы Task в тестах web и e2e-сидов (обе области вне `touches`). Владение видит только `ownerOf` репозитория.
  - **Перебор — по реальному роутеру** существующими `collectProcedures` + `accessPolicyFromMeta` (уже экспортированы для router-divergence.test), а не по объекту контракта: структурное тождество «контракт ≡ роутер» держит router-divergence.test, а исполнение — только через роутер. Новых экспортов из packages/contracts не нужно (правило ADR 0011 об экспортах).
  - **Таблица в отчёте**: `it.each` с именами вида «tasks.remove — чужой ресурс — отказ»: каждая ячейка = отдельный случай в vitest-отчёте. Отказ проверяется глубже кода ошибки: ресурс не тронут (для remove — задача осталась в списке), успех — эффект домена случился (задача удалена).
  - **Слои**: contracts (remove + openapi) / api (миграция, репозитории, роутер, app, тесты: табличный + контрактный набор репозитория += ownerOf/remove + транспортные случаи в app.test) / UI, E2E — не затрагиваются.
  - **Чего не делаем**: аутентификации нет (actor в демо null), 401/403 не разделяем (C2.2), канарейка в tools/ — задача C2.4 (оператор), `toggle`/`list`/`create` остаются `public`.
  - **Канарейка-AC**: проверяется вручную в этой задаче — убрать `owner !== context.actor.id` из мидлвари → табличный тест красный без правки теста; восстановить → зелёный. Выводы обоих прогонов — в PR.
