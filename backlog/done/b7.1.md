# B7.1. Гейт дрейфа routeTree.gen.ts через отдельный генератор

**Проблема.** B7 дала `pnpm regen` (маршрут через `vite build`) и маркеры производных файлов, но гейт дрейфа для `routeTree.gen.ts` не сделан: генерация живёт в vite-плагине `@tanstack/react-start`, отдельного генератора в зависимостях нет, а гейт в быстром verify требует генерацию без сборки.

## Что сделать

- Добавить `@tanstack/router-cli` (версия из `catalog:`, совместимая с генератором `@tanstack/react-start` той же версии — сверить до выбора; расхождение версий даёт ложный дрейф).
- Скрипт `routes:gen` в `apps/web`, `pnpm regen` дополняется им.
- Гейт: committed `routeTree.gen.ts` == свежесгенерированный; канарейка — ручная правка ген-файла красит гейт.
- Включить в verify (шаг + бюджет) и CI static.

## Критерии приёмки

- Ручная правка `routeTree.gen.ts` красит verify; `pnpm regen` закрывает конфликт этого файла без сборки.

## Журнал

- 2026-11-21: выделена из B7 при реализации: генератор routeTree живёт в vite-плагине `@tanstack/react-start`, standalone-генерация требует новой зависимости с сверкой версий — решение о зависимости принимается отдельной задачей (правило «новые зависимости — при реальной необходимости, версия в catalog:»). Остаток B7 (regen через build, маркеры, реестры) — в PR B7.
- 2026-11-22, план до кода (скил feature-workflow §1). Задача операторская (ADR 0007/0009): создаёт новый гейт и правит deny-пути — `tools/verify-steps.ts`, `verify-budgets.json`, `tools/gate-canaries.ts`, `tools/protected-paths.json` (новый гейт в deny тем же PR, ADR 0014 — иначе красный шаг `tool-class`), `.github/workflows/ci.yml`. Перед правками нужен режим обслуживания в worktree задачи: включает человек/оператор, агенту запись в `.claude/settings.local.json` запрещена.
- Развилка «версия @tanstack/router-cli» (раздела «Решение» в задаче нет — решено по ADR 0009): выбрана 1.167.46. Почему: CLI жёстко пиннит `@tanstack/router-generator` своей версии (`npm view @tanstack/router-cli@1.167.46 dependencies` → generator 1.167.46; `@1.168.0` → generator 1.168.0), а в плагин-чейне `@tanstack/react-start@1.169.4` из catalog резолвится generator 1.167.46 (`node_modules/.pnpm`) — совпадение версий генератора исключает ложный дрейф между гейтом и vite-сборкой. Альтернатива: latest 1.168.0 — отклонена, другой генератор. Условие возврата: при подъёме `@tanstack/react-start`/`@tanstack/react-router` в catalog заново сверить версию generator в чейне и поднять router-cli до той же генераторной версии; если standalone-генерация появится в самом react-start — CLI удалить.
- План: 1) `@tanstack/router-cli@1.167.46` в `catalog:` pnpm-workspace.yaml и devDependencies `@repo/web`; 2) скрипт `routes:gen` в apps/web — конфиг CLI повторяет дефолты `tanstackStart()` (`src/routes` → `src/routeTree.gen.ts`), до проводки гейта сверить вывод байт-в-байт с committed файлом; 3) корневой `pnpm regen` дополняется `routes:gen` (package.json:43); 4) гейт `tools/check-routetree-drift.ts`: генерация во временный файл, сравнение с committed; скрипт `routetree:check`, шаг после `openapi` в `fast[]` verify-steps.ts, порог в verify-budgets.json, файл гейта в deny protected-paths.json тем же PR; 5) канарейка по приёмке: правка committed routeTree.gen.ts красит шаг; регистрация в tools/gate-canaries.ts по образцу соседних; 6) CI static — строка `pnpm routetree:check` в ci.yml рядом с `openapi:check` (ci.yml:96); 7) `pnpm verify --full` зелёный; в PR — доказательства: вывод гейта на отравленном файле и `pnpm regen` без сборки, закрывающий дрейф.
- Чего не делаем: маршруты и `routeTree.gen.ts` руками не правим; openapi-гейт не трогаем; пороги не поднимаем; конфигурацию роутера (плагин tanstackStart) не меняем — гейт только сверяет дрейф.
