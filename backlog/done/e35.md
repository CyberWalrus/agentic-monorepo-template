**Проблема.** После восстановления живого ruleset до снапшота (e30, issue #147 закрыт): live ≡ снапшот доказано локально — `node tools/check-ruleset-drift.ts` exit 0 («2 пары») тем же кодом на том же коммите — но два dispatch-прогона nightly (45061076135, 45061584331) красят джобу «дрейфом» по ОБЕИМ парам и завели [issue #157](https://github.com/CyberWalrus/agentic-monorepo-template/issues/157). Фантом старше e30: tags-v «дрейфовал» в прогоне 10:34Z без фактического расхождения; зелёных прогонов джобы не было никогда — это дефект джобы с момента её появления, не регрессия e30. Гипотеза (e30, эскалация): REST API rulesets требует permissions `administration:read`; токен джобы (github.token) имеет только contents:read/issues:write/metadata:read → GET возвращает 403 → чекер интерпретирует недоступность API как дрейф (fail-open в дрейф). _(Уточнение 2026-11-24, см. «Журнал»: API отвечает 200 без ключа `bypass_actors`, а не 403; чекер терял отсутствующий ключ при проекции по форме снимка.)_ Локально не воспроизводится: токен CyberWalrus (admin) читает rulesets.

## Что сделать

1. Подтвердить диагноз по логу джобы (код ответа/сообщение) или расширив сообщение чекера при отказе полным кодом и телом ответа.
2. Permissions джобы ruleset-drift: добавить `administration: read` (job-level, по doctrine e16 — job-level заменяет workflow-level целиком). _(Не сделано: области `administration` у `GITHUB_TOKEN` нет. Решение, альтернатива и условие возврата — «Журнал», 2026-11-24 01:23 MSK.)_
3. Чекер `tools/check-ruleset-drift.ts`: отказ API (403/404/сеть) ≠ дрейф — отдельная ветка с ясным сообщением (код, тело), exit 1 с названием причины; сообщение «дрейф» печатается только при реально полученном сравнимом ответе.
4. Тест в `tools/test/` на классификацию ответов (дрейф / отказ API / совпадение).
5. Диспетч ночной: джоба «ruleset drift» зелёная; issue #157 закрыт с доказательством.

## Решение

Недоступность API остаётся красной (мониторинг не имеет права тихо зеленеть), но обязана называть причину — «дрейф» только при полученном ответе. Условие возврата: если после permissions-фикса джоба всё ещё красная с внятной причиной — это уже настоящий сигнал, разбирать по содержимому дампа.
