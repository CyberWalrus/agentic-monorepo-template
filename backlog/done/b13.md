# B13. Хардненинг гейтов: strict-флаги и носители required-tasks

**Проблема.** Канарейки «type-ошибка» вставляют const evil: number = 'not-a-number' — ошибку, видимую и без strict (tools/gate-canaries.ts:150-159): отключение noUncheckedIndexedAccess/strict в tsconfig остаётся зелёным даже после B8. required-tasks красит только при нуле носителей задачи (tools/check-required-tasks.ts:24,102-103): удаление скрипта mutation из apps/api/package.json (носители остаются: web, contracts) тихо выключает мутационный гейт пакета; test-count warning-only (exit 0 всегда), test-report читает dry-граф turbo (tools/check-test-report.ts:14,20) — исчезнувший скрипт исчезает из графа, требовать отчёт нечего. Остаточный риск задокументирован самим гейтом (tools/check-test-count.ts:31-34).

## Что сделать

- Канарейка evil-probe с ошибкой, видимой только при strict/noUncheckedIndexedAccess: const first = ([] as string[])[0]; first.length (ошибка TS только при noUncheckedIndexedAccess), failedStep typecheck.
- check-required-tasks: минимальное число носителей на задачу (в репо: mutation=3, test≥3) либо сверка носителей задачи в main и в ветке; выбрать проще и зафиксировать порог с комментарием.

## Критерии приёмки

- Отключение noUncheckedIndexedAccess в пакетном tsconfig тестовой ветки красит verify шагом typecheck; негатив-контроль зелёный на чистой базе.
- Удаление скрипта mutation из одного носителя красит required-tasks; сохранение всех носителей — зелёное.
- pnpm canaries зелёный; тесты check-required-tasks обновлены.

## Решение

Выбраны обе минимальные проверки одним PR (одна область — канарейки/чекеры). Альтернатива: drift-гейт содержимого скриптов turbo-задач с эталоном (по образцу routetree/openapi drift) — тяжелее, отложена. Условие возврата: канарейка strict-флагов дублирует защиту B8 — остаётся защитой в глубину; при её флаках в ночных прогонах — пересмотреть (инвариант gates-canary.test.ts покажет).

Задача ведёт оператор (задача будет в режиме обслуживания): touches — tools/** deny-замыкание, новая канарейка.
