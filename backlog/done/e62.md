# E62. Селекторы: data-testid при имеющейся семантике

**Проблема.** `e2e/features/tasks/tasks.visual.ts:23` — селектор по `data-testid` там, где есть семантика; по аудиту таких мест три. Правило AGENTS.md («Селекторы в тестах: `getByRole` / `getByLabel` / `getByText`. `data-testid` только когда семантики нет») нарушено, гейтом не закрыто. Известные атрибуты в продукте: `data-testid="tasks-summary"` (`apps/web/src/features/tasks/TasksPage.tsx:34`, `<p>`), `data-testid="task-item"` (`packages/ui/src/task-item/TaskItem.tsx:24`, `<li>`). Аудит владельца, 2026-11-23, «Низкие → Тесты и документация».

## Что сделать

1. Инвентарь: `git grep -n "data-testid" -- e2e apps/web/src packages/ui/src` — все места в «Журнале», каждое помечено «семантика есть» или «семантики нет».
2. Где семантика есть — заменить селектор на `getByRole`, `getByText` или `getByLabel`; где нет — оставить `data-testid` с комментарием причины в тесте.
3. Атрибуты продукта, оставшиеся без потребителей, убрать; роли не выдумывать — иначе изменится a11y-дерево и визуальные базлайны (базлайны не обновлять; при диффе — триаж по скилу `visual-diff-triage`).

## Критерии приёмки

- Инвентарь в «Журнале»; у каждого оставшегося `data-testid` в тестах — комментарий причины.
- pnpm e2e и pnpm verify зелёные; pnpm visual без новых диффов (или ожидаемые изменения перечислены в PR).

## Решение

Селектор по семантике проверяет заодно доступность: тест по роли падает, когда элемент перестал быть доступным. Условие возврата: если замена селектора делает тест хрупким (несколько совпадающих ролей) — уточнить локатором (`.nth`, фильтр по имени), а не возвращать `data-testid`.
