# D8.5. Создать ruleset тегов `v*` в GitHub

**Проблема.** Снимок ruleset — файл в репозитории; защита включается только в интерфейсе GitHub, у агентов туда доступа нет (ADR 0002: настройки GitHub делает мейнтейнер).

Действие остаётся человеку (ADR 0007, третий вид `needs_human`). Файлы репозитория задача не меняет, кроме отметки о выполнении.

## Что сделать

- Создать ruleset по снимку `.github/rulesets/tags-v.json`: таргет — теги `v*`, запрет изменения и удаления.
- Отметку о выполнении (имя ruleset, дата) занести в `docs/template-state.md` — это единственная правка репозитория, её делает человек отдельным PR или оператор по поручению.

## Критерии приёмки

- Ruleset Active и таргетирован на теги `v*`.
- Попытка перезаписать или удалить существующий тег `v*` отклоняется GitHub (проверка на временном теге, который можно удалить до включения защиты).
- Отметка в `docs/template-state.md`.

Ветка захвачена вручную (`git branch task/d8.5 main` + worktree).
- Хронология: пробный тег `v0.0.0-probe` создан и запушен ДО включения защиты (d938e2f) → ruleset `tags-v` создан POST из payload снимка (id 27351411, Active) → отказ удаления (422 «Cannot delete this tag») и перестановки (GH013 «Cannot update this protected ref») → позитивный контроль: новый тег `v0.0.1-probe` при активном ruleset прошёл (создание не ограничено) → очистка: окно `enforcement: disabled`, оба пробных тега удалены, ruleset возвращён PUT полного payload в `active`. Окно disabled — минуты между шагами, в окне теги не создавались. Финал: `main` и `tags-v` оба Active, тегов на origin нет.
- Сценарий из критериев («тег можно удалить до включения защиты») соблюдён: тег создан до защиты; очистка потребовала короткого окна disabled, потому что `bypass_actors: []` — удалить защищённый тег нельзя никому, даже админу. Это осознанно: снимок повторяет строгость `main.json`.
- Отметка о выполнении — `docs/template-state.md` §7 (единственная правка файлов, кроме переноса этой задачи).
- Зависимость от PR d8.4 (#51) — смысловая (ruleset создан из его снимка), файловая нет: диффы не пересекаются. Что дальше: merge обоих PR человеком (этот PR без label не нужен — защищённых путей не трогает), затем d8.6 — первый тег `v0.1.0` (ждёт также d8.3).
