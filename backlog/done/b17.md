**Проблема.** После B16 стандарт ничем не enforced: новые PascalCase-имена или пробельные появятся снова без единого сигнала — гейта нейминга в tools/ нет (перепроверка grep по tools/ на filename/naming — только работа с previous_filename защищённых путей).

## Что сделать

- tools/check-naming.ts: каждый git-tracked файл обязан матчиться ^[a-z0-9][a-z0-9._-]*$ (каталоги — без точки); исключения — единый список из B16, один источник (чекер читает тот же файл/раздел).
- Шаг naming в verify (tools/verify-steps.ts, fast-волна), скрипт в package.json, тест чекера на синтетическом дереве, канарейка naming-шага в tools/gate-canaries.ts (по З6 каждый блокирующий шаг покрыт).

## Критерии приёмки

- Создание packages/foo/Bar.tsx красит шаг naming; файл из списка исключений проходит; pnpm verify зелёный на чистой базе.
- Канарейка naming-шага красит шаг при обходе чекера; инвариант gates-canary.test.ts зелёный.
- Список исключений — один источник, общий с B16.

## Решение

Выбран блокирующий шаг verify с собственной канарейкой: нарушение нейминга не «тихо ослабляет существующий гейт», поэтому нужна прямая проверка, а канарейка — по правилу З6. Альтернатива: lint-правило oxlint — не покрывает имена файлов вне контента. Условие возврата: ложные срабатывания на новых генерированных файлах — расширять список исключений через PR (файл — review/deny после B8/B16).

Задача ведёт оператор (задача будет в режиме обслуживания): новый гейт + touches — tools/** (deny-замыкание).

- **Решение 1 — правило сегмента.** Выбрано `^\.?_*[a-z0-9][a-z0-9._-]*$` для каждого сегмента — каталогов и имени файла, одинаково. Буквальные формы из условия (`^[a-z0-9][a-z0-9._-]*$`, «каталоги — без точки») красят чистую базу: `.gitignore`, `.github/`, `.claude/`, `__root.tsx`, `_journal.json`, `__screenshots__/`, каталоги скриншотов `__screenshots__/<имя визуального теста>/` (решение b16: каталог зеркалит имя теста); инвентарь b16 считал только заглавные буквы и эти имена не видел. Альтернатива — внести их в список исключений: три новых имени вне списка b16 и правка AGENTS.md (вне touches). Условие возврата: владелец считает точку или подчёркивание первыми нарушением стандарта — тогда отдельной задачей переименовать файлы и убрать допуск.
- **Решение 2 — один источник исключений.** Выбрано: список — константа чекера (файл в deny, расширение только с label `gate-change-approved`, ADR 0014), а чекер на каждом прогоне читает тот же абзац, что и b16, — «Нейминг путей» AGENTS.md и раздел 2.7 architecture.md — и красит шаг при другом наборе имён или пропавшей фразе-якоре. Альтернатива — чекер парсит документацию как источник: тогда исключение добавляется правкой `docs/architecture.md` вне защищённых путей и без label. Условие возврата: фраза-якорь мешает правке документации чаще, чем ловит расхождение, — тогда сверку перенести в тест (не в шаг).
- **Решение 3 — область проверки.** Выбрано `git ls-files --cached --others --exclude-standard`: tracked плюс untracked вне `.gitignore`. Только tracked не работает с канарейкой: раннер применяет плохое изменение к worktree, не коммитя, и откатывает его `git clean`; `git add` в канарейке оставил бы файл в индексе. Побочный эффект: локальный мусор вне `.gitignore` чекер видит так же, как `git status` (`.DS_Store` на macOS без глобального exclude; в этом репозитории его нет ни в `.gitignore`, ни в `core.excludesFile` — проверено 25.11).
