# E26. Сводный check не-required воркфлоу + actionlint

**Проблема.** Кандидат из docs/escaped-defects.md:22 (дефект 2026-11-21: SHA-пин породил github/codeql-action@init@<sha>, workflow не стартовал ни разу, «в required checks security.yml не входит, поэтому main оставался зелёным») до сих пор не заведён: rg «сводн» по backlog/ (включая done/) — 0 файлов; actionlint в репо нет (rg по .github/, tools/, lefthook.yml — пусто); gate агрегирует только внутренние джобы ci.yml (needs: [static, unit, mutation, e2e, visual, perf], ci.yml:414); zizmor — линтер содержимого, не проверка «воркфлоу стартует», и сам живёт в не-required security.yml (:3).

## Что сделать

- Ночная/канареечная джоба: через GitHub API опросить check-runs последнего коммита main по всем workflow; красная, если какой-то workflow не стартовал или красный на свежем коммите (список ожидаемых — из .github/workflows/**, фильтр по ожидаемым триггерам).
- Опционально тем же PR: шаг actionlint по .github/workflows в verify (зависимость в catalog:).
- Сослаться на номер задачи в строке реестра docs/escaped-defects.md:22.

## Критерии приёмки

- Джоба сводного check существует: на синтетической фикстуре «workflow не стартовал» красная, на чистой main зелёная.
- Список ожидаемых workflow выводится из .github/workflows/** автоматически (не хардкод).
- Строка docs/escaped-defects.md:22 ссылается на номер задачи; pnpm verify зелёный (с actionlint, если принят).

## Решение

Выбран сводный check как обязательная часть (закрывает класс «не стартовал/красный вне gate»), actionlint — усиливающая опция того же PR. Альтернатива «сделать все воркфлоу required» отклонена: взрывает время CI и блокирует merge об информационные чеки. Условие возврата: ложные срабатывания на schedule-воркфлоу — фильтр по триггерам и окну свежести коммита.

Задача ведёт оператор (задача будет в режиме обслуживания): новый гейт + touches — .github/workflows/**, tools/** (deny).

**Дополнение (2026-11-23, оператор, развилка по ADR 0009 — actionlint отклонён).** Опциональная часть (actionlint в verify) не принята. Доказательство (пробник /tmp/e26-actionlint-probe, npm `actionlint@2.0.6`, «Actionlint as wasm»): (1) на зелёном main даёт 11 ложных срабатываний на шаблонном плейсхолдере `$/.github/actions/setup` («ref is missing») — API `createLinter()` не принимает конфиг, подавлять находки фильтром в скрипте — ослабление линтера; (2) не ловит класс самого escaped-defect: `github/codeql-action@init@<sha>` парсится как валидная форма `repo@ref` — 0 находок на bad-change пробнике. Выбрано: гейт workflow-health без actionlint. Альтернатива (реальный CLI вне npm-реестра) отвергнута правилом supply-chain (прецедент secretlint: «npm-пакет из каталога, а не бинарь вне цепочки поставок»). Условие возврата: вернуться при появлении в npm-реестре конфигурируемого actionlint (умеет .github/actionlint.yaml) или после структурного изменения `$/`-плейсхолдера.
