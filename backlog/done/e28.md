# E28. Разовая канарейка $/-резолва в gate-integrity

**Проблема.** Доверие gate-integrity к $/-ссылкам на локальный экшен (gate-integrity.yml:82,183; чекаут base.sha :80,:181; комментарий «Локальный экшен тоже резолвится из базы» :76) держится на changelog GitHub 2026-07-30, который для pull_request_target точную семантику не раскрывает («exact commit that is running» — какой коммит, не сказано; страница syntax docs.github.com обрезана до uses-раздела). Если бы $/ резолвился по merge-ref, PR контролировал бы .github/actions/setup, исполняемый в доверенном workflow ДО проверки protected-paths (:82 → :131-134), — запрещённый шапкой pwn-request. Перепроверка: код-заявления, commit 3926797e и backlog/done/e23.md согласованно указывают на резолв по base; эмпирической проверки не существует (после введения синтаксиса экшен никто не менял, в 6 последних прогонах merge-ref-сетап не дискриминировался).

## Что сделать

- Разовый маркер-PR: правка .github/actions/setup/action.yml с эхо-маркером; в логе gate-integrity прогона PR зафиксировать, какая версия экшена исполнилась (base или PR).
- Результат (резолв по коммиту определения или по merge-ref) записать в ADR 0002 и ADR 0014.
- При merge-ref-резолве — немедленный фикс тем же PR (вернуть ./-синтаксис или перенести шаг), строка в docs/escaped-defects.md.

## Критерии приёмки

- В ADR 0002 и ADR 0014 зафиксирован результат прогона маркер-PR: какая версия .github/actions/setup исполнилась; вывод однозначен.
- Если резолв по merge-ref — фикс применён и проверен тем же PR; строка в docs/escaped-defects.md добавлена.

## Решение

Выбрана одноразовая проверка: дискриминирующий случай редкий, постоянная канарейка (PR на каждую проверку) несоразмерна. Условие возврата: GitHub опубликует точную семантику — закрыть вопрос ссылкой; при изменениях pulls-семантики GitHub — повторить канарейку.

Задача ведёт оператор (задача будет в режиме обслуживания): маркер-PR правит .github/** (deny).
