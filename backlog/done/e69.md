# E69. Тестовый API в проде: два рубежа на одном входе

<!-- 2026-11-24: depends_on: e72 — работа вне доски, волна seed-D7. Задача объявляет docs/architecture.md; пока D7 считает этот путь пересечением (правка — задача e72), такие задачи захватываются по одной. e72 отклонена или остановлена — зависимость снять тем же PR. -->

**Проблема.** `apps/api/src/server-config.ts:75`: рубеж запрета — `superRefine` (`ENABLE_TEST_API` вместе с `NODE_ENV === 'production'` → ошибка конфигурации); второй рубеж, по аудиту, смотрит на тот же `NODE_ENV`, а поле опционально. `NODE_ENV` не задан или задан иначе (`prod`, `staging`) — оба рубежа молчат: «два рубежа» дают одну точку отказа. Вне Docker, чтобы прод-гвард гарантированно сработал, нужны три явных включения — перечислить их при захвате. Аудит владельца, 2026-11-23, «Низкие → Безопасность и стабильность».

## Что сделать

1. Инвентарь в «Журнале»: где решается «тестовый API закрыт» (`server-config.ts`, `app.ts`, `server.ts`, `apps/api/Dockerfile`), какие входы у каждого рубежа; перечислить «три явных включения» с указанием строк.
2. Разделить входы: у прод-гварда — независимый явный сигнал; либо default-fail-closed — тестовый API включается только при явном `NODE_ENV` в `development` или `test` (сегодня закрыт только при `production`), тогда отсутствие `NODE_ENV` означает «тестовый API закрыт». Выбор — по «Решению».
3. Тесты (`apps/api/src/server-config.test.ts`, `apps/api/src/app.test.ts`): матрица `NODE_ENV` × `ENABLE_TEST_API` × второй сигнал — разрешена ровно одна комбинация, остальные — отказ или закрытый тестовый API.
4. Dockerfile и документация развёртывания — обязательные прод-переменные перечислены явно.
5. Строка в `docs/escaped-defects.md` тем же PR (дыра защиты; латентная — с пометкой).

## Критерии приёмки

- Матрица тестов зелёная; до правки тест «`NODE_ENV` не задан, `ENABLE_TEST_API=1`» показывает открытый тестовый API (красный), после — закрыт; либо в «Журнале» доказательство, что на рантайме сценарий недостижим, с закрывающим инвариантом.
- Инвентарь рубежей и «три включения» — в «Журнале» со строками.
- pnpm verify зелёный; строка добавлена в `docs/escaped-defects.md`.

## Решение

Default-fail-closed: тестовый API открывается явным значением, а не закрывается одним из возможных. Новая переменная не вводится, пока не доказано, что `NODE_ENV` для этого недостаточен. Условие возврата: если у потребителя запуск в development без `NODE_ENV` ломается — документировать обязательный `NODE_ENV=development` для dev, а не возвращать открывание по умолчанию.

- 2026-11-25 — **Решение (по разделу «Решение»): default-fail-closed, без новой переменной.** Оба рубежа разрешают тестовый API только при явном `NODE_ENV=development` или `NODE_ENV=test`; `ENABLE_TEST_API=1` при незаданном `NODE_ENV` — отказ при старте с названной причиной, одним текстом в обоих рубежах (`ENABLE_TEST_API=1 needs an explicit NODE_ENV=development or NODE_ENV=test: …`); для `production` текст прежний. Опечатки и «почти прод» первый рубеж отклоняет enum, второй — тем же текстом про явное значение. Развилки:
  - _Отказ при старте, а не молчаливое «выключено»._ Выбран отказ: второй рубеж умеет только бросать, а «один запрет — один текст» должен держаться на обоих рубежах; модуль окружения уже отказывает на неоднозначных значениях (`server-config.ts:26-28`); молчаливое выключение превратило бы E2E и ручной запуск в «сервер жив, тестовый API закрыт» — причина дальше от симптома. Альтернатива — `enableTestApi=false` без ошибки. Условие возврата: появится потребитель, которому нужен старт с флагом без `NODE_ENV` (в репо такого нет).
  - _`NODE_ENV=test` для E2E-сервера_ (`e2e/playwright.config.ts`). Альтернатива — `development` (обе разрешены гвардом). Условие возврата: контуры `e2e`/`perf`/`visual` в CI покажут отличие поведения сервера под `NODE_ENV=test` от прежнего (переменной не было) — заменить на `development`.
  - _Имя `assertTestApiNotInProduction` сохранено_: теперь она отвергает и незаданную среду, но переименование потянуло бы `app.ts` и тесты без изменения поведения; doc-комментарий описывает новую матрицу.
  - _Dockerfile_: флаги тестового API заданы нулями в ENV образа, а не оставлены дефолту кода (защита от будущего изменения дефолта); поведение не меняется.
