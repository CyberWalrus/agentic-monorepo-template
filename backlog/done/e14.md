# E14. turbo env-гигиена: `REUSE_SERVER` и мёртвые декларации

**Проблема.** Задокументированный escape hatch молча не работает: `e2e/playwright.config.ts:45` читает `REUSE_SERVER`, ADR 0005 документирует `REUSE_SERVER=1`, но в `env` задачи `e2e` в `turbo.json` переменной нет — strict env-режим Turborepo не пропускает её до конфига, reuse тихо отключается. Это тот же класс дефекта, что задокументированный инцидент `VIDEO=on` (architecture.md §3.2), но его никто не поймал. Рядом мёртвая декларация: `API_URL` в `env` задач `e2e`/`perf` не читает никто (адрес вычисляется в `tools/ports.ts`) — она только раздувает ключ кэша.

## Что сделать

- Добавить `REUSE_SERVER` в `env` задачи `e2e` (и `perf`, если он там нужен).
- Убрать мёртвые `API_URL`-декларации: адрес детерминирован портами, чтение переменной конфигом не подключать.
- Канарейка в `tools/test/`: переменные, читаемые конфигами e2e из `process.env`, входят в `env` соответствующих задач turbo — следующий такой дефект ловится гейтом, а не человеком.
- Заметка в architecture.md §3.2 рядом с инцидентом `VIDEO=on`: strict env-режим требует объявления каждой читаемой переменной.

## Решение

- **Канарейка grep-контрактом, а не ручным списком.** Почему: ручной список снова дрейфует; grep по `process.env['…']` в `e2e/` против `env` задач — машинная проверка того же правила.
- Условие возврата: grep начнёт ловить ложные (переменные читаются условно) — вести явный реестр в конфиге.

## Критерии приёмки

- `REUSE_SERVER=1 pnpm e2e` переиспользует серверы (видно по логу/портам); канарейка красится при удалении переменной из `env` задачи `e2e`; `API_URL` в `env` больше нет.

## Журнал

- 2026-11-20: заведена по итогам аудита обвязки (линза архитектуры). Поведение strict env-режима подтверждено документацией Turborepo и прецедентом `VIDEO=on`, живым прогоном не проверялось. Номера строк — по состоянию дерева на дату аудита.
- 2026-11-21: живой прогон подтвердил дефект аудита и поймал его вторую половину. До правки: `REUSE_SERVER=1 pnpm turbo run e2e --force` против поднятого `pnpm dev` падал — `Error: http://127.0.0.1:3693/health is already used … or set reuseExistingServer:true` (конфиг не видел переменную, читал порты dev из `reports/ports.json` и пытался поднять свои); тот же прогон без `--force` реплеил чужой прогон из кэша (19 ms, `FULL TURBO`, порт `3684` из чужого worktree в логе) — переменная не попадала ни в env задачи, ни в хеш; токен `e2e/reports/instance-token` при обеих попытках перезаписывался. После правки: reuse подтверждён тем же `REUSE_SERVER=1 pnpm e2e` — `11 passed`, в логе нет ни одной строки `[WebServer]` (Playwright ничего не поднимал), токен и PID владельцев портов до и после не изменились. AFTER-прогон шёл против вручную поднятых серверов с env, идентичным `webServer` конфига (`ENABLE_TEST_API=1`, `INSTANCE_ID` = токен worktree): `pnpm dev` не ставит `ENABLE_TEST_API`, а `api-origin.spec` требует `/__test__` — ограничение dev-оркестратора, вне рамок задачи. `API_URL` удалён из `env` `e2e`/`perf`: читателей `process.env['API_URL']` в задаче нет (адрес вычисляется в `tools/ports.ts`, `apps/web` получает его явно от конфига Playwright, в CI — shell-переменная из `node tools/ports.ts --env`). `architecture.md` §3.2 дополнен заметкой о двустороннем правиле. `pnpm verify --full` зелёный; UI и доменная логика не менялись — `pnpm visual`/`pnpm mutation` не требуются.
- 2026-11-21: **канарейка (третий пункт «Что сделать») не реализована — защищённый путь.** Место канарейки — vitest-тест в `tools/test/` (единственный `include` корневого `vitest.config.ts`, шаг `test:hooks`), а `tools/test/**` — `deny` в `tools/protected-paths.json`: правка обычной сессией запрещена хуком и песочницей, PR с таким диффом требует label `gate-change-approved` от человека, создание гейт-файлов — операторская работа (ADR 0014, «Правило декомпозиции»: продуктовая часть — обычная сессия, подключение гейта — маленький операторский PR). В `touches` задачи стоит blanket `tools/**`, поэтому доска показала «свободна» — маршрут ошибочный, границу держат хук и CI (ADR 0014). Нужен следующий операторский PR: grep-контракт «переменные, читаемые конфигами e2e из `process.env['…']` (текстовый скан `e2e/playwright.config.ts`, `global-setup.ts`, `fixtures.ts`), входят в `env` задач `e2e`/`perf` в `turbo.json`» как фикстурный тест в `tools/test/` по разделу «Решение» этой задачи; условие возврата — там же. До той канарейки правило живёт только в этой заметке §3.2.
