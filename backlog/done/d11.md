# D11. Lefthook не ставится при `pnpm install` изнутри worktree

**Проблема.** Скрипт `prepare` запускает `lefthook install` только при условии `[ -d .git ]`. В worktree `.git` — файл-указатель, а не каталог, поэтому установка зависимостей внутри worktree хуки не ставит (прогон D2, 2026-11-14). Коммиты из свежего worktree молча идут без `pre-commit` (format, lint) и `pre-push` (typecheck, тесты, границы), пока хуки не появятся от установки в основном клоне: `.git/hooks` общий на все worktree клона.

## Что сделать

- В `prepare` заменить проверку на устойчивую к worktree: например, `[ -e .git ]` или вызов `lefthook install` без условия.
- Канарейка: установка зависимостей в каталоге, где `.git` — файл (эмуляция worktree), ставит хуки.
- Прогнать сценарий D2 в чистом worktree без установки в клоне: коммит должен пройти через lefthook.

## Критерии приёмки

- Канарейка красная до изменения и зелёная после; коммит из нового worktree без установки в клоне показывает вывод lefthook.

## Журнал

- 2026-11-14: найдено в прогоне D2 (ZCode, сценарий «ветка → worktree → install → verify → commit»).
- 2026-11-14 (ZCode, сессия выполнения): красно-зелёное доказательство в чистом клоне. Красный прогон (до фикса, 141eaae): клон → worktree (`.git` — файл) → `pnpm install` только в worktree → в общем `.git/hooks` клона хуков нет (только sample), коммит проходит молча, без вывода lefthook — баг воспроизведён. Фикс: `[ -e .git ]` в `prepare` (71d3f07). Зелёный прогон (после фикса): тот же сценарий с нуля — install в worktree ставит `pre-commit` и `pre-push` в общий `.git/hooks`, коммит из worktree показывает баннер lefthook (`lefthook v2.2.2 hook: pre-commit`). `pnpm verify` зелёный (16 шагов); `pnpm verify --full` — перед PR.
- 2026-11-14 (ZCode): открытым остаётся постоянная канарейка. По своей природе она не влезает в таблицу `GateCanary` (prepare — не шаг verify, «плохое изменение» не роняет ни один шаг), а проверка «install там, где `.git` — файл, ставит хуки» — это расширение раннера `tools/run-gate-canaries.ts`: клон во временном каталоге → worktree → `pnpm install` → assert `pre-commit`/`pre-push` в общем `.git/hooks`. Полный клон обязателен, а не worktree раннера: хуки общие на клон, в CI они уже поставлены установкой в корневом чекауте — проверка внутри канареечного worktree дала бы ложно-зелёный результат. `tools/**` под deny — нужен режим обслуживания; предложено человеку (см. PR).
