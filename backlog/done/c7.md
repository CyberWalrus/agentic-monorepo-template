# C7. Генератор фичи

**Проблема.** Каждая новая фича собирается из одних и тех же слоёв руками: контракт, модуль API, фича web, каталог E2E, план. Разброс решений и расход контекста агента — цена каждого запуска.

## Что сделать

- Команда `pnpm gen feature <name>` создаёт заготовки во всех слоях: контракт, модуль API, фича web, каталог E2E, план в `e2e/specs/<name>.md`.
- Канарейка: сгенерированная фича во временном worktree проходит `verify`.

## Критерии приёмки

- Сгенерированная фича во временном worktree проходит `pnpm verify` без правок.

## Журнал

**Сделано.** `pnpm gen feature <name>` (tools/gen.ts) создаёт заготовки во всех пяти слоях: контракт (`packages/contracts/src/<name>.ts` + юнит-тесты схемы, проводка в `index.ts`), модуль API (`apps/api/src/<name>/` — in-memory репозиторий с интерфейсом, тесты репозитория и проводки через RPC-клиент над `app.fetch`, якорная проводка в `router.ts`/`authorization.ts`/`app.ts`), фичу web (`apps/web/src/features/<name>/` — страница, форма создания, хуки TanStack Query + поведенческие тесты), каталог E2E (`e2e/features/<name>/<name>.spec.ts`) и план (`e2e/specs/<name>.md`). После записи генератор прогоняет oxfmt по созданным/пропатченным файлам и перегенерирует `openapi.json`. `pnpm gen canary` проверяет критерий приёмки: worktree от HEAD → `pnpm install` → генерация `gen-canary` → `pnpm verify` → уборка.

**Критерий приёмки.** «Сгенерированная фича во временном worktree проходит `pnpm verify` без правок» — покрыт самой канарейкой `pnpm gen canary` (см. ниже — прогон зелёный), плюс юнит-тесты `tools/test/gen.test.ts` гоняют настоящий CLI subprocess-ом против фикстуры-репозитория (8 тестов: все пять слоёв, hyphenated-имена, вторая фича рядом с первой, отказ на коллизии/дрейфе якоря до записи, трассировка AC сгенерированной E2E против её плана).

**Решения.**

- Домен заготовки — вертикальный срез list+create с политикой public (образец — tasks): без toggle/owner/Postgres. Альтернатива — пустые TODO-файлы: отклонена, они не прошли бы гейты (юнит-тесты, knip, трассировка). Сущность — имя без хвостовой 's'; kebab остаётся в путях и текстах, символы кода — camelCase (канарейка поймала первую версию шаблонов, где `gen-canary` попадал в код идентификатором).
- Страница не монтируется в маршрут: `routeTree.gen.ts` пишет vite при сборке, а fast verify не собирает — новый маршрут без регенерации ломал бы typecheck в свежем worktree. Маршрут, визуальный тест и перф-бюджет добавляет автор фичи (это записано в подсказке генератора и в заголовках шаблонов); состояние загрузки появляется вместе с Suspense в маршруте, пусто/ошибка/успех в заготовке есть и покрыты тестами.
- E2E заготовки — контрактный HTTP через OpenAPI-транспорт (`API_URL/api/<name>`), как seedTasks/api-origin; UI-сценарии приходят с маршрутом. AC заготовки трассируются двусторонне (юнит-тест + гейт трассировки в --full).
- Тесты генератора — subprocess-стиль backlog-cli.test.ts, без импорта gen.ts: файл, втянутый импортами `tools/test/**`, попадает в замыкание гейт-контурa (check-tool-class) и обязан быть deny, а генератор — инструмент review-класса. pnpm в тестах подменяется стабом через PATH.
- Коллизии и дрейф якорей ловятся до первой записи: план генерации валидируется целиком, генерация применяется либо полностью, либо никак.

**Проверка.** `pnpm verify` в worktree задачи — PASS (18 шагов). `pnpm gen canary` — зелёный (см. финальную запись журнала). Дифф не трогает защищённые пути: tools/gen.ts и package.json — класс review; новые зависимости не добавлялись.

**Дальше.** Эксперимент: несколько сгенерированных фич в одном репозитории покрываются юнит-тестом («вторая фича рядом с первой»); если в реальном использовании появятся коллизии имён символов (например, `useNotes` в двух фичах) — вернуться к задаче и добавить валидацию занятых символов.
