# E67. visual-approve: токен в argv двух git-команд

**Проблема.** `.github/workflows/visual-approve.yml:128`: `git fetch --depth=1 "https://x-access-token:${{ github.token }}@github.com/${REPO}.git"`, так же push базлайнов — токен в URL git-команды виден в `ps` (argv) на время команды. Смягчение: раннер эфемерный, токен живёт один job. Это осознанный остаток e24 (PR, строка реестра 2026-11-23): экспозиция сужена с env шести шагов до URL двух команд, остаток описан в комментарии (`:126-127`) и журнале `backlog/done/e24.md`. Аудит владельца, 2026-11-23, «Низкие → Безопасность и стабильность», подтверждает остаток как низкий риск.

## Что сделать

1. Оценить варианты без токена в argv: `actions/checkout` с сохранением учётных данных на втором шаге; заголовок авторизации через переменные окружения git (`GIT_CONFIG_*`) вместо URL; credential helper, читающий токен из env шага. Для каждого — где живёт токен (argv, env шага, `.git/config` в дереве PR) и что видит лог.
2. Выбрать вариант по решению в «Решении»; инвариант e24 — после checkout PR head ничего из PR-дерева не исполняется — не ослабить.
3. Если контур меняется: обновить структурный тест e38 (`tools/test/visual-approval.test.ts`) — в URL git-команд workflow нет `x-access-token:`; zizmor-комментарий шапки — без ложных утверждений.
4. PR с разделом «Изменения гейтов»; находки `security-reviewer` — в PR. Строку реестра за e24 дополнить: экспозиция argv закрыта либо принята с обоснованием.

## Критерии приёмки

- Либо токена нет в argv (тест п.3 зелёный; `ps` и `git config --list` на живом прогоне — в «Журнале»), либо в «Журнале» записано решение «остаточный риск принят» со сравнением вариантов из п.1.
- Инвариант e24 не ослаблен (тест e38 зелёный); `pnpm probe:plugin` и zizmor зелёные.
- Строка реестра e24 дополнена тем же PR при изменении; при решении «принят» — дополнена обоснованием.

## Решение

По умолчанию — не менять контур, если каждый вариант без argv ставит токен туда, где экспозиция шире: в env шага (e24 убрал его оттуда намеренно) или в `.git/config` в дереве PR. На эфемерном раннере argv виден только процессам того же job. Условие возврата: раннер перестаёт быть эфемерным (self-hosted) или появляется второй workflow с токеном в URL — тогда обязательный переход на `GIT_CONFIG_*`.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — `.github/**`, `tools/test/**` (deny).
