# C3.3. Preview-окружение на PR

**Проблема.** Preview-окружений нет ни человеку для одобрения визуальных изменений, ни агентам для исследовательского тестирования.

## Что сделать

- Preview-окружение на PR на базе production-entry из C3.2: образ и команда запуска в PR, жизнь до merge или закрытия (форма — в разделе «Решение»).
- Агентам preview даёт исследовательское тестирование вне гейтов на том же образе, что деплоится.
- Доступ к preview с данными тестового контура, не production-секретами.

## Решение (2026-11-15)

Выбор делегирован человеком агенту в сессии 2026-11-15; принимается merge PR с этой правкой (ADR 0009, «Развилки в задачах»).

- **Окружение на PR, а не общий кластер.** Общего кластера нет, а его появление — отдельная инфраструктура с собственными секретами; окружение на PR изолировано по построению (З9).
- **Ядро без SaaS (З12):** на каждый PR job собирает образ из C3.2 и кладёт его в GHCR с тегом `pr-<номер>` (хватает `GITHUB_TOKEN`, новый аккаунт не нужен); в PR появляется комментарий с командой запуска образа. После merge или закрытия PR тег удаляется.
- **Живой URL — необязательный слой.** Он требует аккаунта у провайдера и секрета деплоя; это действия из «Что остаётся человеку» (ADR 0009). В этой задаче слой не реализуется. Он становится отдельной задачей, когда человек добавит в `docs/github-setup.md` имя переменной секрета провайдера — не значение секрета; выбор провайдера следует из заведённого аккаунта.
- Следствие для B3.1: человек смотрит визуальный дифф по отчёту CI, а не по живому окружению.

## Критерии приёмки

- PR получает комментарий с тегом образа и командой запуска автоматически; после merge или закрытия PR тег удаляется; секреты production в образ и в job не попадают.
- Job не запускается для PR из форков с правом записи в реестр (доверенная база, З2).

## Журнал

- 2026-11-15: развилка «общий кластер или окружение на PR» закрыта разделом «Решение»; критерий «ссылка на живое окружение» заменён на образ в GHCR, живой URL вынесен в необязательный слой; `needs_human` снят. Задача трогает `.github/workflows/**` — её ведёт оператор (ADR 0009).
- 2026-11-22: захват оператором (`task/c3.3`), файл перенесён в `backlog/done/`. План составлен по разделу «Решение» — новых развилок нет. План: job в `.github/workflows/ci.yml` на `pull_request` собирает образы production-entry из C3.2 (`apps/api/Dockerfile`, `apps/web/Dockerfile`) и пушит их в GHCR тегом `pr-<номер>` через `GITHUB_TOKEN`; право записи в реестр (`packages: write`) — только у этого job и только для PR не из форка (доверенная база, З2). В PR автоматически публикуется комментарий с тегами образа и командой запуска preview — команда нужна и человеку для одобрения визуальных изменений (B3.1 смотрит по отчёту CI), и агентам для исследовательского тестирования вне гейтов. Отдельный шаг на `pull_request: closed` удаляет тег `pr-<номер>` после merge или закрытия. Production-секреты в job и образ не попадают: единственный секрет — `GITHUB_TOKEN`, контекст сборки чистится `.dockerignore` (ADR 0012). В `docs/github-setup.md` добавляется описание роли GHCR (пакеты, права, очистка). Не делаем: живой URL (необязательный слой — отдельная задача, когда человек добавит в `docs/github-setup.md` имя переменной секрета провайдера), перевод E2E/перфа на production-entry (C3.4), правки Dockerfile и entry (C3.2). Замечание: реализация правит `.github/**` — защищённый путь (`tools/protected-paths.json`:21), операторский режим обслуживания в worktree задачи (ADR 0009). Человеку остаётся: approve/merge PR; аккаунт провайдера и секрет деплоя для будущего слоя живого URL.
