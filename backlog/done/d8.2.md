# D8.2. `copier.yml`: вопросы, `_exclude`, файл версии; шаблонизация CODEOWNERS

**Проблема.** Копия из шаблона через `copier copy` приносит файлы разработки шаблона (`docs/roadmap.md`, `docs/research/`, `backlog/`, `docs/template-state.md`, следы владельца в `CODEOWNERS` — проба 2026-11-14 в журнале d8) и теряет связь с версией шаблона.

Задача ведёт оператор: `touches` попадает в защищённые пути (`.github/**`, `tools/**`, `copier.yml` — новый deny после этой задачи). Ведёт её оператор (ADR 0009).

## Что сделать

- `copier.yml` в корне шаблона: вопросы «имя проекта» и «владелец репозитория»; владелец обязателен — без него `gate-integrity` в проекте никогда не станет зелёным (ADR 0008).
- `_exclude` файлов разработки шаблона по результату пробы (журнал d8): минимум `docs/roadmap.md`, `docs/research/`, `backlog/`, `docs/template-state.md`, `.github/rulesets/main.json` не исключается (едет). Внимание: собственный `_exclude` Copier **заменяет** исключения по умолчанию, включая `.git` и `~` — их надо вернуть явно (ADR 0008, таблица «Файлы разработки шаблона»).
- Никаких `_tasks` и `_migrations`: они исполняют команды на машине человека при создании/обновлении (ADR 0008). Проверка отсутствия — в канарейке (d8.3).
- Шаблонизация владельца: источник — `.github/CODEOWNERS.jinja` с подстановкой ответа Copier; живой `.github/CODEOWNERS` шаблона — класс «шаблон», в копию **не едет** (в `_exclude`), в копии его замещает отрендеренный из jinja файл с владельцем проекта. Путь назначения рендера совпадает с исключаемым файлом — эту коллизию проверить в ручной пробе задачи (проба 2026-11-14 jinja ещё не знала). Живой CODEOWNERS остаётся рабочим для собственных PR шаблона; расхождение пары (владелец шаблона ↔ jinja) ловит канарейка d8.3.
- Файл версии `tools/copier-version.txt` — единственный источник закреплённой версии Copier (З10): из него берёт CI (d8.3) и инструкция в `docs/github-setup.md` (новый раздел «Создание проекта из шаблона»: `copier copy` из тега, обязательные ответы, ссылка на файл версии; копия из **тега**, не из worktree).
- Защищённые пути: `copier.yml`, `.github/CODEOWNERS.jinja`, `tools/copier-version.txt` — в `deny` `tools/protected-paths.json`; записи для них — в CODEOWNERS шаблона.
- Проба руками перед PR: `copier copy` из worktree во временный каталог, `pnpm install && pnpm verify` в копии — зелёные; замер и список того, что уехало/не уехало — в «Журнал» этой задачи.

## Критерии приёмки

- `copier copy` создаёт копию, в которой `git ls-files` не содержит `docs/roadmap.md`, `docs/research/`, `backlog/`, `docs/template-state.md` и имени владельца шаблона; `pnpm install && pnpm verify` в копии зелёные.
- `pnpm verify` шаблона зелёный с новыми записями защищённых путей; `docs:check` копии зелёный.
- В `copier.yml` нет `_tasks` и `_migrations`; ответы сохраняются в `.copier-answers.yml` копии.
- Демо-домен (`apps/`, `packages/`, `e2e/`) копируется — решение d8: рабочий пример нужнее пустого каркаса, повторно при обновлении не приезжает (проверит d8.7).

Механизм «живой `.github/CODEOWNERS` + рендер в тот же путь» в copier 9.19.1 невозможен. Решение: живой CODEOWNERS шаблона переехал в `docs/CODEOWNERS` (третье допустимое GitHub-расположение, приоритет ниже `.github/`), в копию не едет (исключение `docs/CODEOWNERS` — самоякорное), рендер jinja попадает ровно в `.github/CODEOWNERS` копии, который жёстко читает `gate-integrity`. Альтернативы: живой файл в корне (работает, но исключение требует ведущего слеша — паттерн без слеша матчит компонент пути на любой глубине и задел бы рендер); копия без CODEOWNERS и ручное создание человеком (ломает ADR 0008 «владелец подставляется обязательно», красит `gate-integrity` первого PR до настройки). Цена решения: `check-gate-approval.ts` принимает кандидатов CODEOWNERS (`.github/`, корень, `docs/` — как порядок приоритета GitHub, берёт первый существующий) — правка гейта, отражена в разделе PR «Изменения гейтов»; условие возврата: GitHub убирает поддержку `docs/CODEOWNERS` или `gate-integrity` меняет способ чтения владельцев — ревизия ADR 0002/0008.
