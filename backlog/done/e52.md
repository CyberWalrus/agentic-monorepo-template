# E52. remove задачи: успех без удаления

**Проблема.** `apps/api/src/router.ts:35`: `remove` вызывает `context.tasks.remove(input.id, context.workspaceId ?? undefined)` и отвечает успехом независимо от того, удалена ли задача. Домен владельца не проверяет (комментарий `:33-34`: у задачи без владельца — нет или чужой — мидлварь отказывает раньше, C2.3), а результат удаления никто не смотрит: когда владелец совпал, а workspace чужой, задача остаётся на месте, а клиент получает успех. Латентно: для проявления нужен актор — в шаблоне акторов нет (c2.3), в проекте-потребителе с акторами появится. Аудит владельца, 2026-11-23, «Средние → Домен и фронтенд». Строки в `docs/escaped-defects.md` нет.

## Что сделать

1. Воспроизвести и зафиксировать в «Журнале» точную комбинацию (владелец, workspace, реализация хранилища), при которой remove отвечает успехом без удаления; если на текущем коде комбинация недостижима — записать доказательство тестом.
2. Регрессии: задача владельца A в workspace W1, запрос remove с заголовком workspace W2 — ответ ошибка, задача на месте; одинаково для InMemory (`apps/api/src/tasks/repository.test.ts`) и Postgres (`apps/api/src/tasks/database.test.ts`); на уровне роутера (`apps/api/src/router-divergence.test.ts`) — ответ совпадает с ответом для несуществующего id (существование чужой задачи не раскрывается).
3. Роутер проверяет результат домена и отвечает `errors.NOT_FOUND()`, когда не удалено; либо домен бросает NOT_FOUND, когда задачи в этом workspace нет, — одно из двух. Если для этого нужен ответ или ошибка, которых нет в контракте, — сначала отдельная задача изменения контракта (contract-first), от неё зависит эта.
4. Строка в `docs/escaped-defects.md` тем же PR.

## Критерии приёмки

- Тест из п.2 красный до правки (успех без удаления) и зелёный после; на обеих реализациях хранилища исход одинаковый — либо в «Журнале» записано доказательство недостижимости с закрывающим инвариантом.
- Ответ для «чужой по workspace» совпадает с ответом для несуществующего id.
- pnpm verify зелёный; pnpm mutation по изменённой логике — выживших мутантов нет.
- Строка добавлена в `docs/escaped-defects.md`.

## Решение

Ошибка «не найдено», а не «запрещено»: чужая задача для клиента не существует — тот же принцип, что у мидлвари C2.3. Условие возврата: если контракт уже описывает для remove иной ответ на эту ситуацию — следовать контракту и записать в «Журнале».
