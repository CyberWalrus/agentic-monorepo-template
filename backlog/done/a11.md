# A11. Дрейф живого ruleset от снимка

**Проблема.** Снимки `.github/rulesets/*.json` описывают живые правила GitHub, но применяет их человек в интерфейсе (A9.1, d8.4): живой ruleset можно изменить или выключить в любой момент — а снимок продолжит утверждать защиту, которой нет. `gate-integrity` защищает файлы `.github/**` в PR, но не состояние интерфейса GitHub; сверка живого состояния со снимком существует только как разовое ручное действие (прецедент d8.5 — GET и посимвольная сверка), дрейф после неё не ловится ничем (находка security-ревью A9, 2026-11-17).

## Что сделать

- Ночной job в `nightly.yml`: `gh api repos/:owner/:repo/rulesets` → для каждого ruleset с известным id (реестр живых правил — [docs/template-state.md](../../docs/template-state.md), раздел о живых правилах) сверить живую конфигурацию со снимком; расхождение — issue с label `nightly-failure`.
- Обвязка отчётов nightly уже есть; доступ к API — тот же `gh`, что у `backlog doctor`.

## Критерии приёмки

- Канарейка: расхождение снимка и живого ruleset детектируется (детерминированный bad-change — правка снимка в фикстуре); недоступный `gh api` валит шаг громко (З11), не молча.

## Журнал

- 2026-11-17: заведена из security-ревью A9 (находка 2): дрейф живого ruleset и снимка не ловится ничем, кроме разовой ручной сверки; рекомендация — ночной чек с issue по label `nightly-failure`.
