## Решение

Выбрано: deny для конфигов сканеров/ignore/тулчейна (в нормальной работе фич не меняются — как их соседи .oxlintrc.json/.oxfmtrc.json/knip.json), review для **/tsconfig.json и **/package.json (меняются в каждой второй фиче — граница по ADR 0014: обязательное ревью). Альтернатива «всё в deny» отклонена: превратит каждую фичу, трогающую package.json, в режим обслуживания. Условие возврата: если review-класс окажется проходим мимо ревью (в репозитории-потребителе CODEOWNERS пуст) — ужесточить до deny; канарейка strict-флагов (B13) остаётся защитой в глубину независимо от класса.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — tools/protected-paths.json и lefthook.yml (deny).

**Находка 3 ревью (denyWrite `**/.gitignore` × `pnpm install`, 23.11) — решение за владельцем, в ветке не принималось.** Факты: (1) репродукция в каталоге вне репозитория (`git archive HEAD`, pnpm 12.21.0): `pnpm install --frozen-lockfile --prefer-offline --ignore-scripts` — контроль exit 0 (598 пакетов), под `sandbox-exec` с запретом записи `(^|.*/)\.gitignore$` — exit 1, «installing dependencies», `…/cpu-features@0.0.10/…/deps/cpu_features/.gitignore: Operation not permitted (os error 1)`, 57 пакетов из 598; (2) в свежем node_modules под глобы ветки попадают `.gitignore` ×2, `.eslintignore` ×2, `.prettierignore` ×5 — на origin/main ни один `**/`-глоб таких файлов не задевает (`**/__screenshots__/**`, `**/vitest.config.ts`, `**/stryker.*` — 0 совпадений), коллизию вводит b8; (3) в бинаре Claude Code 2.1.330 есть транслятор глоб→regex без исключения dot-файлов (`**/` → `(.*/)?`, `**` → `.*`, `*` → `[^/]*`); что он применяется к `filesystem.denyWrite` на macOS — не проверял, живого прогона в Claude Code не делал. Почему честного решения без сужения защиты в задаче нет: `denyWrite` обязан совпадать с `deny` по строкам (`tools/check-sandbox-paths.ts:164-173`, З10), а глоб, покрывающий `.gitignore` на любой глубине для хука и CI (`**/.gitignore`), в песочнице регуляркой задевает и файлы пакетов; паттерны ограниченной глубины сталкиваются начиная с 5-го уровня (раскладка pnpm `node_modules/.pnpm/<pkg>@<ver>/node_modules/<pkg>/<file>`) и оставляют без класса `apps/web/src/features/<фича>/<файл>` и глубже; перечисление каталогов первого уровня (альтернатива развилки находки 1, 22:43) оставляет новый каталог без класса. Варианты: **A** — развести списки правилом: `denyWrite` = `deny` минус явные исключения для глобов, совпадающих с файлами пакетов (`**/.gitignore`, `**/.eslintignore`, `**/.prettierignore`), в песочнице — конкретные пути ignore-файлов; цена — правка гейта `tools/check-sandbox-paths.ts` (deny), его канарейки и ADR 0004 («ровно deny»), отдельная задача режима обслуживания; хук и CI сохраняют полный охват, песочница для новых вложенных ignore-файлов остаётся как на main. **B** — снять три `**/`-глоба, оставить конкретные пути: цена — новая вложенная `.gitignore` вне скрытых каталогов снова без класса в хуке и CI (открывает обязательную находку 1 первого раунда), то есть сужение защиты. **C** — оставить как есть: цена — по репродукции каждая агентная сессия Claude Code в новом worktree падает на `pnpm install` в preflight. Выбрано: ничего — код не менялся, merge до решения не делать. Ближайший шаг — один живой прогон свежей `pnpm install` в Claude Code с песочницей в новом worktree: падает → A задачей режима обслуживания; не падает — находка снимается доказательством, `$comment` дополняется. Условие возврата: если при A в песочнице воспроизведён вектор находки 1 первого раунда (новая вложенная `.gitignore` уводит файл от гейтов) — пересмотреть границу «песочница — конкретные пути».
