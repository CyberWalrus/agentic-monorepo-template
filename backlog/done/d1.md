# D1. Общие инструкции агентов — в AGENTS.md

**Проблема.** ZCode читает только `AGENTS.md`: `CLAUDE.md` не читается, `@import` не раскрывается (документация ZCode, проверено 2026-11-14). Таблицы скилов и ревьюеров лежат в `CLAUDE.md`, поэтому основной клиент их не видит.

## Что сделать

Перенести из `CLAUDE.md` в `AGENTS.md` три раздела: «Скилы» (с путями к файлам `SKILL.md`: агент без поддержки скилов читает их как документы), «Субагенты-ревьюеры» (как роли и этапы, без привязки к механизму субагентов) и правило для Healer из «Playwright Test Agents». В `CLAUDE.md` остаются четыре темы: хуки, песочница, режим обслуживания, MCP. `AGENTS.md` должен остаться коротким (architecture.md 3.9).

## Критерии приёмки

- Три раздела есть в `AGENTS.md` и отсутствуют в `CLAUDE.md`; `docs:check` зелёный.

## Журнал

### 2026-11-15 — перенос завершён, задача готова к PR

**Что сделано.** Три раздела перенесены из `CLAUDE.md` в `AGENTS.md` (после «Как делать фичу», перед «Правилами»):

- «Скилы (`.claude/skills/`)» — таблица скилов + вводная «скил — это документ `SKILL.md`; агент без поддержки скилов читает его как файл» (пути к скилам — базовый каталог в заголовке раздела).
- «Субагенты-ревьюеры (`.claude/agents/`)» — таблица ревьюеров переформулирована без привязки к механизму субагентов: «роли на этапах плана и PR — достаточно отдать им план/дифф в любом механизме ревью».
- «Playwright Test Agents» — правило Healer: помечать тест `fixme`/`skip` нельзя — работающее неправильно приложение это баг; агенты генерирует `tools/playwright-agents.sh`, перегенерация после обновления Playwright.

В `CLAUDE.md` остались четыре темы (хуки, песочница, режим обслуживания, MCP) и `@AGENTS.md` сверху; `AGENTS.md` остался коротким (~128 строк, architecture.md 3.9).

**Решения.**

- Прошлая сессия оставила перенос незакоммиченным в worktree `task-d1` (ветка без коммитов, журнал пуст). Продолжено по прямому поручению человека (`pnpm backlog resume d1` — легальный путь продолжения чужой ветки, ADR 0007); правки прошлого агента сохранены как есть.
- Ветка отставала от main на 13 коммитов: stash → fast-forward до `4b12894` → stash pop. `CLAUDE.md` на main с базы ветки не менялся, хунки `AGENTS.md` (пункт про «Журнал» в Правилах, раздел «Развитие самой обвязки») не пересекаются с точкой вставки — слилось без конфликтов.
- Текст перенесённых разделов не расширялся: задача — перенос. Дополнение таблицы скилов (например, `task-board`) — отдельное решение, вне скоупа d1.

**Доказательства:** критерий приёмки: «Скилы», «Субагенты-ревьюеры», «Playwright Test Agents» есть в `AGENTS.md` и отсутствуют в `CLAUDE.md`; `pnpm verify` PASS (16 шагов, `docs` зелёный, 288 тестов), `pnpm verify --full` PASS (21 шаг, 20.5 с) — до открытия PR.

**Ревью плана/диффа (architecture-reviewer, sanity-reviewer — approve).** По находке minor от обоих ревьюеров поправлен протухший указатель в `docs/adr/0001-initial-stack.md:27` (политика Healer теперь в `AGENTS.md`, а не `CLAUDE.md`) — файл добавлен в `touches` этого же файла задачи. Незаблокировавшие замечания для человека: в таблице «Скилы» нет строки `task-board` (пре-существующий пробел на main, кандидат в backlog — отдельная задача, на чужой ветке файлы доски не правят); заголовок «Субагенты-ревьюеры» сохраняет слово «Субагенты» при обобщённом теле — допустимо, переименование при следующей правке.
