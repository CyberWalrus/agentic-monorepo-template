# E71. `branch-scope`: ложный красный по незакоммиченной первой записи `git status`

**Проблема.** Гейт `branch-scope` проверяет и закоммиченный дифф, и незакоммиченное состояние рабочего дерева (`git status --porcelain`). Обёртка `git()` в `tools/backlog-doctor.ts:26-28` делает `trim()` вывода. Строка `git status --porcelain -z` первой записи начинается со статуса ` M` — ведущий пробел означает «не в индексе»; `trim()` его срезает, и `entry.slice(3)` в `tools/check-branch-scope.ts:141` отрезает первый символ пути. Путь не совпадает ни с собственными путями файла задачи (`:150`), ни с `touches` — гейт называет «вне touches» файл с искажённым именем, в том числе входящий в touches. Наблюдение (журнал `backlog/done/b8.md`, запись 2026-11-23 22:17 MSK): с незакоммиченной правкой `backlog/done/b8.md` первой в выводе `pnpm verify --only docs,branch-scope,format,lint` красил `branch-scope` — «файлы вне touches задачи: acklog/done/b8.md», exit 1; на закоммиченном состоянии тот же вызов → PASS. Направление fail-closed (ложный красный, не пропуск), но агент получает неверное имя файла и не может понять, что чинить.

## Что сделать

1. `tools/backlog-doctor.ts`: не обрезать вывод для вызовов с `-z` (NUL-разделённый вывод) — `trim()` только для построчных вызовов; либо `tools/check-branch-scope.ts` разбирает статус без опоры на обрезанный вывод.
2. Тест в `tools/test/check-branch-scope.test.ts`: (а) незакоммиченная правка файла внутри `touches`, стоящая первой в выводе статуса, не считается выходом за touches; (б) незакоммиченный посторонний файл по-прежнему красит гейт с правильным именем; (в) запись `A `/`M ` (в индексе) не затрагивается.
3. Канарейка «дифф вне touches задачи» (`tools/gate-canaries.ts`) остаётся красной на постороннем файле — прогон `pnpm verify --json --only branch-scope` после bad-change.
4. Строка в `docs/escaped-defects.md`: дефект чекера прошёл все гейты и найден при работе над b8.

## Критерии приёмки

- Тесты (а)–(в) зелёные; `pnpm verify --only branch-scope` на ветке с незакоммиченной правкой своего файла задачи — зелёный, имя файла в сообщении при реальном выходе за touches — без искажений.
- `pnpm verify` зелёный.

## Решение

Выбрана правка разбора вывода (не обрезать NUL-вывод) с тестом на первую запись: чинит причину, не меняет предмет проверки. Альтернатива — убрать проверку незакоммиченного состояния — отклонена: окно жизни транзиентных фикстур (`tools/hooks/.lint-probe.fixture.ts`, `b6-canary-leak.fixture.ts`) гейт ловит именно в рабочем дереве. Условие возврата: если окажется, что обрезка нужна другим потребителям `git()`, — развести два помощника.

Задача ведёт оператор (режим обслуживания): touches — `tools/**` под deny.
