# B4.1. Выбор E2E-тестов по фичам

**Проблема.** `e2e` оформлен одним пакетом: любое изменение web или api запускает все E2E, хотя vision обещает «E2E затронутых фич».

## Что сделать

- Отображение путей в фичи: изменение в `apps/web/src/features/<f>/` запускает `e2e/features/<f>/`; изменение в `packages/`, `apps/api`, `src/lib` или конфигах запускает всё.
- Тесты `@critical` идут всегда; в merge queue идёт всё.
- Эвристика может ошибаться только в сторону «запустить больше»; полноту страхует merge queue.

## Критерии приёмки

- Канарейка: изменение в `features/<f>` не запускает чужие фичи, изменение в `packages/` запускает всё; PR с пропущенным тестом ловится merge queue.

## Журнал

- 2026-11-17 16:24 MSK: режим обслуживания включён (оператор, поручение человека «ты оператор»): ветка `task/b4.1` захвачена командой `pnpm backlog start b4.1 --operator` (внедрена задачей D13, PR #59) — первый захват без ручных git-команд; в worktree задачи создан `.claude/settings.local.json` (ADR 0009).
- Решение (развилка «где живёт выбор и как всегда гонять @critical», ADR 0009): выбор — файловый (`testIgnore` проекта functional в `e2e/playwright.config.ts`), значение приходит через env `E2E_FEATURES`, который считает CI в job `e2e` по `git diff --name-only <base.sha>...HEAD` тем же base, что у `TURBO_SCM_BASE`; локальный `pnpm e2e` и merge queue/nightly без env — идёт всё; env действует только при `CI` (M1-ревью: локальный прогон агента не сужается случайной переменной). Логика — чистая функция в `tools/e2e-select.ts` + CLI (stdin/args → `all` или список). «@critical идут всегда»: конфиг не игнорирует файл незаданной фичи, если в его исходнике есть литерал `@critical` (скан исходника при вычислении конфига; упоминание в комментарии тоже считается — направление «больше»); альтернатива — второй проект `critical` с `--grep` — отклонена: дубли проектов ломают семантику отчёта test-report и усложняют CI-команду. Защита от опасного направления «выбрать пусто»: (1) незаданная app-фича без своего каталога в `e2e/features/` переводит выбор в `all` (новая поверхность продукта — полный E2E, пока у неё нет e2e); (2) пустой/неразборчивый список → `all`; (3) не-фича под `e2e/features/` (helpers) — общая кодовая база E2E → `all`; (4) каталог без `*.spec.ts`/`*.visual.ts` — не фича; (5) пустой отчёт functional красит существующий гейт `test:report` (A3).
- Ревью плана (2026-11-17): `architecture-reviewer` — approve (обязательные M1 «env только при CI» и M3 «аннотации З5/З6» — сделаны); `sanity-reviewer` — changes-requested, все три находки закрыты: H1 — сквозные e2e-фичи (a11y, api-origin, route-states, traceability — без app-каталога) не игнорируются никогда, гоняются в каждом PR: тем самым окно «a11y/route-states не доезжают до main до a9.1» закрыто самим правилом, merge queue (a9.1) остаётся страховкой полноты для фичевых отсечений; H2 — `E2E_FEATURES` объявлен в `env` turbo-задачи e2e (перезапуск PR с тем же SHA больше не реплеет из кэша отчёт старого подмножества), `turbo.json` и `docs/architecture.md` добавлены в `touches`; M3 — тест отсортирован/переписан. Вердикты в разделе PR «Изменения гейтов».
- Канарейки: юнит-тесты чекера (`tools/test/e2e-select.test.ts`) + канарейка проводки в `gate-canaries.ts` (срыв привязки конфига красит `test:hooks`); аннотации исключений — З5/З6 в `docs/architecture.md` (M3-arch).
