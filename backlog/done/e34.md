# E34. Джоба телеметрии трендов падает в ночи

**Проблема.** Ночь 45013082390 (2026-11-22), джоба «telemetry trends (c9.4)» — шаг «telemetry report (trends.json + step summary)» завершился exit 1; внятного сообщения об ошибке в логе не видно (только `##[error]Process completed with exit code 1`). По замыслу (nightly.yml:46–50) отсутствие артефакта читается как «нет данных», поэтому падение — это либо незакрытая ветка обработки отсутствия (нарушение З11), либо отдельный дефект отчёта. Вероятный каскад от e31 (нет артефакта flaky-rate из-за упавшего flake hunt), но падение на отсутствующих данных всё равно дефект: absence обязано быть обработанным состоянием.

## Что сделать

1. Локально воспроизвести прогон отчёта на артефактах последней ночной (или на пустом наборе) и получить настоящее сообщение об ошибке — записать его в «Журнал».
2. Устранить: либо ветка обработки отсутствия данных (если каскад — после e31), либо дефект логики отчёта.
3. Тест в `tools/test/` на пустой/частичный набор входов: отчёт завершается «нет данных», а не исключением.
4. Диспетч ночной: «telemetry trends (c9.4)» зелёная.

## Решение

Сначала диагноз, потом выбор ветки фикса; каскадная версия не отменяет пункт 3 — absence-обработка проверяется тестом в любом случае. Условие возврата: если причина в самом GitHub API (лимиты, недоступность) — добавить ретрай с внятным сообщением, не менять семантику.

## Критерии приёмки

- Отчёт на пустом/частичном входе пишет «нет данных» и завершается 0.
- Диспетч ночной: «telemetry trends» зелёная.
