# D13. Режим оператора в `pnpm backlog`

**Проблема.** ADR 0009 разрешает операторской сессии вести задачи режима обслуживания и задачи с `needs_human: оператор: …`, но `pnpm backlog start` отказывает на обоих статусах, а `next` такие задачи не выдаёт (`tools/backlog.ts`, `commandStart` и `commandNext`). До этой задачи оператор захватывает задачу ручными git-командами — это отступление от правила «git вызывает сама команда, а не агент» (ADR 0007). Забытый файл режима обслуживания ничем не обнаруживается (тихое окно ADR 0004).

## Что сделать

- `pnpm backlog next --operator`: выдаёт первую задачу оператора — статус «режим обслуживания» или `needs_human`, начинающийся с `оператор:`; порядок — приоритет, затем число задач, которые она открывает. Если в клоне уже есть ветка задачи режима обслуживания без открытого PR — сообщает о ней и новую не выдаёт (ADR 0009, «Очерёдность»).
- `pnpm backlog start <id> --operator`: захватывает такую задачу тем же атомарным созданием ветки. Без флага поведение прежнее: отказ с объяснением. Флаг — подсказка, а не граница (З3): границей остаётся CI.
- `pnpm backlog list`: задачи с `needs_human` вида `оператор: …` и `отложено: …` показывает отдельными статусами, а не общим «заблокирована».
- `docs:check`: непустой `needs_human` начинается с `оператор:`, `отложено:` или `человек:`; иное красит проверку. Третий префикс вводится этой задачей — для действий из строки «Что остаётся человеку» ADR 0009; существующие задачи приводятся к нему тем же PR. `оператор:`-действие, называющее label, approve, merge, пароль, токен или аккаунт, красит проверку: такие действия не делегируются (ADR 0009, «Что остаётся человеку»).
- `pnpm backlog doctor`: файл `.claude/settings.local.json` в основном checkout — блокирующее расхождение безусловно; в рабочем дереве задачи — если у его ветки есть открытый PR или нет коммитов дольше `DOCTOR_IDLE_HOURS`.
- После внедрения убрать ручные git-команды из `AGENTS.md`, `CLAUDE.md`, скила `task-board` и строки «Захват до D13» ADR 0009.

## Критерии приёмки

- Канарейки: `start` без флага на задаче режима обслуживания получает отказ, с флагом — захват; из двух одновременных `start --operator` одной задачи проходит один; оставленный файл режима обслуживания красит `doctor`; `needs_human` без допустимого префикса красит `docs:check`.
- В инструкциях агентов не осталось ручного захвата через `git branch`.

## Журнал
