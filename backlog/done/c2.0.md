# C2.0. Метаданные политик доступа в контракте и тест перебора

**Проблема.** Ошибки доступа (чтение чужого ресурса по id) типичны для сгенерированного кода, а ревьюер-LLM их не гарантирует; политика доступа должна объявляться в контракте и проверяться тестом, а не договорённостью.

Продуктовая часть бывшей C2.1: защищённых путей не трогает, её берёт обычный агент. Канарейку шага добавляет оператор задачей C2.1.

## Что сделать

- Каждая процедура контракта объявляет политику доступа в метаданных (тип: публичная, владелец, администратор — с параметрами).
- Тест в `packages/contracts` перебирает контракт и падает на процедуре без политики. Тест идёт обычным шагом `test` в `pnpm verify` — блокирует сразу, без правки `tools/`.
- Метаданные проектировать с учётом будущего oRPC 2 (сейчас 2.0.0-beta.50, до стабилизации не мигрировать): смена затрагивает только пакет контрактов.
- Выбор набора типов политик и их параметров — архитектурная развилка: записать ADR (список запланированных ADR — `docs/architecture.md`, раздел 5, где развилка привязана к этой задаче).
- После правки контракта — `pnpm --filter @repo/contracts openapi` (скил `api-contract-change`).

## Критерии приёмки

- У каждой процедуры контракта объявлена политика; тест перебора зелёный.
- В PR показано направление: временно убранная политика одной процедуры красит тест (вывод прогона в описании PR; постоянная канарейка — C2.1).
- `openapi.json` перегенерирован, дрейфа нет.
