# C1.6. Миграции: advisory lock на старте сервера

**Проблема.** `migrateTaskDatabase` вызывается на каждом старте сервера (`apps/api/src/server.ts:26-28`), а `drizzle-orm` 0.45.4 в `migrate` не берёт блокировку: читает последнюю запись `__drizzle_migrations` и применяет DDL вне транзакции. Две реплики, стартовавшие одновременно против пустой базы, обе решат «миграций нет» — вторая упадёт на `CREATE TABLE`. Шаблон с production-образом (ADR 0012) должен держать scale-out ≥ 2 из коробки.

## Что сделать

- Обернуть запуск миграций в `pg_advisory_lock` (сессионный, на отдельном соединении) с гарантированным снятием в `finally`.
- Тест: два параллельных старта против пустой базы — оба зелёные, миграции применены ровно один раз.

## Решение

- **Advisory lock в процессе сервера.** Почему: не добавляет шаг в деплой и сохраняет честность образца «поднялся — база готова».
- Альтернатива: вынести миграции в init-шаг деплоя/отдельный контейнер. Условие возврата: появится оркестрация с явными init-шагами — переезжать туда.

## Критерии приёмки

- Тест параллельного старта зелёный; повторный старт на мигрированной базе не выполняет DDL повторно.

## Журнал

- 2026-11-20: заведена по итогам аудита обвязки (линза бэкенда). Поведение `migrate` подтверждено чтением dist drizzle-orm 0.45.4, не прогоном. Номера строк — по состоянию дерева на дату аудита.
