# E60. Перф-смоук API: чужой путь и нестабильный набор данных

<!-- 2026-11-24: depends_on: e72 — работа вне доски, волна seed-D7. Задача объявляет docs/architecture.md; пока D7 считает этот путь пересечением (правка — задача e72), такие задачи захватываются по одной. e72 отклонена или остановлена — зависимость снять тем же PR. -->

**Проблема.** `e2e/perf/k6/api-smoke.js`:

- Перф-бюджет API меряет прямой `/api/tasks`, а не продуктовый `/rpc` через прокси — бюджет описывает путь, которым пользователь не ходит; накладные расходы oRPC-сериализации и прокси в бюджете не видны.
- Список без пагинации не проверен ни на одном уровне больше 20 задач; k6-смоук считает p95 по растущему списку — метрика несравнима от прогона к прогону.

Аудит владельца, 2026-11-23, «Средние → Тесты и перф». Строк в `docs/escaped-defects.md` нет.

## Что сделать

1. k6-смоук: сценарий по продуктовому пути (`/rpc` через прокси web) с теми же метриками (p95, доля ошибок); прямой `/api/tasks` оставить диагностическим сценарием без бюджета или убрать.
2. Фиксированный набор: перед замером список приводится к известному размеру (константа сценария), одинаковому от прогона к прогону.
3. Тест на список больше 20 задач: InMemory (`apps/api/src/tasks/repository.test.ts`) и Postgres (`apps/api/src/tasks/database.test.ts`) — 50 задач возвращаются целиком, порядок «newest first», без обрезки; в e2e (`e2e/features/tasks/tasks.spec.ts`) — одна проверка на 30 и больше задач.
4. `perf-budgets.json`: порог нового сценария — по правилу раздела «Пороги» ADR 0009; существующие пороги не поднимать.
5. В `docs/architecture.md` — какой путь меряет бюджет API.
6. Строка в `docs/escaped-defects.md` тем же PR.

## Критерии приёмки

- Отчёт `pnpm perf` показывает сценарий `/rpc` с бюджетом; записи в `perf-budgets.json` относятся к продуктовому пути.
- Три прогона `pnpm perf` подряд — размер списка в сценарии одинаков (числа в «Журнале»).
- Тесты из п.3 зелёные; если они вскрывают обрезку или сбой порядка — дефект исправлен и отражён в строке реестра.
- pnpm verify зелёный; строка добавлена в `docs/escaped-defects.md`.

## Решение

Бюджет меряет тот путь, который проходит запрос пользователя, на фиксированных данных: иначе число ничего не значит. Условие возврата: если `/rpc` через прокси в k6 требует авторизации или ручек, которых нет в тестовом окружении, — остановиться и записать в «Журнале», чего не хватает, не добавляя продуктовых ручек ради теста.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — `perf-budgets.json` (deny).

  1. Порог `api` не менялся (50 мс, доля ошибок 0.01), в `perf-budgets.json` добавлен только комментарий, какой путь меряет секция. Почему: по ADR 0009 «Пороги» потолок нового сценария — медиана CI-замера × 3 с округлением вверх до 10 мс, а CI-замера нового сценария нет до первого прогона PR; локальные числа — не CI. Альтернатива — поставить потолок по локальному замеру (1,09 мс × 3 → 10 мс): отклонена, на CI-раннере такой потолок с высокой вероятностью красный, а подъём порога — ослабление, которое делает только человек. Следующий шаг: после первого CI-прогона k6 пересчитать по правилу — вниз оператор, вверх человек.

Альтернатива — сценарий create с фиксированным числом итераций (размер растёт детерминированно): отклонена, p95 снова считается по растущему списку. Условие возврата: появится размер-нейтральный create (например, тест-API в k6-шаге) — добавить сценарий create с собственным порогом.
