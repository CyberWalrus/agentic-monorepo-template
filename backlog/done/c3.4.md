# C3.4. E2E и перф против production-способа запуска

**Проблема.** E2E и перф гоняются против dev/preview-способа запуска, а деплоится production-entry — тестируется не то, что едет в прод.

## Что сделать

- E2E, перф и визуальные тесты поднимают приложения тем же способом, что и production (entry из C3.2), локально и в CI.
- `vite preview` и dev-серверы остаются только для интерактивной разработки.
- Перф-метрики переснять после переключения: способ запуска меняет абсолютные числа (`perf-budgets.json` при сдвиге правит оператор отдельным PR по правилу ADR 0009, «Пороги»).

## Критерии приёмки

- `pnpm verify --full` и CI поднимают приложения production-способом; ссылок на `vite preview` в скриптах тестов не осталось.

## Журнал

- 2026-11-22, план до кода (раздела «Решение» в файле нет — развилку закрыл сам, ADR 0009 «Развилки в задачах»). Единственный тестовый способ подъёма web — webServer в `e2e/playwright.config.ts:136` (`pnpm --filter @repo/web start` = `vite preview`, `apps/web/package.json:16`); api уже production-способ (`node src/server.ts`), и в CI-перфе тоже (`ci.yml:341`).
  (1) Развилка «судьба скрипта `start`»: оставляю как есть, e2e webServer переключаю на `start:prod` (`node server.ts`; PORT — env, обязательный без дефолта, `apps/web/src/lib/env.ts:75-82`; HOST — дефолт 127.0.0.1; API_URL обязателен). Почему: touches не включает `apps/web/**`, приёмка требует отсутствия `vite preview` только в скриптах тестов, а preview остаётся «интерактивной разработкой» по условию задачи. Альтернатива (`start` = production, `start:preview` = интерактивный) тянет правки README, текстов-hint в `env.ts`/`env.test.ts` и `product-logic-reviewer.md` — отдельная задача; условие возврата: появление требования «`start` — production по умолчанию».
  (2) Readiness-URL webServer web — `${WEB_URL}/healthz` вместо корня: дёшево и без SSR-зависимости от API (`apps/web/src/server-app.ts:180`).
  (3) `tools/visual.sh` и `tools/visual-inner.sh` правок не требуют: `vite preview` в них отсутствует (grep), visual-скриншоты идут через общий playwright-конфиг, build web внутри `visual-inner.sh:23` уже есть. Проверено `docker run ... node -v` в visual-образе pw1.64.1-noble: Node v24.22.1 — type stripping нативный, `node server.ts` совместим.

Файл режима обслуживания не создаётся: ZCode хуки проекта не исполняет, по ADR 0009 («Режим обслуживания оператором») «в клиенте без хуков проекта шаги 2 и 4 пусты»; verify после каждого шага, `verify --full` + `canaries` перед PR — сам.   Перф: после переключения переснять (`pnpm perf` локально, тренд в CI); сдвиг абсолютных потолков — по правилу ADR 0009 «Пороги» (медиана CI-замера × 3, замер прикладывается к PR; значение слабее текущего порога — предлагает и выполняет только человек). Детерминированные метрики (запросы, байты) измениться не должны — если изменились, это регрессия, чинится код.
