# C10.1. Логика хуков — CLI в `tools/` без привязки к агенту

**Проблема.** Логика хуков живёт внутри формата Claude Code; основной клиент ZCode исполняет только пользовательские хуки и хуки плагинов, хуки уровня проекта игнорирует — контура L0 в ZCode нет (ADR 0007).

## Что сделать

- Перенести логику каждого хука в CLI в `tools/`: проверка гейта, формат входа — JSON на stdin, код выхода 2 блокирует.
- Хуки в `.claude/` становятся тонкими адаптерами, вызывающими CLI.
- Каждый CLI тестируется напрямую, без запуска агента.

## Критерии приёмки

- Все решения хуков принимаются в `tools/`; адаптеры в `.claude/` не содержат логики, кроме вызова CLI; CLI покрыты тестами.

## Журнал

- 2026-11-17 22:16 MSK: режим обслуживания включён (оператор, поручение человека «сделай сам все» в чате сессии): захват командой `pnpm backlog start c10.1 --operator`; в worktree задачи создан `.claude/settings.local.json` (ADR 0009).
- Решения: логика переехала в `tools/hooks/` как CLI-модули **1:1** (guard-bash, protect-paths, protect-result, stop-verify, lint-changed-file, session-start, lib) — файлы и так были stdin-JSON-скриптами с exit 2 на блокировку, так что «CLI-режим» у них уже был, переехал без изменений; в адаптерах `.claude/hooks/*.ts` остались только обёртки (у guard-bash/protect-paths/protect-result/stop-verify — fail-closed exit 2 как раньше, у lint-changed-file/session-start — прямой import, поведение не менялось). Адаптер вызывает CLI-модуль **импортом в том же процессе**, а не подпроцессом: двойной spawn на каждый PreToolUse удвоил бы задержку каждой команды агента; контракт CLI («JSON на stdin, exit 2») сохранён и доступен напрямую (`node tools/hooks/guard-bash.ts`) — им пользуются адаптеры будущих клиентов (c10.3) и тесты. Команды в `.claude/settings.json` не менялись — точки входа те же. Сообщения об ошибках адаптеров сохранены дословно (их могли пинить тесты — не пинили, но слова специфичны для каждого хука).
- Тесты: спавнили адаптеры — переезд для них прозрачен, пути входов не изменились; обновлены только списки копируемых файлов в фикстурах snapshot/stop-verify. Тест `hooks are dependency-free` теперь ходит по цепочкам шести адаптеров (включая lint-changed-file) и пинит инвариант C10.1: всё вне точки входа живёт в `tools/` (общие модули — protected-paths, analyze-command, snapshot — были в цепочке и раньше); внешних зависимостей по-прежнему ноль (З4).
- Для c10.2/c10.3: адаптеры других клиентов — тот же вызов CLI (`node tools/hooks/<x>.ts` или импорт); контракт documented в заголовках адаптеров.
- Ревью диффа (2026-11-17): `sanity-reviewer` — changes-requested (заголовки protect-result/stop-verify ссылались на несуществующие *.main.ts — исправлены; «каждый CLI покрыт тестом» — добавлен прямой тест lint-changed-file: чистый файл exit 0, no-explicit-any exit 2, несуществующий exit 0); `security-reviewer` — approve (семантика защиты сохранена дословно, projectDir не от import.meta.dirname — переезд не влияет на пути, dependency-free усилен, оба расположения под deny; info для c10.3 — fail-closed обёртка и форматы протокола); `architecture-reviewer` — changes-requested (красный незакоммиченный тест на момент снимка — исправлен: пробник в tools/hooks, oxlint скипает gitignored reports/; MEDIUM fail-closed жила только в адаптерах, прямой вызов CLI падал exit 1 — закрыто: `failClosedExit` в tools/hooks/lib.ts + обработчики uncaughtException/unhandledRejection в каждом CLI, прямой вызов с битым входом exit 2, пин-тест; LOW — чек-лист расхождений для c10.3 записан в «Журнал» ниже; ADR для C10.1 не нужен — требование ADR для контура ZCode из ADR 0007 (D2) относится к c10.3, в c10.3.md не вписать с этой ветки (чужой файл) — записано здесь и в PR).
