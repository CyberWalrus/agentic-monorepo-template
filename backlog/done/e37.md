# E37. install-hook.test.ts:41 — `git add -A` без cwd ставит в индекс реального репозитория

**Проблема.** `tools/test/install-hook.test.ts:41` — `spawnSync('git', ['add', '-A'])` без опций: cwd наследуется от vitest (корень реального репозитория), тогда как соседний pnpm-вызов на :40 передаёт `{ cwd: root }` фикстуры. Во время `pnpm test:hooks` команда ставит в индекс реального worktree все изменённые/untracked файлы; когда параллельный `tools/test/lint-changed-file.test.ts` держит probe-фикстуру `tools/hooks/.lint-probe.fixture.ts`, та попадает в индекс («AD» после afterAll-rmSync) и flaky-образно красит branch-scope («файлы вне touches: tools/hooks/.lint-probe.fixture.ts»; чекер читает `git status --porcelain`, check-branch-scope.ts:134). Найдено в e24 (2026-11-23, журнал backlog/done/e24.md): 2 из 4 локальных прогонов verify красные; тот же flake может красить CI. Дефект прошёл все гейты задачи d12 (PR #116) и найден после merge — строки в `docs/escaped-defects.md` нет.

## Что сделать

1. `tools/test/install-hook.test.ts:41`: передать `{ cwd: root }` (второй `git add -A` перед commit 'lockfile' в buildFixture).
2. Проверка: до фикса прогон test:hooks на worktree с изменёнными файлами ставит их в индекс; после — `git status --porcelain` не меняется от прогона тестов (несколько прогонов подряд — flake branch-scope исчез).
3. Строка в `docs/escaped-defects.md` за d12 — тем же PR (исправление и строка идут вместе, AGENTS.md, «Всегда»).
4. pnpm verify зелёный; PR обычным поездом.

## Критерии приёмки

- `git status --porcelain` на worktree с изменёнными и untracked файлами до и после `pnpm test:hooks` идентичен (5 прогонов подряд, команда и результат — в «Журнале»).
- Все git-команды файла, меняющие индекс или дерево (`add`, `commit`, `checkout`), выполняются с `cwd` фикстуры.
- Строка за дефект d12 добавлена в `docs/escaped-defects.md` тем же PR.
- pnpm verify зелёный.

## Решение

Точечный фикс одной строки. Альтернатива — занести probe-фикстуру в .gitignore — шире и меняет политику игноров; не требуется. Условие возврата: если после фикса branch-scope продолжает флакить — причина не в этом тесте, разбирать по логу чекера отдельной задачей.
