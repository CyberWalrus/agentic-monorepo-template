# E55. Веб-сервер: не-GET мимо статики без ограждений, кэширование по URL

<!-- 2026-11-24: depends_on: e72 — работа вне доски, волна seed-D7. Задача объявляет docs/architecture.md; пока D7 считает этот путь пересечением (правка — задача e72), такие задачи захватываются по одной. e72 отклонена или остановлена — зависимость снять тем же PR. -->

**Проблема.**

- `apps/web/src/server-app.ts:327`: `app.all('*', (c) => handler(c.req.raw))` — все не-GET/HEAD запросы мимо статики (server functions TanStack Start, POST-маршруты) идут в SSR-обработчик без лимита тела и таймаута; ограждения `bodyLimitGuard` и `timeoutGuard` есть только у `/rpc/*` и `/api/*` в API (`apps/api/src/app.ts:243-244`). Сегодня server functions нет — латентно: первая добавленная получит неограниченное тело и отсутствие таймаута.
- `apps/web/src/server-app.ts:194`: `cacheable: decoded.startsWith('/assets/')` — решение о кэшировании принимает путь запроса, а не файл, который реально разрешён и отдан.

Аудит владельца, 2026-11-23, «Средние → Домен и фронтенд» и «Низкие → Безопасность и стабильность». Строк в `docs/escaped-defects.md` нет.

## Что сделать

1. Лимит тела и таймаут для не-GET/HEAD мимо статики — тот же контур, что у API; общая реализация в `apps/web/src/lib` или `packages/` (не импорт из `apps/api`), значения — из конфигурации, ответы 413 и 504 той же формы, что у API.
2. `cacheable` — по разрешённому файлу: находится ли `resolvedPath` внутри каталога ассетов сборки, а не по префиксу URL.
3. Тесты в `apps/web/src/server-app.test.ts`: POST мимо статики с телом сверх лимита → 413; зависший обработчик → 504; `/assets/…`, разрешающийся вне ассетов, → не cacheable; обычный ассет → cacheable.
4. В `docs/architecture.md` — строка о контуре веб-сервера (лимит и таймаут на всех не-GET).
5. Строка в `docs/escaped-defects.md` за `cacheable` (дефект слитого кода); для лимита и таймаута — та же строка с пометкой «латентно, закрыто до проявления».

## Критерии приёмки

- Тесты из п.3 зелёные; тест на 413 красный до правки.
- Ответы 413 и 504 веб-сервера по форме совпадают с ответами API (тест на форме тела).
- pnpm verify зелёный; строка добавлена в `docs/escaped-defects.md`; раздел `docs/architecture.md` обновлён.

## Решение

Ограждение ставится на класс запросов, а не на каждый новый маршрут: иначе каждая следующая server function будет забытым исключением. Условие возврата: если лимит на SSR-обработчик ломает штатный поток TanStack Start (тело больше лимита) — задать отдельное значение для этого класса и записать причину в «Журнале», а не снимать ограждение.
