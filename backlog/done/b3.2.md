# B3.2. Разнос визуальных сценариев по файлу на компонент

**Проблема.** Все визуальные сценарии UI лежат в одном файле `components.visual.test.tsx`: дифф одного компонента перегоняет всё и путает отчёт.

## Что сделать

- Разнести визуальные сценарии по файлу на компонент.
- Пересобрать базлайны после разноса одним одобрением (B3.1): сами снимки не меняются, меняется их группировка в отчётах.

## Критерии приёмки

- `pnpm visual` зелёный на текущих базлайнах; в отчёте сценарии сгруппированы по компоненту.

## Журнал

- 2026-11-14. План прошёл ревью `architecture-reviewer` (approve) и `sanity-reviewer`; blocker принят: «Route states» остаётся одним комбинированным сценарием — разделение его на три одиночных снимка меняло бы содержимое базлайнов, а задача требует «сами снимки не меняются». Итог: 4 файла — `Button`/`TextField`/`TaskItem` рядом с компонентами (маркап сценариев идентичен прежнему) + `route-states.visual.test.tsx` для группы состояний; общий `Frame` — в `src/testing/visual-frame.tsx`, импорт `tokens.css` внутри хелпера (пиксели не зависят от сценария).
- 👤 Критерий «`pnpm visual` зелёный на текущих базлайнах» достигается шагом человека: `pnpm visual:update` (базлайны перегруппируются в директории по именам новых файлов, пиксели прежние — сверено побайтово с captures прогона), `git rm` осиротевшей `packages/ui/src/__screenshots__/components.visual.test.tsx/`, метка `gate-change-approved` на PR. До этого шага красная visual-джоба CI — ожидаемое состояние PR, а не дефект разноса.
- Скилы `feature-workflow` и `writing-tests` переведены на конвенцию `<Component>.visual.test.tsx` рядом с компонентом.
