# B2.4. Храповик мутаций для web и контрактов в nightly

**Проблема.** Храповик работает только для `apps/api`; для web и контрактов порог `break` статичен.

## Что сделать

- Расширить nightly-храповик (см. A3) на мутационные счёты web и контрактов: nightly предлагает PR с повышением, когда счёт устойчиво выше порога.
- Оператор один раз ставит `break` по правилу ADR 0009 («Пороги»): фактический мутационный счёт, округлённый вниз, минус 5 процентных пунктов. Дальше порог движется только вверх.

## Критерии приёмки

- Канарейка: искусственно завышенный порог красит nightly-задачу; предложение PR формируется при устойчивом превышении.

- 2026-11-22, решение (раздела «Решение» в задаче нет): «устойчивое превышение» = счёт выше текущего `break` в двух последних зелёных nightly подряд; предлагаемое значение — правило ADR 0009 от минимума двух счётов, и только если оно выше текущего порога (вниз храповик не двигает). Альтернативы: один прогон (шумно, каждое случайное повышение — PR) или коммитимый файл состояния (горячий файл З9 с постоянным churn — счёт меняется каждым смерженным PR); артефактный образец уже есть у perf-trend. Условие возврата: если двухпрогонное окно даст частые холостые PR — окно расширяется до трёх прогонов тем же механизмом, ослаблением это не является (порог от этого не падает).
