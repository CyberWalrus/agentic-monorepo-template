# D8.8. Рецепт раздела 8 для свежей копии из тега

**Проблема.** С `v0.2.0` обещание `docs/github-setup.md`, раздел 8 («Затем в копии выполните `pnpm install && pnpm verify` — должно быть зелёным») для свежей копии из тега не выполняется: проба 2026-11-26 по рецепту дословно — `pnpm verify` **FAIL in 46.8 с** (`docs/template-state.md`, раздел 10). Корня два:

- Копия по рецепту — не git-репозиторий, а гейт нейминга (b17, #276, `0d91803e`) вне git закрывается отказом, а не пропуском (З4): красные `naming` и `test:hooks`.
- Базе сравнения контракта взяться неоткуда: с e48 (#215, `53531be2`) гейт без `--base <ref>`, `TURBO_SCM_BASE` или `origin/main` красный (`packages/contracts/scripts/openapi-compat.ts`) — шаг `openapi`.

CI этого не видит: канарейка копии (`tools/run-template-copy-canary.ts`) делает `git init -b main` с коммитом (строки 132–137) и ставит `OPENAPI_COMPAT_ALLOW_HEAD_BASE=1` (строка 169) — шагов, которых в инструкции нет, поэтому run канареек `45715253246` на том же коммите зелёный. Того же корня второе: пример команды пришпилен к `--vcs-ref=v0.1.0` (`docs/github-setup.md:103`) при живом `v0.2.0` — дословный запуск создаёт копию прошлого выпуска, с актуальным тегом — красный `pnpm verify`.

Задачу ведёт оператор (задача будет в режиме обслуживания): `tools/run-template-copy-canary.ts` — класс `deny` (`tools/protected-paths.json`). `docs/escaped-defects.md` — общий путь доски, в `touches` не указывается.

## Что сделать

1. Рецепт раздела 8 (`docs/github-setup.md`) дополнить тем, без чего `pnpm verify` в свежей копии красный, — не ослабляя гейты:
   - копия — git-репозиторий с первым коммитом (`git init -b main`, `git add -A`, `git commit`) — как у реального проекта и как уже делает канарейка;
   - явная база сравнения контракта (e48) из документированных каналов — `git fetch origin main` после пуша, `--base <ref>` или `TURBO_SCM_BASE`; `OPENAPI_COMPAT_ALLOW_HEAD_BASE=1` остаётся только у канарейки;
   - `--vcs-ref`: написать, откуда брать актуальный тег `v*`, чтобы пример не отставал от выпуска.
2. Канарейка копии идёт по документированному рецепту — по тем же командам, что раздел 8, без шагов, которых в инструкции нет. Либо рецепт выполняет один скрипт, который зовут и человек, и канарейка, либо канарейка сверяет свои шаги с текстом раздела 8; расхождение красит канарейку.
3. Строка в реестре пропущенных дефектов (`docs/escaped-defects.md`) — тем же PR, что и исправление: #215 и #276 смержены при зелёной канарейке копии, а дорога потребителя красная — дефект найден пробой из тега, не гейтом. В колонке «Появился ли гейт или канарейка» — канарейка по документированному рецепту; если она невозможна — «гейт невозможен, потому что …».
4. `docs/template-state.md`, раздел 10: результат пробы по новому рецепту и возврат заголовка на ✅ по условию из «Решений выпуска» (1).

## Решение

- Что выбрано: чинить рецепт и канарейку, поведение гейтов не трогать.
- Почему: обещание адресовано человеку, а зелёный CI стоит на пути, которого человек по инструкции пройти не может. Пропуск гейта нейминга вне git-репозитория и база `HEAD` по умолчанию — ослабление гейтов (З4; e48 закрыл именно его), оно запрещено.
- Альтернатива: научить гейты пропускать шаги вне git-репозитория и без базы сравнения. Отвергнута по той же причине.
- Условие возврата: если проба покажет, что явную базу контракта нельзя дать до первого пуша и рецепт с ней невыполним для человека, — развилка «пустая база для корневого коммита» выносится в отдельную задачу с ADR; `OPENAPI_COMPAT_ALLOW_HEAD_BASE=1` потребителю не отдавать.

## Критерии приёмки

- Свежая копия из актуального тега по разделу 8 дословно — без команд вне инструкции — проходит `pnpm install && pnpm verify`; проба записана в `docs/template-state.md`.
- Канарейка копии в CI идёт по тому же рецепту: шаг, убранный из инструкции, или расхождение канарейки с разделом 8 красят её (проверяется инверсионной пробой).
- В `docs/escaped-defects.md` — строка с канарейкой по документированному рецепту либо «гейт невозможен, потому что …».
- Заголовок раздела 10 `docs/template-state.md` — ✅.

## Связи
