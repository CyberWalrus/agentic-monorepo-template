# E21. Храповик test-count: WARNING на отчёт базлайна, которого нет

**Проблема.** Записи `test-count-baseline.json` для исчезнувших отчётов пропускаются молча: `tools/check-test-count.ts:244-246` делает `existsSync → continue`. При удалении пакета (прогон e6 без `apps/api`, 2026-11-21) храповик печатает «4 report(s) compared» без единого WARNING: запись `apps/api/reports/vitest.json` не сравнивается, а сверка с merge-base тоже зелёная — сам файл базлайна никто не правил. Храповик слепнет к удалению пакета, вопреки собственному принципу «битый базлайн — WARNING: храповик не имеет права молча ослепнуть» (заголовок того же файла).

## Что сделать

- В `tools/check-test-count.ts` при прогоне без `--affected` (полный прогон, как в job `static` и локально) отсутствующий файл отчёта из базлайна — WARNING: «baseline entry "<path>": report is missing (package deleted or report no longer produced)».
- С `--affected` поведение не менять: отчёт негейтованного пакета отсутствует легально (тот же контракт, что у `check-test-report.ts`).
- Тесты в `tools/test/` по соседям: отчёт есть — зелёный; отчёта нет без `--affected` — WARNING; с `--affected` — тихо.

## Критерии приёмки

- Копия без `apps/api`: `pnpm test:count` печатает WARNING про `apps/api/reports/vitest.json` и суммирует его в счётчик warnings (exit-код по-прежнему 0 — warning-only, статус гейта за человеком, З7).
- Полный workspace без `--affected`: ни одного нового WARNING.
- Прогон с `--affected` и отсутствующим отчётом негейтованного пакета: без WARNING.

Факт: скобка задачи «полный прогон, как в job static» не подтверждается CI — static гоняет только `turbo run test:hooks` (ci.yml:86–91), поэтому в static из 5 записей базлайна на диске есть только `reports/vitest-hooks.json`; unit гоняет `turbo run test $AFFECTED` (PR — `--affected`, merge queue/push — полный) и вызывает `pnpm test:count` без флага (ci.yml:141). Если CI не трогать, новый WARNING льётся в каждый прогон: в static — 4 «пропавших» отчёта пакетов, в unit на каждом PR — все не затронутые пакеты. Выбрано: добавить булев флаг `--affected` в `check-test-count.ts` (тот же контракт, что у `check-test-report.ts:34,44` — «в этом вызове отчёты могут легально отсутствовать»), в unit передавать `pnpm test:count $AFFECTED` (зеркало строки `test:report --from-turbo test $AFFECTED` выше), в static — литеральный `--affected`; локальный verify (`tools/verify-steps.ts:66`, шаг `test-count` после полного `turbo run test`) остаётся без флага — полный workspace, критерий 2 выполняется. Почему: WARNING обязан появляться ровно там, где прогон полный (локально, merge queue, push, nightly-сводка), и молчать там, где отчёты отсутствуют легально. Альтернатива (отклонена): CI не трогать — постоянные ложные WARNING в static и на PR убивают сигнал warning-only гейта. Условие возврата: если человек prefers другой wiring — откатить два hunk-а в ci.yml, чекер и тесты от него не зависят. Следствие: PR трогает защищённый `.github/workflows/ci.yml` — нужно ревью CODEOWNERS и label `gate-change-approved` (ADR 0002), это действие человека.
