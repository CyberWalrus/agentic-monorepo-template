# D8.3. Канарейка копии шаблона и исключение из З5

**Проблема.** Без проверки копия тихо ломается: ссылка на исключённый документ уронит `docs:check` уже в проекте, а `_exclude` протухнет после нового файла разработки (ADR 0008, «Проверка»).

Задача ведёт оператор: `touches` — `tools/**`, `.github/workflows/**`.

## Что сделать

- Канарейка копии (шаг `pnpm canaries` и/или job CI — форма по усмотрению оператора в рамках З6): во временном каталоге `copier copy` из текущего состояния, затем `pnpm install`, `pnpm verify`; проверяется содержимое копии:
  - копия непустая и полная — без `--vcs-ref=HEAD` copier молча создаёт пустую копию и завершается с кодом 0 (проба 2026-11-14, журнал d8);
  - в копии нет `docs/roadmap.md`, `docs/research/`, `backlog/`, `docs/template-state.md`, имени владельца шаблона (владелец для проверки — из ответов прогона или из CODEOWNERS шаблона);
  - в `copier.yml` нет `_tasks` и `_migrations`;
  - в копии есть снимки ruleset — все файлы из `.github/rulesets/` шаблона присутствуют в копии (generic-проверка, не по списку: чрезмерный `_exclude` не уберёт их молча);
  - в копии нет `.github/CODEOWNERS.jinja` — в проект попадает только отрендеренный `CODEOWNERS` (см. d8.2);
  - `.github/CODEOWNERS` соответствует `.github/CODEOWNERS.jinja` (владелец шаблона вместо плейсхолдера) — расхождение источников красит канарейку.
- Триггер на PR: bad-change в `copier.yml` должен красить проверку **на PR**, а не только в nightly — расширить paths-триггер `.github/workflows/canaries.yml` на `copier.yml`, `.github/rulesets/**`, `tools/copier-version.txt` либо сделать канарейку копии постоянным job внутри `gate` (`.github/workflows/ci.yml`). Сейчас canaries.yml триггерится по литеральному списку путей, в котором `copier.yml` нет, и `.github/workflows/**` канарейки не перезапускает — без этого пункта детекция деградирует до nightly.
- Версия Copier для установки — из `tools/copier-version.txt` (один источник с инструкцией, З10).
- Исключение из З5: из песочницы агента канарейка не запускается (PyPI вне allowlist доменов, ADR 0004), её гоняют CI и человек. Текст исключения — в `docs/architecture.md` (З5) **этим же PR**; способ локального запуска человеком — в `docs/` (место выбирает оператор: инструкция обслуживания шаблона).
- Ночные прогоны: канарейка копии входит в nightly, как остальные канарейки гейтов.

## Критерии приёмки

- Канарейка зелёная на PR с изменением гейтов и в nightly: копия проходит `pnpm verify`, `git ls-files` в ней не содержит `docs/roadmap.md`, `docs/research/`, задач шаблона и имени владельца шаблона; снимки ruleset и отрендеренный `CODEOWNERS` в копии есть, `CODEOWNERS.jinja` — нет.
- Поломка детектируется на PR: bad-change в `copier.yml` (добавлен `_tasks`, изменён `_exclude`) запускает канарейку и красит её; подсунутый в копию файл из `_exclude`-списка, убранный снимок ruleset, расхождение CODEOWNERS/jinja — канарейка красная (проверка на детерминированный bad-change, как канарейки других гейтов).
- З5 в `docs/architecture.md` упоминает исключение канарейки копии; выполняется правило З6 «гейт без канарейки может тихо перестать ловить» — канарейка самой канарейки не нужна: она сама является проверкой механизма, её живость доказывает PR с bad-change из критериев выше.

Почему: B1 — канарейки в каждом PR не нужны; paths покрывают все входы чекера (copier.yml, .copier-answers.yml.jinja, .github/rulesets/**, пара CODEOWNERS, tools/copier-version.txt), полный прогон — nightly и PR, трогающие `tools/**`. Условие возврата: появится класс файлов шаблона, влияющий на копию и не попадающий в paths, — добавить path или перейти к постоянному job.
