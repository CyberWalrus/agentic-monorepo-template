# C1.2. Реализация TaskRepository на Postgres за Drizzle

**Проблема.** Демо-домен хранит данные в памяти; шаблону нужен образец работы с постоянным хранилищем — области, где сгенерированный код ошибается чаще всего.

## Что сделать

- Реализовать `TaskRepository` на Postgres за существующим интерфейсом, контрактный набор из C1.1 гоняется против обеих реализаций.
- Drizzle закрепить на 0.45.x (1.0 не вышел), точная версия в `catalog:`; типы Drizzle не выпускаются за пределы репозитория.
- Эндпоинт сброса данных с настоящей базой пересмотреть: опаснее, чем с памятью.
- Перф API после подключения замерить и записать замер в «Журнал». Сам `perf-budgets.json` в этой задаче не меняется: потолок пересчитывает оператор отдельным PR по правилу ADR 0009 («Пороги»).

## Решение (2026-11-15)

Выбор делегирован человеком агенту в сессии 2026-11-15; принимается merge PR с этой правкой (ADR 0009, «Развилки в задачах»).

- **Postgres — контейнер Docker из закреплённого образа** (`postgres:17-alpine`, закрепить по digest), а не внешний сервис. Внешний сервис отклонён: ядро работает без SaaS (З12), сеть песочницы агента — только localhost и реестр npm (ADR 0004), а секрет подключения оказался бы доступен коду PR.
- **Запуск одинаковый локально и в CI: контейнер поднимает сам тест** через Testcontainers (`@testcontainers/postgresql`, версия в `catalog:`, обоснование зависимости — в PR). Порт случайный, поэтому два worktree не пересекаются (З9). Блок `services:` в workflow отклонён: это второй, только CI-шный способ запуска (З5) и правка `.github/**`, то есть режим обслуживания. В PR показать, что прогон проходит под песочницей: docker-сокет из allowlist ADR 0004, образ тянет демон.

- Контейнер стартует в `beforeAll` файла с Postgres-набором, а не в `globalSetup`: `**/vitest.config.ts` — защищённый путь, и задача его не трогает.
- Если Docker недоступен, Postgres-набор падает с объяснением, что запустить (З11). Пропускать его нельзя: `.skip` и условный пропуск запрещены.
- `server.ts` по умолчанию остаётся на in-memory; Postgres включается переменной `DATABASE_URL`. Поэтому `pnpm dev`, E2E и перф не требуют Docker до задачи C1.5.
- Если холодный старт контейнера выводит шаг unit за бюджет из `verify-budgets.json`, бюджет не поднимать: записать замер в «Журнал» и вынести Postgres-набор в отдельную задачу Turborepo для `--full` — это правка `tools/verify-steps.ts`, её делает оператор отдельной задачей.
- Альтернатива и условие возврата: PGlite (Postgres внутри процесса, без Docker) — если требование Docker станет узким местом локального цикла. Отклонён сейчас: это не тот движок, что в production (расширения, блокировки, параллелизм — см. C1.4).

## Критерии приёмки

- Контрактный набор зелёный против in-memory и Postgres в CI; миграции для тестовой схемы применяются автоматически.
