# C11.1. Обновление Oxfmt

**Проблема.** Oxfmt в каталоге — `^0.75.0`, в реестре — 0.79.0 (сверка от 2026-11-22, `docs/roadmap.md` «Стек»). Oxfmt всё ещё 0.x и может менять форматирование, поэтому обновляется отдельным PR (требование задачи C11; декомпозиция по ADR 0007 — один PR на задачу, план-ревью C11).

## Что сделать

- Поднять в каталоге `pnpm-workspace.yaml` `oxfmt: ^0.75.0` -> `^0.79.0`, переустановить lockfile.
- Прогнать `pnpm format`; поехавшее форматирование перечислить в PR как ожидаемое (если файлов много — остановиться и вынести человеку, см. условие возврата).
- `pnpm verify` зелёный; при изменении пикселей UI (маловероятно от форматтера) — ожидаемые визуальные изменения в PR, базлайны пишет человек.

**Условие возврата** (из развилки C11, план-ревью 2026-11-22): если формат-дифф 0.79 окажется широким и бессмысленным (сотни файлов без смысловых изменений) — не поднимать Oxfmt, вынести человеку. Oxfmt 0.x — форматтер, дифф форматирования сам по себе не дефект.

## Критерии приёмки

- `pnpm verify --full` зелёный; Oxfmt в каталоге `^0.79.0`; других изменений в PR нет (одна задача — один PR).

## Журнал

- 2026-11-22: реализовано — каталог `oxfmt ^0.79.0`, lockfile переустановлен, `pnpm format` на 502 файлах не изменил ни одного (условие возврата не сработало: дифф форматирования пуст). verify зелёный.
