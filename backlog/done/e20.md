# E20. Гейт «обязательные turbo-задачи присутствуют в workspace»

**Проблема.** `turbo run mutation` без единого пакета с задачей `mutation` завершается **exit 0** («No tasks were executed» — прогон e6 в копии без `apps/api`, 2026-11-21). В CI job `mutation` (`ci.yml:147`, команда на `:172`) зеленеет, `gate` (`ci.yml:378`) зеленеет: удаление `apps/api` агентом тихо выключает мутационное тестирование. Ни один PR-гейт этого не ловит; ловят только ночные канарейки (пишут в `apps/api/src/`) — не гейт. Та же дыра открыта для `e2e`, `test`, `build`: в PR с `--affected` пустой dry-граф легален как docs-only (`tools/check-test-report.ts:324-330`), merge queue поймает только e2e, mutation — никто.

**Решение.** Новый шаг verify — чекер состава: каждая обязательная задача (`build`, `test`, `e2e`, `mutation`) объявлена хотя бы одним пакетом workspace. Проверка по dry-графу turbo или по package.json пакетов — чекер решает; источник обязательного списка — один литеральный список в чекере.

## Что сделать

- `tools/check-required-tasks.ts`: для каждой задачи из обязательного списка найти хотя бы один пакет workspace с этой задачей (turbo `--dry=json`, как это делает `check-test-report.ts`); ноль пакетов — красный со списком «задача: ни одного пакета». Пустой workspace — красный целиком.
- Шаг в `tools/verify-steps.ts` (fast-волна, рядом с `boundaries`/`knip`) и явный шаг в job `static` `ci.yml`; скрипт `required-tasks:check` в корневом `package.json`.
- Канарейка в `tools/gate-canaries.ts`: bad-change «последний пакет с задачей `mutation` потерял задачу» красит новый шаг (гейт живой, З5).
- Тесты чекера в `tools/test/` по образцу соседних (ноль задач — красный, все на месте — зелёный, опечатка в списке — красный).
- Новый гейт попадает в deny `tools/protected-paths.json` тем же PR (ADR 0014) — иначе `tool-class` красный.

## Критерии приёмки

- Копия репозитория без `apps/api` (и без других пакетов с `mutation`): `pnpm verify` красный шагом required-tasks с сообщением «mutation: ни одного пакета», а не зелёный turbo-WARNING.
- Полный workspace: шаг зелёный; `pnpm verify --full` не меняет остального.
- Удаление задачи `mutation` из последнего пакета-носителя — канарейка красит шаг (прогон `pnpm canaries` локально).
- docs-only PR зелёный: гейт смотрит на состав workspace, не на прогон.

  1. **Что и зачем.** Turbo-прогон без носителей задачи завершается exit 0, поэтому удаление последнего пакета с `mutation`/`e2e` тихо выключает гейт CI.   2. **Механизм (развилка «Решение» — чекер решает): выбран turbo `--dry=json` без `--affected`** (по «Что сделать»), по образцу `turboGraph` (`tools/check-test-report.ts:158-176`): dry-граф — это ровно то, что turbo исполнил бы, включая root-задачи и валидность turbo.json; чтение package.json дешевле, но пропускает задачи, объявленные вне `scripts`, и не валидирует конфиг turbo. Условие возврата: если dry-спавн turbo станет заметной статьёй бюджета fast-волны — перейти на чтение package.json workspace-пакетов тем же литеральным списком.

Красная до изменения, зелёная после — по правилам ADR 0009. Проводку канарейки проверит общий инвариант `gates-canary` (steps против `allStepNames`).

Тест на защищённость: файл в `deny` (как в `verify-budgets.test.ts:98`).
  6. **Затронутые слои:** tools-гейты (verify-контур), CI, корневой package.json; продукт, контракты, UI, e2e — не трогаем. **Чего не делаем:** не меняем пороги существующих шагов, не запускаем `--affected` в чекере (состав ≠ прогон), не закрываем через ночные канарейки — именно PR-гейт.
