# B14. Канарейка build-шага

**Проблема.** Build — единственный блокирующий шаг verify без канарейки (tools/verify-steps.ts:75): среди 44 значений failedStep нет 'build'. З6 (docs/architecture.md:38) заявляет «каждый блокирующий шаг verify покрыт канарейкой»; тест инварианта это пропускает формально — build входит в union steps канареек «build,bundle» (tools/gate-canaries.ts:292-306, 477-492), но ни одна не требует красный build. Сценарий «красный build остался зелёным» (fail-open дрейф шага) не детектируется ничем: удаление шага поймает gates-canary.test.ts, исчезновение turbo-задачи — required-tasks, а именно прогон сломанного билда — никто. Попутно docstring tools/gate-canaries.ts:10 числит perf в исключениях — у perf уже есть канарейка.

## Что сделать

- Канарейка с детерминированно сломанным билдом (битый импорт/ассет в клиентском модуле apps/web), steps 'build', failedStep 'build'. Сборка offline — нестабильности от сети быть не должно.
- Исправить docstring исключений в tools/gate-canaries.ts:9-10 (perf больше не исключение).

## Критерии приёмки

- Канарейка красит build на грязной базе; негатив-контроль раннера зелёный на чистой базе; pnpm canaries зелёный.
- З6 согласован с фактом: build покрыт канарейкой (или исключение задокументировано в architecture.md:38).
- Docstring исключений в tools/gate-canaries.ts:9-10 не числит perf.

## Решение

Выбрана канарейка, а не исключение: З6 обещает покрытие, канарейка дешевле пересмотра обещания. Альтернатива: исключение в З6 + whitelist gates-canary.test.ts. Условие возврата: 2+ флака канарейки в ночных прогонах или неустранимая дороговизна против verify-budgets — переключиться на исключение по той же задаче.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — tools/gate-canaries.ts (deny).
