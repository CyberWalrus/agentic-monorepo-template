# D16. Прогон облачного клиента

**Проблема.** [ADR 0010](../../docs/adr/0010-cloud-agents.md) фиксирует статусы гарантий в облачном контуре: быстрая петля агента, изоляция вендора и захват задачи — «не определено», Lefthook и `AGENTS.md` — «по документации, прогоном не проверено». Перевести «не определено» в факт может только живой прогон облачного клиента (Codex Cloud, Copilot coding agent) — агента в чистом checkout на инфраструктуре вендора, без хоста и локальных инструментов.

## Что сделать

По методу задачи D2 (прогоны трёх локальных клиентов), но для облачного клиента: дать агенту эталонный сценарий (ветка → правка → `pnpm install` → `pnpm verify` → коммит → PR) и записать таблицу «клиент × шаг»:

- чистый checkout и `pnpm install --frozen-lockfile` в рантайме вендора;
- сеть до npm registry;
- Chromium для e2e и browser-тестов (`playwright install --with-deps chromium`);
- Docker для интеграционных тестов на Postgres — у песочниц вендоров его может не быть; отсутствие — ожидаемая находка прогона, а не противоречие;
- исполнение инструкций `AGENTS.md`;
- Lefthook: ставится ли `prepare` и срабатывает ли на коммите клиента — или вендор коммитит через API, минуя git-хуки;
- захват задачи на доске — ожидаемо недоступен (ADR 0010, ADR 0007), подтвердить фактическое поведение;
- PR облачного агента проходит `gate` и `gate-integrity`.

## Решение (2026-11-15)

Выбор клиента не оставляем вопросом. По умолчанию **Copilot coding agent**: включается на существующем GitHub-репозитории, без второй платформы. Запасной — **Codex Cloud**, переключение — если активация Copilot окажется недоступна на тарифе репозитория.

Прогон выполняет облачный клиент вне доски: человек включает агента и передаёт ему сценарий (активация — аккаунт или платный ресурс, не делегируется — [ADR 0009](../../docs/adr/0009-operator-delegation.md)); результаты записывает и файл задачи переносит в `done/` PR, в теле которого назван `d16` (ADR 0007, «Замыкание задачи»). Если шаг требует входа или активации — в ячейку пишется «нужен вход человека», задача закрывается с тем, что удалось проверить (прецедент D2).

## Критерии приёмки

- Таблица «клиент × шаг» по всем ячейкам из «Что сделать»: в каждой — результат прогона либо «нужен вход человека».
- Статусы ADR 0010 сверены с прогоном; расхождения исправлены в ADR тем же PR.

## Журнал

- 2026-11-15, ZCode-сессия: заведена из решения ADR 0010 (D15) — единственная задача, выведенная из таблицы «гарантия × контур»; других задач решение не требует (канарейка облачного контура отвергнута в ADR).
- 2026-11-22: закрыта БЕЗ прогона — решение человека в чате («купить лицензию не буду, давай как-то без этого»). Оба вендора из раздела «Решение» требуют платного ресурса: Copilot coding agent — лицензии Pro/Pro+/Business/Enterprise (пейволл подтверждён в браузере встроенного клиента: «No Copilot in the cloud access», репо-настройка видна, назначение задач — нет); Codex Cloud — подписки ChatGPT Plus/Pro/Team и недоступен из региона без VPN (гео-блок chatgpt.com, тот же класс, что у codex CLI в d2). Активация платного ресурса не делегируется и не выполняется (ADR 0009); человек решил контур не активировать. По протоколу файла задачи («задача закрывается с тем, что удалось проверить», прецедент D2): таблица «клиент × шаг» не создавалась — прогон не проводился, ВСЕ ячейки = «нужен вход/платный ресурс»; статусы ADR 0010 «не определено» остаются честными и помечены «прогон не состоялся» тем же PR. Условие возврата — в условиях пересмотра ADR 0010.
- 2026-11-22, «выпилить Copilot-зависимое из структуры проверки» (поручение человека): в файлах репозитория Copilot не упоминается ни разу — гейты детерминированы (.github/ grep пуст). Copilot-зависимое было только в настройках GitHub: «Copilot Autofix» висел On при отсутствии лицензии (работать не мог) — выключен в Settings → Code security тем же решением; Agentic autofix и AI Scan уже были Off. Контур проверки проекта от Copilot не зависит и теперь не содержит его следов.
