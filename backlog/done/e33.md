# E33. Храповик мутационных порогов не находит отчёты web и контрактов

**Проблема.** Ночь 45013082390 (2026-11-22), джоба «mutation ratchet (b2.4)» упала на шаге «check current scores»: `✗ web: missing-report — отчёта нет — храповик не имеет права молча ослепнуть (З11)` и то же для contracts. При этом `mutation (full)` в том же прогоне зелёная и заливает три артефакта (api, web, contracts) — значит, отчёты создаются, но fetch-state джобы храповика их не достаёт: имя артефакта, ретеншн, API list-artifacts или путь чтения разошлись с загрузкой. Ослепший храповик не поднимает пороги и не замечает их пробитие.

## Что сделать

1. Диагноз: сверить имена артефактов upload в джобе `mutation-full` с тем, что читает fetch-state в `check-mutation-ratchet.main.ts` (и с историческими артефактами прошлых ночных через API); найти коммит, после которого разошлись.
2. Фикс: имена/чтение приведены к одному источнику (константа имён артефактов в одном месте, а не строками в двух файлах).
3. Тест в `tools/test/` на соответствие имён upload↔read (тексты шагов workflow против констант ридера), чтобы дрейф ловился локально.
4. Диспетч ночной: джоба зелёная (или честный PR поднятия порога, если счёт вырос — по правилу ADR 0009).

## Решение

Единая константа имён артефактов, импортируемая и чекером; правка workflow остаётся текстом, но тест сверяет её с константой. Условие возврата: если окажется, что GitHub API артефактов возвращает иное (ретеншн/очистка) — переключить fetch-state на прямое чтение артефактов текущего прогона через `needs`/download последнего зелёного.

## Критерии приёмки

- Тест имён upload↔read зелёный.
- Диспетч ночной: «mutation ratchet (b2.4)» зелёная.
