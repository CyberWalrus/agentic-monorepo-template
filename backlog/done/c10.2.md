# C10.2. Плагин Claude Code из `.claude/` для других репозиториев

**Проблема.** Хуки и скилы лежат в `.claude/` и работают только в Claude Code и только в этом репозитории; шаблон не может переиспользовать собственную обвязку.

## Что сделать

- Упаковать `.claude/` (хуки-адаптеры, скилы, ревьюеры) в плагин Claude Code с манифестом.
- Плагин переиспользуется в других репозиториях без копирования файлов; пути к CLI из C10.1 резолвятся относительно репозитория-потребителя.
- Проба плагина в стороннем тестовом репозитории до merge.

## Критерии приёмки

- В чистом репозитории с подключённым плагином скил вызывается, хук блокирует ослабление гейта; в этом репозитории поведение не изменилось.

## Журнал

- Решение — плагин без копий файлов: корень плагина = сама `.claude/` (маркетплейс-источник `./.claude` в `.claude-plugin/marketplace.json` в корне репозитория). Каталоги `skills/` и `agents/` уже совпадают с раскладкой плагина, поэтому скилы и ревьюеры едут в плагин 1:1, без дублирования и дрейфа. Альтернатива (отдельный каталог `claude-plugin/` с копиями скилов) отвергнута: две копии контента расходились бы при каждой правке.
- Проводка хуков: манифест `.claude/.claude-plugin/plugin.json` перенаправляет поле `hooks` на `.claude/.claude-plugin/hooks.json`, потому что дефолтный путь `hooks/hooks.json` попал бы в защищённый `.claude/hooks/**` (deny, ADR 0014) — файл там создать нельзя. В `hooks.json` плагина нет адаптеров: команды вызывают CLI потребителя напрямую (`node "$CLAUDE_PROJECT_DIR/tools/hooks/<x>.ts"`) — это и есть «пути к CLI резолвятся относительно репозитория-потребителя»; поведение 1:1 с settings.json проверяется пробой (события, matcher'ы, таймауты; команды — замена пути, защитные — плюс `|| exit 2`).
- Fail-closed без адаптеров (З4): у защитных хуков (guard-bash, protect-paths, protect-result, stop-verify) команда в плагине оканчивается `|| exit 2` — эквивалент fail-closed обёрток адаптеров c10.1; без него репозиторий без `tools/hooks` падал бы «module not found» с кодом 1 = не блокирует. session-start и lint-changed-file — прямые, как их адаптеры. `pnpm verify`-сбой потребителя без CLI — exit 2, проверено пробой.
- Ограничения плагина (записаны в description манифеста и AGENTS.md): потребителю нужны шаблонные `tools/` (мир copier-копии, ADR 0008 — плагин дополняет copier); подключать плагин поверх скопированной `.claude/` нельзя — хуки задвоятся; скилы в сессии потребителя именауются с префиксом плагина (`agent-harness:feature-workflow`).
- Проба (`tools/probe-claude-plugin.ts`, `pnpm probe:plugin`): собирает чистого потребителя в `reports/plugin-probe/` (скелет из шаблонных `tools/`, без `.claude/`), подключает плагин project-скоупом (user-конфиг не трогается), проверяет инвентарь кэша, паритет проводки с settings.json, блокировки (`--no-verify`, запись в `perf-budgets.json` — deny; benign — проходят; без `tools/hooks` — exit 2) и headless-сессию `claude -p`, в которой модель вызывает Skill `agent-harness:feature-workflow`. Проба — не гейт: гоняется вручную при изменении `.claude/`; LLM-часть требует авторизации (`--skip-llm` для детерминированной части). Кэш плагина перед установкой инвалидуется — иначе install переиспользует кэш той же версии и проба проверила бы старые файлы.
- Итог пробы (merge-кандидат этой ветки): инвентарь 6 скилов + 8 ревьюеров; проводка 4 события 1:1; `--no-verify` и запись в perf-budgets.json запрещены, benign проходят, без tools/hooks exit 2; в headless-сессии потребителя модель вызвала `Skill agent-harness:feature-workflow` и пересказала раздел 1. Дополнительно зафиксировано живой сессией: Stop-хук плагина трижды блокировал завершение сессии в потребителе (`verify` красный из-за отсутствия раннера в скелете) и отпустил после третьего блока — контур работает в потребителе как в шаблоне.
- «В этом репозитории поведение не изменилось»: защищённые файлы (`.claude/settings.json`, `.claude/hooks/**`, `tools/hooks/**`) не менялись; новые файлы не подключаются никаким загрузчиком в этом репозитории (плагин никуда не установлен); `pnpm verify` зелёный. Инструменты разработчика в `tools/` (класс review): пробник `tools/probe-claude-plugin.ts` — entry-глоб knip `tools/*.ts`, гейтом не является.
- Без ADR: распределение обвязки решено в ADR 0008 (плагин — «дополняет copier, не заменяет», задача C10); новых архитектурных развилок нет. Для c10.3 (ZCode-адаптер): чек-лист c10.1 остаётся в силе; отсюда добавка — выходной протокол хуков в плагине и в settings.json идентичен (одни и те же CLI), проверять маппинг нужно только точку входа.
