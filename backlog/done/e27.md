**Проблема.** Untrusted PR-джобы (merge-ref, исполняют код PR) получают TURBO_TOKEN из environment cache-read прямо в env (ci.yml:49-53, 119-123, 174-178, 222-226, 274-278, 334-338, 386-390); код PR может прочитать токен и писать в remote-кэш напрямую, если серверная гарантия read-only сломана — из репозитория это не проверяемо. ADR 0017:23 принимает риск, критерий приёмки A7 (architecture.md:190) — разовая проверка «после подключения»; периодического контроля нет. Сейчас exposure спящий: оба environment пусты (gh api secrets total_count 0 — прогон линзы), merge_group remote не читает (ci.yml:40).

## Что сделать

- Канарейка (ночная/canaries): если секрет TURBO_TOKEN в cache-read заведён — подключиться к remote-кэшу и попытаться записать артефакт; успех записи = красная канарейка (токен пишет). Секрета нет — зелёная с warning (нет токена — нечего проверять).
- Ссылку на канарейку — в ADR 0017 и architecture.md A7: критерий приёмки становится периодическим, а не разовым.

## Критерии приёмки

- Канарейка зелёная на текущей конфигурации (секрета нет — warning, не падение).
- При фикстурном write-способном токене (локальный стаб) канарейка красная.
- ADR 0017 и architecture.md A7 ссылаются на канарейку; pnpm canaries зелёный.

## Решение

Выбрана периодическая проверка вместо разовой — компромисс A7 остаётся, контроль непрерывный. Альтернатива «одноразовые scoped-токены» отложена: изменения на стороне turbo-бэкенда. Условие возврата: заводится секрет TURBO_TOKEN — канарейка начинает реально проверять; если сервер умеет выдавать scoped-токены — заменить проверку записи на проверку scope.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — tools/**, .github/workflows/** (deny).

- **Решение 3 — чем проверять.** Прямой HTTP-запрос тем же `PUT /v8/artifacts/<hash>`, каким пишет turbo, а не прогон turbo: клиент с read-only токеном молча пропускает неудачную запись. Форма запроса (`teamId`, `Authorization: Bearer`) — по протоколу Turborepo remote cache и строкам установленного бинарника turbo 2.11.13 (`/v8/artifacts/`, `teamId`, `Bearer `). Живой захват запросов turbo локально не удался: turbo не дошёл до стаба на 127.0.0.1 (30 с таймаута) — в песочнице сессии loopback не работает между процессами (то же с `curl` и дочерним `node`). Расхождение протокола не даёт ложного зелёного: неверный путь или параметр ломает и read-пробу → exit 2. Условие возврата: при выборе бэкенда сверить форму с реальным сервером по первому прогону с токеном.
- **Решение 4 — вердикты (fail-closed, З11).** exit 0 `skipped` — секрета нет, предупреждение; exit 0 `read-only` — чтение 404, запись 401/403; exit 1 `write` — PUT принят (2xx); exit 2 `unknown` — конфиг неполный, токен не читает (401/403 на чтение), сервер недоступен или ошибается, иной код ответа. Отказом в записи засчитываются только 401 и 403: 400/404/405 — красный с телом ответа, классификатор расширяет человек. Отклонено: «зелёный на любом отказе PUT» — мёртвый эндпоинт выглядел бы защитой. Read-проба перед записью обязательна: отказ записи ничего не доказывает, если токен вообще не читает.
- **Решение 5 — заглушка.** Хеш случайный (sha256-hex, как у turbo) — у настоящего артефакта такой не встретится; GET 200 на него — красный. Тело PUT — gzip-октеты без токена; токен маскируется во всём, что пришло от сервера или из ошибки. Один повтор на сбой сети, таймаут и 5xx, чтобы ночная джоба не краснела от разового сбоя.
