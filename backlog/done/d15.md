# D15. Облачные агенты: статус гарантий и облачный контур

**Проблема.** Агенты работают не только в локальных клиентах (ADR 0007): Codex Cloud и Copilot coding agent запускаются в чистом checkout на инфраструктуре вендора — без интерфейса хоста, секретов человека и локальных инструментов. Аудит трендов 2026-11-14 назвал облачных агентов гэпом P1: защита gate-integrity (ADR 0002) действует и там, но контура для облачного запуска нет — не задокументировано, какие гарантии шаблона в облаке держатся, какие не определены и что от облачного контура требуется.

## Что сделать

- ADR 0010 с таблицей «гарантия × контур запуска» (локальный клиент, оператор, облако): детерминированные гейты, gate-integrity (ADR 0002), result-based защита (ADR 0003), песочница (ADR 0004), канарейки. Для облака у каждой гарантии явный статус «держится / не определено / не применимо» с причиной; ссылки на задачу C10 (контур L0 основного клиента) и D2 (прогоны клиентов).
- В ADR — решение: минимальный облачный контур (что обязано работать в чистом checkout без хоста: checkout → `pnpm install` → `pnpm verify --full`), что шаблон облачному агенту не обещает и условия пересмотра.
- Из решения вывести задачи (например, канарейка облачного контура — тронет `tools/`, значит, режим обслуживания) или записать в ADR, что задач не нужно, с обоснованием.

## Критерии приёмки

- ADR 0010 в `docs/adr/` содержит таблицу «гарантия × контур» по трём контурам и решение с условиями пересмотра; противоречий с ADR 0002, 0003, 0004, 0007, 0009 нет.
- Из решения выведены задачи с проверяемыми критериями приёмки и `touches`, либо в ADR записано, что задач не нужно и почему.
