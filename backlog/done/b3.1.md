# B3.1. CI — источник визуальных базлайнов с одобрением

**Проблема.** Базлайны обновляет человек только локально через Docker; на машине без Docker агент не видит визуальный дифф до CI.

## Что сделать

- При визуальном диффе CI-job выкладывает артефакт с новыми снимками и отчётом.
- Мейнтейнер одобряет их командой в комментарии PR (раздел «Решение»), после чего доверенный workflow коммитит снимки из артефакта в ветку PR.
- В сводку PR идёт список изменённых снимков и ссылка на отчёт.

## Подводные камни

- Workflow, коммитящий базлайны, проверяет автора команды и исполняется из доверенной базы (A1).
- Коммит с `GITHUB_TOKEN` не запускает CI: нужен токен приложения или повторный запуск.
- Рендеринг под эмуляцией amd64 отличается от нативного: источник истины — один, CI.

## Решение (2026-11-15)

Выбор делегирован человеком агенту в сессии 2026-11-15; принимается merge PR с этой правкой (ADR 0009, «Развилки в задачах»).

- **Одобрение — команда мейнтейнера в комментарии PR**, с SHA head-коммита: `/approve-visual <sha>`. Workflow на `issue_comment` исполняется из базовой ветки (З2) и принимает команду, только если автор комментария — глобальный владелец CODEOWNERS, а SHA совпадает и с текущим head PR, и с SHA артефакта. Проверку автора переиспользовать из `tools/check-gate-approval.ts`, а не писать вторую.
- Почему команда, а не ручной запуск workflow: одобрение остаётся в ленте PR рядом с отчётом о диффе (З11), а SHA в команде закрывает подмену снимков новым push между просмотром и одобрением.
- Отклонено: `workflow_dispatch` с номером PR. Проще по правам, но одобрение не видно в PR, а номер и SHA вводятся руками.
- **Само одобрение остаётся за человеком** и оператору не делегируется (ADR 0009, «Что остаётся человеку»).
- Расширение набора доверенных workflow требует своего ADR (заголовок `gate-integrity.yml`) и правки политики исполнения из `docs/github-setup.md`, п. 3 — политику в интерфейсе GitHub меняет человек.

## Критерии приёмки

- Канарейка: одобренный артефакт доезжает до ветки PR коммитом доверенного workflow; неодобренный — нет.
- Команда от автора не из глобальных владельцев CODEOWNERS и команда с устаревшим SHA не приводят к коммиту.
