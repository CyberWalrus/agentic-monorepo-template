# B9. `verify` как интерфейс агента

**Проблема.** Отчёт `verify` отдаёт агенту хвост вывода в 60 строк вместо адресной диагностики; с ростом репозитория понадобится режим затронутого; режим обслуживания сейчас выключает все хуки разом.

## Что сделать

- **Компактная диагностика.** Перейти на отчёты инструментов (JSON-отчёт Vitest, формат `agent` у Oxlint уже используется) и отдавать список «файл, строка, сообщение».
- **Режим затронутого.** Быстрый режим гоняет всё, пока это занимает секунду. С ростом понадобятся `--affected` и `--since`.
- **Быстрый цикл.** Vitest 5.1 добавил `--last-failed` и `--since-last-run`, их стоит дать агенту отдельной командой.
- **Режим обслуживания по областям.** Сейчас `disableAllHooks` выключает всё, включая линт после правки и `Stop`. Нужен файл, который создаёт человек или оператор (ADR 0009; обычному агенту запись запрещена), со списком путей, открытых на сессию — для оператора это пути из `touches` его задачи. Остальные хуки продолжают работать.
- **Шум.** `turbo run test` предупреждает об отсутствующих `outputs` у пакетов без покрытия.

## Критерии приёмки

- Падение проверки выдаёт список «файл, строка, сообщение» без хвоста сырого вывода.
- Режим обслуживания по областям: открытые пути не защищены, остальные хуки работают.

Turborepo локально отправляет телеметрию (`telemetry.vercel.com`; `TURBO_TELEMETRY_DISABLED` задан только в CI) — в песочнице это отказ сети в выводе. Knip выдаёт две подсказки по конфигу: `chrome-devtools-mcp` в `ignoreDependencies` и лишний entry `vitest.config.ts`. Кэширование `test:hooks` сюда не входит — это задача E1.
- 2026-11-22, захват b9 (`pnpm backlog start b9 --operator`), план до кода. Раздела «Решение» в задаче нет — развилки решаю сам и фиксирую здесь (ADR 0009):
  1. **`--affected`/`--since` откладываю.** Выбрано: не включать в этот PR — быстрый verify занимает секунды, критерии приёмки затронутый режим не проверяют, а `check-test-report.ts` уже умеет `--affected` для CI. Альтернатива: реализовать сейчас же. Условие возврата: быстрый verify перестал укладываться в бюджет времени (`verify-budgets.json`) или CI-прогонам нужен локальный затронутый режим.
  2. **Предупреждение turbo о нехватке `outputs`** правлю явными `outputs` там, где их нет (пакеты без coverage; пакетных turbo.json в репо пока нет — конкретику выбираю по поведению turbo 2.11 при реализации). Альтернатива: выносить coverage в отдельную задачу. Условие возврата: пакетные конфиги ломают хеш/кэш задачи `test`.
  3. **Телеметрию turbo глушу** `TURBO_TELEMETRY_DISABLED=1` в env спавна шагов verify (tools/verify.ts уже передаёт FORCE_COLOR/NO_COLOR). Альтернатива: персистентный `turbo telemetry disable` — машинно-локальный, шаблон его не воспроизводит.
  4. **Режим обслуживания по областям:** новый сессионный файл со списком открытых путей (создаёт человек/оператор, ADR 0009); его уважают protect-paths и guard-bash, остальные хуки (lint-changed-file, stop-verify, session-start) продолжают работать; `backlog doctor`/`inbox` должны показывать забытый файл; паритет `.claude/.claude-plugin/hooks.json` — тем же PR (`pnpm probe:plugin`).
