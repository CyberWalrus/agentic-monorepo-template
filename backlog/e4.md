# E4. `pnpm preflight` — проверка окружения с объяснением

**Проблема.** Требования к окружению разбросаны по документам и проявляются поздно и невнятно: версия Node не та — падает typecheck; Docker не запущен — падают интеграционные тесты на Postgres внутри `pnpm verify` с ошибкой Testcontainers; хуки Lefthook не установлены в worktree (дефект D11) — проверки L1 и L2 молча не работают; Chromium не скачан — падает browser mode. Новый человек или агент в новом клиенте (ADR 0010: облачный контур) тратит первый прогон на угадывание причины.

## Что сделать

- Команда `pnpm preflight` (не `doctor`: это встроенная команда pnpm) с режимом `--json`. Проверки, каждая с сообщением «что не так и какой командой исправить»:
  - Node против `.nvmrc`, pnpm против `packageManager`;
  - `node_modules` есть и соответствует lockfile;
  - git-хуки Lefthook установлены в этом checkout или worktree;
  - Docker отвечает (нужен для `pnpm verify` и `pnpm visual`);
  - Chromium для Playwright и Vitest browser mode установлен;
  - файл `.claude/settings.local.json` существует — предупреждение «режим обслуживания включён»;
  - `gh` установлен и авторизован — предупреждение, не ошибка: без него `pnpm backlog doctor` неполон.
- `preflight` — не гейт: в `pnpm verify` не входит и ничего не блокирует. Падение шага verify из-за окружения ссылается на `pnpm preflight` в подсказке.
- В `AGENTS.md`, раздел «Команды» и «Worktree»: первым шагом в новом окружении — `pnpm preflight`.

## Решение (2026-11-15)

- **Отдельная команда, а не шаг verify.** Почему: verify — про код, а не про машину; проверка окружения в гейте сделала бы гейт зависимым от хоста.
- Альтернатива: проверять окружение при `pnpm install` (скрипт `prepare`). Отклонена: установка не должна падать из-за выключенного Docker, а окружение ломается и после установки.
- Условие возврата: сессии чаще раза в неделю тратят прогон verify на ошибку окружения, не вызвав preflight, — тогда verify сам вызывает preflight при падении.

## Критерии приёмки

- На исправном окружении команда зелёная меньше чем за секунду.
- Тесты: неверная версия Node, отсутствующие хуки и недоступный Docker дают каждое своё сообщение с командой исправления; `--json` отдаёт список проверок со статусами.
