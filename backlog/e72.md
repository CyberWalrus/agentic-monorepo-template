# E72. D7 и общие документы: очередь из одной задачи

**Проблема.** D7 (ADR 0007; `touchesOverlap` в `tools/backlog-board.ts`) запрещает захват задачи, если её `touches` пересекаются с `touches` любой задачи в работе. Очередь держат две записи, которые есть почти у каждой задачи обвязки.

1. Условное замыкание гейта — `tools/protected-paths.json`, `tools/check-tool-class.ts`, `.claude/settings.json` — прописано «на случай нового файла гейт-контура» у почти всех операторских задач. Изъято из `touches` свободных задач тем же PR, что завёл эту задачу (у b17 и e27 оставлено: там создаются новые файлы гейт-контура, для них замыкание обязательно).
2. `docs/architecture.md` — незащищённый документ (класс null) с законами обвязки. Его объявляют 16 открытых задач (main 77323543): b17, e27, e35, e39, e40, e49, e55, e59, e60, e63, e64, e65, e66, e68, e69, e70 — документ для них предмет по тексту, изъять путь нельзя. Задачи захватываются строго по одной, независимо от того, какие разделы каждая правит; после мержа текущей задачи с этим путём первый же следующий захват запирает остальные.

Замер независимого ревью 2026-11-24 03:20 MSK (модель на `touchesOverlap` по файлам доски main): из 33 открытых задач вне работы D7 блокирует 25; захватываемы e57, e67 и e29 (оператору); держат e35 — 15 задач через `docs/architecture.md`, e45 — 13 через тройку замыкания. После изъятия тройки захватываемы также e42, e46, e48; мягкий список (эта задача) снимает остальные блокировки по `docs/architecture.md` — по тому же замеру ещё 9 задач. Для реестра `docs/escaped-defects.md` такая очередь решена списком `SHARED_PATHS` (PR #192): файл считается лежащим в `touches` любой задачи. Для `docs/architecture.md` это не подходит — реестр append-only, а правка законов обвязки обязана оставаться объявленной.

1. ADR `docs/adr/0023-d7-shared-document-paths.md`:

   - два вида общего пути: `SHARED_PATHS` (не объявляется, пересечений не создаёт — только append-only реестры) и мягкие пути (обязаны быть объявлены в `touches`, пересечений не создают);
   - критерий приёма пути в мягкий список: класс не `deny`, путь обязана править задача по записанному правилу, конфликт не задевает гейт-контур; пополняется только через ADR. `AGENTS.md` (класс review) в этой задаче не включается — назвать, при каком условии его рассматривать;
   - альтернативы: расширить `SHARED_PATHS` (отклонена — правка законов без объявления), изъять путь из `touches` задач (отклонена — документ предмет каждой из них), считать пересечение только по deny/review (отклонена — вернёт реальные пересечения по продуктовому коду, например e55 × e61, e62 × e54);

Записать альтернативу «устранить причину по З9: перечень ADR — строка на ADR или отсылка к `docs/adr/`, числа 3.1 — производные», выбор и условие перехода. ## Критерии приёмки

- Тесты красные на коде main и зелёные после правки: (а)–(г) и `fileInTouches` — `backlog-board.test.ts`; захват — `backlog-branch-lock.test.ts`; `next --operator` и `start --operator` — `backlog-operator.test.ts`. Ручные мутанты убиты (в «Журнале»): путь попал в `SHARED_PATHS` вместо мягкого списка — красит (в); фильтруется весь `docs/**` — красит (б) и (г); фильтра нет — красит (а) и тест захвата.
- Гейт не изменился: правка `docs/architecture.md` в дереве задачи без этого пути в `touches` красит `branch-scope` и называет ровно его — команда и вывод в «Журнале».
- Документы согласованы: ни в ADR 0007, ADR 0009, ADR 0023, `architecture.md` (3.11), `AGENTS.md`, скиле не осталось «пересечение по любому пути запрещает захват»; шаг `docs` зелёный.
- Очередь: замер до и после с командой в «Журнале» — сколько задач вне работы блокирует D7; перечислены освобождённые и пути оставшихся. Контрольные пары: e39 и e27 захватываются одновременно; e39 и e40 (общий `.github/workflows/nightly.yml`) — по-прежнему по одной; e65 и e66 — по-прежнему по одной.
- `pnpm verify --full` и `pnpm canaries` зелёные, или названо, кто их запускает; после правки скила — `pnpm probe:plugin` или запись, почему не запускался.

## Решение

Выбрано исключить общие незащищённые документы из счёта пересечений, сохранив обязанность объявлять их в `touches`: убирает очередь, не открывая правку законов без объявления. Гейт `branch-scope` не меняется — `touches` по-прежнему читаются из main, `fileInTouches` прежний.

Порядок входа: e72 сама объявляет `docs/architecture.md`, поэтому задачи с этим путём, не находящиеся в работе (e27, e39, e40, e49, e55, e59, e60, e63, e65, e66, e68, e69, e70, b17), тем же PR поставлены в `depends_on: e72`, а e66 — ещё и в `depends_on: e39, e40` (чинит ту же строку 3.4 и тот же перечень nightly). e72 захватывается первой среди них — после мержа e35 и e64, которые уже в работе. Если ADR 0023 отклонён или задача остановлена — тем же PR снять `depends_on: e72` у этих задач: иначе они ждут вечно.

Условие возврата: (1) один случай, когда автослияние `docs/architecture.md` дало неверный текст закона и это найдено после merge, — строка реестра, путь возвращается в счёт пересечений; (2) доля пар задач в работе, конфликтующих в этом файле, за 30 дней выше порога — порог называет человек в PR реализации (новый порог по ADR 0009 «Пороги» предлагает человек). Владельцу в PR вынести два момента: сужение условия возврата ADR 0009 («Очерёдность») и новый порог.

Задача ведёт оператор (режим обслуживания): `tools/backlog-board.ts` и `tools/test/backlog-*.test.ts` — deny.
