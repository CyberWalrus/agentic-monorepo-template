# E5. README по факту и раздел «Как этим пользоваться»

**Проблема.** `README.md` — первый документ для человека, и он расходится с репозиторием (сверка 2026-11-15):

- «`pnpm verify` ~1–5 с с кэшем» — фактически 7,1 с (до задачи E1).
- Контур L4 описан как действующий («всё то же на смёрженном состоянии»), но merge queue недоступна и строгая база выключена (задача A9).
- «Скриншот-тесты требуют Docker» — Docker нужен и для `pnpm verify`: интеграционные тесты API поднимают Postgres через Testcontainers.
- Контур L0 описан только для Claude Code, хотя основной клиент — ZCode, где L0 пока нет (C10.1, C10.3).
- Нет ни слова о том, как системой пользоваться: три роли (агент, оператор, человек), доска задач, фразы запуска сессий, что остаётся человеку. Это описано в `AGENTS.md`, `docs/roadmap.md` и ADR 0007/0009 — в документах для агентов.

Гейт `docs:check` это не ловит: он проверяет существование команд и ссылок, а не правду утверждений.

## Что сделать

- Привести «Быстрый старт» и таблицу контуров к факту. Для каждого контура — честный статус: действует, частично или не работает, со ссылкой на задачу, которая это закрывает.
- Перечислить требования окружения в одном месте: Node, pnpm, Docker (для чего именно), Chromium; для облачных клиентов — ссылка на ADR 0010.
- Добавить раздел «Как этим пользоваться» для человека: какие сессии запускать и какими словами («продолжай по плану», «ты оператор»), что делает каждая роль, что человек делает сам (approve, label последним шагом, merge, базлайны, секреты), где смотреть очередь (`pnpm backlog list`).
- Числа времени не дублировать из других документов: одно место правды — таблица 3.1 `docs/architecture.md`, README ссылается на неё.

## Что учесть

- E5 — единственный владелец `README.md`: задачи A9, E1 и E4 меняют факты, но README не трогают, чтобы файл не стал «горячим» (З9). Если они закрыты раньше — README отражает новое состояние, если позже — E5 пишет текущее со ссылкой на задачу.
- README едет в проект из шаблона (ADR 0008): не ссылаться на документы, которые не едут (`docs/roadmap.md`, `docs/template-state.md`, `docs/research/`), иначе `docs:check` в копии покраснеет.

## Критерии приёмки

- Каждое число и статус в README сверены прогоном или ссылаются на место правды; в PR — таблица «утверждение → чем проверено».
- Человек, не читавший `AGENTS.md`, по README понимает, какую сессию запустить и что от него потребуется.
- `pnpm verify` зелёный.
