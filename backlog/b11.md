# B11. Тесты хуков use-tasks: конкаренси оптимистики

**Проблема.** `apps/web/src/features/tasks/use-tasks.ts` — единственное место с нетривиальной логикой конкурентности на клиенте (guard `isMutating(...) === 1` в `refetchAfterLastMutation`, порядок `setQueryData` → `cancelQueries({ revert: false })` → `mutateAsync` → rollback), и для него нет ни одного теста: в фиче покрыты `task-cache`, `summarize`, `CreateTaskForm`, `TasksPage`, а сами хуки — нет. E2E покрывает happy-path: регрессия в guard'е (например, инвалидация на каждую мутацию, затирающая оптимистичное состояние) не поймается ничем до прод-гонки. Задача также готовит почву B2.2: без базовых тестов мутанты `use-tasks.ts` неубиваемы.

## Что сделать

- Браузерные тесты на deferred-промисах (паттерн уже есть в `TasksPage.test.tsx:22-30`): refetch между двумя мутациями не затирает оптимистичное состояние; ошибка мутации откатывает значение; после последней мутации выполняется ровно один refetch.

## Критерии приёмки

- Три сценария зелёные; инверсией guard'а в `use-tasks.ts` красится хотя бы один из них (проверить руками перед PR).
