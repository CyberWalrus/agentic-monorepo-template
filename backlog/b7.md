# B7. «Горячие» файлы: конфликты при параллельной работе

**Проблема.** Файлы, которые правит каждая фича, при десятках людей с агентами и merge queue дают поток конфликтов (З9): `apps/web/src/routeTree.gen.ts` (генерируется, но закоммичен), `packages/contracts/openapi.json` (генерируется), `packages/contracts/src/index.ts`, `apps/api/src/router.ts`, `packages/ui/src/index.ts`, `packages/ui/src/components.visual.test.tsx`, `perf-budgets.json`, `pnpm-lock.yaml`. Условие настоящей параллельности: пока каждая фича правит общие реестры, пути почти всех задач доски пересекаются.

## Что сделать

1. Производные файлы пометить в `.gitattributes`, завести одну команду `pnpm regen` и записать в `AGENTS.md`: конфликт в производном файле решается перегенерацией, руками его не сливают.
2. Решение человека: коммитить ли `routeTree.gen.ts` или генерировать его задачей Turborepo перед typecheck.
3. В реестрах (`contract`, `router`, barrel UI) держать одну строку на домен в алфавитном порядке и проверять порядок гейтом. Тогда конфликты тривиальны.
4. Визуальные сценарии разнести по файлам (B3), перф-бюджеты по маршрутам (A6).

## Критерии приёмки

- Конфликт в производном файле решается `pnpm regen`; правило записано в `AGENTS.md`.
- Порядок строк в реестрах проверяет гейт: канарейка с переставленными строками красная.
- Пересечения `touches` между задачами доски становятся редкими.
