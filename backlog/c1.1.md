# C1.1. Контрактный набор тестов репозитория задач

**Проблема.** `TaskRepository` имеет одну in-memory реализацию без набора тестов, который зафиксировал бы поведение интерфейса. Прежде чем добавлять Postgres, поведение нужно зафиксировать.

## Что сделать

- Собрать контрактный набор: один набор прогоняется против любой реализации `TaskRepository` (подстановка реализации — параметр набора).
- Набор покрывает: CRUD, порядок, граничные случаи статусов, поведение при отсутствии ресурса.
- Пока единственная реализация — in-memory, набор гоняется против неё.

## Критерии приёмки

- Канарейка: намеренно сломанная in-memory реализация (например, потеря порядка) красит контрактный набор.
