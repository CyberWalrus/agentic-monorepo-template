# D8.7. Синтетический потомок: проверка `copier update`

**Проблема.** Механика обновления (`copier update` переносит разницу версий, сохраняя правки проекта) не проверяется, пока обновлять нечего: с одним тегом потомков не бывает (ADR 0008, «Проверка» — «со второго тега»).

Задача ведёт оператор (задача будет в режиме обслуживания): `touches` — `tools/**`, `.github/workflows/**`. Блокировка снимается PR с доказательством существования второго тега (ADR 0007, «отложено»).

## Что сделать

- Расширение канарейки d8.3: во временном каталоге — копия из **предыдущего** тега, синтетическая правка «проекта» (например, строка в README), `copier update` до следующего тега, затем `pnpm verify`.
- Проверка: правка «проекта» переживает обновление; файлы разработки шаблона не приезжают повторно; демо-домен при обновлении не дублируется (решение d8); конфликт обеих сторон помечается маркерами, канарейка красная.
- Запуск — там же, где канарейка d8.3 (CI и человек; исключение из З5 уже записано d8.3).

## Критерии приёмки

- На втором теге канарейка потомка зелёная: правка «проекта» сохранилась, `pnpm verify` в обновлённой копии зелёные, повторно приехавших файлов разработки нет.
- Поломка детектируется: утерянная правка «проекта» или приехавший excluded-файл красят канарейку.
