# C1.2. Реализация TaskRepository на Postgres за Drizzle

**Проблема.** Демо-домен хранит данные в памяти; шаблону нужен образец работы с постоянным хранилищем — области, где сгенерированный код ошибается чаще всего.

## Что сделать

- Реализовать `TaskRepository` на Postgres за существующим интерфейсом, контрактный набор из C1.1 гоняется против обеих реализаций.
- Drizzle закрепить на 0.45.x (1.0 не вышел), точная версия в `catalog:`; типы Drizzle не выпускаются за пределы репозитория.
- Эндпоинт сброса данных с настоящей базой пересмотреть: опаснее, чем с памятью.
- Перф-бюджет API после подключения перекалибровать (`perf-budgets.json` — защищённый файл, правит человек).

## Критерии приёмки

- Контрактный набор зелёный против in-memory и Postgres в CI; миграции для тестовой схемы применяются автоматически.
