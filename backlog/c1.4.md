# C1.4. Изоляция unit/integration тестов на Postgres

**Проблема.** С настоящей базой каждый тест должен получать чистое состояние без общего сброса данных между параллельными воркерами.

## Что сделать

- Выбрать схему изоляции unit/integration: Postgres внутри процесса (PGlite) или база на воркер из шаблона.
- PGlite неполный (расширения, блокировки, параллелизм), поэтому контрактный набор обязан идти и против настоящего Postgres в CI — изоляция не отменяет C1.2.
- Схема изоляции описывается в `docs/`, чтобы фичи копировали её, а не придумывали свою.

## Критерии приёмки

- Два воркера гоняют integration-тесты параллельно без взаимного влияния; `SHARED_DATA_LOCK` для unit/integration больше не нужен.
