# B18. Пометки @critical: продуктовое решение

**Проблема.** Непомечены @critical: валидация пустого заголовка (tasks AC-3, tasks.spec.ts:46), pre-hydration (AC-5, :78), утечка /health (api-origin.spec.ts:23), not-found (route-states.spec.ts:4), оба a11y-скана (:5, :24), e2e-reporting (api-logs.spec.ts:19), визуальные и perf-сценарии. Эффект сегодня нулевой: тегирование файловое (tools/e2e-select.ts:197-209), а все spec-файлы фичи tasks и так содержат тег; сквозные фичи гоняются всегда. При появлении второй app-фичи непомеченные файлы той фичи начнут выпадать из PR CI при выборе E2E_FEATURES.

## Что сделать

- Решение по тегам принято (см. «Решение»): поставить `@critical` в `e2e/features/route-states/route-states.spec.ts` (not-found, :4) и `e2e/features/a11y/a11y.spec.ts` (оба a11y-скана, :5 и :24). `e2e/features/tasks/tasks.spec.ts` и `e2e/features/api-origin/api-origin.spec.ts` уже помечены (тег файловый, tools/e2e-select.ts:197-209) — сверить при захвате.
- `e2e/features/e2e-reporting/api-logs.spec.ts` не помечать — отказ с причиной записан в «Решении».
- В `.claude/skills/writing-tests/SKILL.md` дополнить инструкцию: тег файловый — помечай файл, если хотя бы один его тест критичен.

## Критерии приёмки

- Каждый путь из списка либо помечен @critical, либо в «Журнале» записан отказ с причиной.
- pnpm e2e зелёный; прогон tools/e2e-select.ts подтверждает, что помеченные файлы не выпадают из выбора E2E_FEATURES.
- В скиле `writing-tests` есть правило файлового тега.

## Решение

Решение принято агентом по прямому поручению владельца (23.11):

- `route-states/route-states.spec.ts` и `a11y/a11y.spec.ts` помечаются `@critical` — это пользовательские состояния UI (not-found и доступность): их выпадение из PR CI при выборе `E2E_FEATURES` оставило бы непроверенным то, что видит каждый пользователь при ошибочном URL или с ассистивной технологией.
- `e2e-reporting/api-logs.spec.ts` — отказ с причиной: инфраструктура отчёта, не пользовательский путь; его регрессия видна по самому отчёту CI.
- `tasks.spec.ts` и `api-origin.spec.ts` уже помечены.

Условие возврата: возражение владельца в PR или появление второй app-фичи — тогда теги пересматриваются до её мержа.
