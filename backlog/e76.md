**Проблема.**

- `.github/workflows/security.yml:70–72`: обёртка `zizmorcore/zizmor-action` пиннута по SHA, но вход `version` сканера не задан — джоба берёт актуальный релиз. 24.11.2026 так включился zizmor v1.32.0 с аудитом `ref-version-mismatch`: без единого изменения в репозитории джоба `zizmor` покраснела на всех PR, и поезд слияния простоял около двух часов (строка реестра от 2026-11-24 в `docs/escaped-defects.md`, лечение — PR #232).
- Формат комментария версий действий не защищён: в `main` 41 строка несла подвижный тег (`actions/checkout@<sha> # v7`, `github/codeql-action@<sha> # v3` и другие). zizmor замечает несоответствие только после того, как тег уехал на новый релиз, — то есть в момент остановки, а не до него. PR #232 перевёл комментарии на неизменяемые теги релизов, но новый пин (например, от Renovate при подключении нового действия — «When pinning, Renovate adds a comment to preserve the original ref») снова принесёт `# vN`.

Найдено ревью PR #232 (архитектура и здравый смысл, 2026-11-24).

## Что сделать

1. **Зафиксировать версию сканера.** В джобе `zizmor` задать вход `version` у `zizmorcore/zizmor-action` — точная версия. Путь обновления версии описать: либо отдельное правило Renovate (custom manager по `security.yml`), либо ручной PR по расписанию — выбор записать в «Журнале» с причиной. Обновление сканера становится PR, на котором прогон идёт до переключения.
2. **Упреждающий локальный гейт формата комментария.** Новый чекер `tools/check-action-pins.ts`: для каждой строки `uses: <владелец>/<действие>@<40 hex>` в `.github/**` комментарий после пина обязан называть неизменяемый тег релиза (`# vX.Y.Z`), а не только мажорную версию (`# vN`); локальное действие `./.github/actions/setup` без пина — разрешено. Красный на строке с `# vN`, зелёный на текущем дереве (после PR #232).
3. **Подключение гейта — тем же PR, по З5 и З6.** Шаг в `tools/verify-steps.ts`, job в `.github/workflows/ci.yml` и `needs` у `gate`, канарейка в `tools/gate-canaries.ts` (красная до изменения, зелёная после), бюджет времени; новый `check-*` — в `tools/protected-paths.json` (`deny`), в `KNOWN_GATES` `tools/check-tool-class.ts`, в `denyWrite` `.claude/settings.json`. Шаги `tool-class` и `sandbox` зелёные.
4. **Документы.** `docs/github-setup.md`, раздел 5: соглашение о комментарии версий (одно предложение добавлено PR #232) дополнить про зафиксированную версию сканера и путь её обновления. `docs/architecture.md` — строка о новом гейте.
5. **Реестр.** В строке от 2026-11-24 (подвижные теги в комментариях) графу «Появился ли гейт или канарейка» дополнить: гейт добавлен, имя шага.

## Критерии приёмки

- Тест чекера: строка `uses: …@<sha> # v7` красная, `… # v7.0.1` зелёная, локальное действие без пина зелёное; на текущем дереве шаг зелёный.
- Канарейка нового чекера красная до изменения и зелёная после (саботаж — до и после, числа в «Журнале»).
- В джобе `zizmor` задан вход `version`; путь обновления версии описан в `docs/github-setup.md`.
- `pnpm verify` зелёный; шаги `tool-class`, `sandbox`, `test:hooks` зелёные; бюджет времени шага — в `verify-budgets.json`.
- Ревью `architecture-reviewer` и `security-reviewer` пройдено: новый шаг не ослабляет ни один гейт и не замедляет `pnpm verify` сверх бюджета.

## Решение

Выбрано: зафиксированная версия сканера и локальный гейт формата комментария. Почему: останов 24.11 вызвали две вещи вместе — незакреплённая версия сканера (новые аудиты приходят без PR) и незащищённый формат комментария (гейт видит дефект только после сдвига тега). Альтернатива — подавить аудит `ref-version-mismatch` в конфигурации zizmor — отклонена: это ослабление гейта. Цена зафиксированной версии — новые аудиты приходят позже, на срок до следующего обновления; условие возврата по ней: если обновление сканера не удаётся провести отдельным PR дольше месяца — вернуть плавающую версию и записать причину в «Журнале». Условие возврата по гейту: если чекер даёт ложные отказы на легитимных пинах (действие без тегов релиза) — разрешить в чекере явную пометку с причиной, а не снимать проверку.

Задача ведёт оператор (создаёт новый гейт): `touches` — защищённые пути, режим обслуживания по ADR 0009; новый гейт — один PR (ADR 0014).
