# E40. Ночной test-count-ratchet: PR не создаётся, а ошибка замаскирована

**Проблема.** Джоба «test count ratchet (a10)» в `.github/workflows/nightly.yml:302-338` зелёная, а PR храповика не создаётся. Ночная 45166469990 (23.11, job 137664598522): базлайн поднят (apps/api 114 → 232, apps/web 71 → 93, packages/contracts 16 → 59, packages/preflight new → 27), коммит `a83bc87` уехал в `chore/test-count-ratchet`, затем `pull request create failed: GraphQL: GitHub Actions is not permitted to create or approve pull requests (createPullRequest)` — и сразу ложное `PR храповика уже открыт — ветка обновлена.` из `|| echo …` (`nightly.yml:335-338`). Первопричина — настройка Actions `can_approve_pull_request_reviews: false` («Allow GitHub Actions to create and approve pull requests» выключена): `gh pr create` с `github.token` запрещён. Маскирование двойное: `git push … || true` (:333) и `gh pr create … || echo` (:338) превращают любой отказ в success. Ветка обновляется каждую ночь без PR; на main базлайн попал только руками (#186, `3f0346b8`). Дефект прошёл все гейты a10 (PR #109) — строки в `docs/escaped-defects.md` нет.

Попутно, не исследовано: ключ `reports/vitest-hooks.json` в `test-count-baseline.json` остался `296`, тогда как шаг `test:hooks` в CI (job `static`) прогоняет 718 тестов.

## Что сделать

1. Настройку «Allow GitHub Actions to create and approve pull requests» не включать (решение владельца): автоматика с `github.token` PR не открывает.
2. Шаг «PR with raised baseline» — громкий и честный:
   - убрать `|| true` у первого push и `|| echo` у `gh pr create`;
   - отличать «PR уже открыт» (проверка `gh pr list --head chore/test-count-ratchet` до create: PR есть — ветка обновлена, это не ошибка) от любого иного отказа;
   - иной отказ, включая `GitHub Actions is not permitted to create or approve pull requests`, — exit 1 с сообщением: причина дословно и следующее действие человека («ветка chore/test-count-ratchet обновлена — PR открывает человек»).
3. Канарейка в `tools/test/test-count-ratchet.test.ts`: «PR создан или громкая ошибка» — отказ create, не являющийся «уже открыт», красит шаг. Если тесту проще пинить скрипт, чем inline-YAML, — вынести логику шага в тестируемый скрипт (выбор — в «Журнале»).
4. Проверить, почему `reports/vitest-hooks.json` остался `296` при 718 тестах. Гипотеза для проверки: джоба запускает только `pnpm turbo run test`, а `test:hooks` — корневой скрипт (`package.json:36`) вне графа turbo, отчёт в джобе не появляется. Если базлайн занижен из-за отсутствующего отчёта — починить источник отчёта; запись поднимается только вверх (update не понижает).
5. Привести описание храповика в `docs/architecture.md` (3.4: «открывает PR храповика») к фактическому контуру.
6. Замыкание: `tools/protected-paths.json`, `tools/check-tool-class.ts`, `.claude/settings.json` — правятся тем же PR, если появляется новый файл гейт-контура (шаги `tool-class`, `sandbox` зелёные).
7. Строка в `docs/escaped-defects.md` тем же PR: в графе «что добавлено» — канарейка из п.3.

## Критерии приёмки

- Прогон шага без открытого PR при выключенной настройке: exit 1, в логе причина отказа дословно и действие человека; ни «уже открыт», ни success.
- Прогон при уже открытом PR: ветка обновлена, шаг зелёный, сообщение правдивое.
- Канарейка из п.3 красная до правки шага и зелёная после.
- Причина записи `296` установлена и записана в «Журнале»; запись приведена к факту либо объяснена.
- `docs/architecture.md` не обещает автоматического открытия PR; строка в реестре добавлена; pnpm verify зелёный; шаги `tool-class` и `sandbox` зелёные.

## Решение

Громкая ошибка вместо тихой зелени: монитор, который не может выполнить действие, обязан быть красным и называть причину. Альтернатива «включить настройку Actions» отклонена владельцем: это разрешение автоматике создавать и одобрять PR ради одной джобы. Вторая альтернатива — PAT или токен App для джобы — новый секрет и новое доверие; не вводится. Условие возврата: если ручное открытие PR храповика станет узким местом (чаще одного PR в неделю) — вернуться к вопросу токена отдельной задачей.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — `.github/**`, `tools/test/**`, замыкание (deny).
