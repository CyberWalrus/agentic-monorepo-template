# E54. Toggle задачи: откат ошибки подменяет кэш устаревшим снимком

**Проблема.** `apps/web/src/features/tasks/use-tasks.ts:63`: при неудачном toggle откат ставит в кэш списка `previous` — снимок до клика (`rollbackTaskToggle(previous)`). Между кликом и откатом в кэш могли прийти свежие данные (фоновый refetch, другая мутация) — откат затирает их снимком: добавленная задача исчезает, изменённая возвращается к старому состоянию до следующего refetch. `cancelQueries` (:59) отменяет только refetch, начатый до мутации. Аудит владельца, 2026-11-23, «Средние → Домен и фронтенд». Строки в `docs/escaped-defects.md` нет.

## Что сделать

1. Регрессия в `apps/web/src/features/tasks/use-tasks.test.tsx`: во время мутации toggle в кэш списка приходит обновление (добавлена задача или изменена другая) → сервер отвечает ошибкой → после отката в кэше остались новые данные, а откатилась только одна задача.
2. Откат точечный: `setQueryData(listKey, (tasks) => rollbackTaskToggle(tasks, id))` от текущего состояния кэша; подмена снимком — только если текущего состояния в кэше нет. Логика — чистая функция в `apps/web/src/features/tasks/task-cache.ts` (юнит-тест в `task-cache.test.ts`).
3. Проверить соседние мутации фичи (создание задачи) на тот же шаблон «откат снимком» — результат в «Журнале».
4. Строка в `docs/escaped-defects.md` тем же PR.

## Критерии приёмки

- Тест из п.1 красный до правки (свежие данные затёрты) и зелёный после.
- Юнит-тест отката по текущему состоянию зелёный; pnpm verify зелёный.
- Осмотр соседних мутаций записан в «Журнале»; строка добавлена в `docs/escaped-defects.md`.

## Решение

Точечный откат от текущего состояния вместо подмены снимком: снимок верен только в мгновение клика. Мутационное тестирование не применимо — web `.tsx` вне мутаций по ADR 0022; защиту держит юнит-тест чистой функции. Условие возврата: если у TanStack Query для этого есть штатный механизм (контекст снаппота на момент мутации в `onError`) — использовать его и записать в «Журнале», поведение то же.
