# C12. Генератор openapi: корректные схемы ответов и кодов ошибок

**Проблема.** Два дефекта сгенерированного `packages/contracts/openapi.json` (аудит 2026-11-20, линза бэкенда):

1. `z.void()` у `tasks.remove` рендерится в всегда-ложную схему `anyOf: [{ not: {} }, { not: {} }]` — ей не удовлетворяет ничего, кодогенерация клиента даст мусорный тип.
2. 400 не документируется для публичных процедур: oRPC возвращает `BAD_REQUEST` при провале `CreateTaskInputSchema` (тест `app.test.ts:50-56`), но в спеке у POST /tasks только 200/403/500 — потребитель кодогенерацией получит неполный контракт.

## Что сделать

- Проверить опции генератора (`packages/contracts/scripts/openapi.ts`) для обеих проблем; если опции нет — минимальное обогащение спеки после генерации так, чтобы `openapi:check` оставался детерминированным.
- Рантайм не меняется: контракт в коде остаётся тем же.

## Решение

- **Сначала опции генератора, потом обогащение.** Почему: ручное обогащение — второй источник правды, который надо удерживать гейтом; опция держит один источник.

## Критерии приёмки

- Схема 200 DELETE — корректная; у POST /tasks и toggle документирован 400; перегенерация стабильна, `openapi:check` зелёный.

## Журнал

- 2026-11-20: заведена по итогам аудита обвязки. Связана с C6: C6 — гейт совместимости между версиями контракта, эта — корректность содержимого спеки на текущей версии.
