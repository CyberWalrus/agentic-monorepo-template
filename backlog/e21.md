# E21. Храповик test-count: WARNING на отчёт базлайна, которого нет

**Проблема.** Записи `test-count-baseline.json` для исчезнувших отчётов пропускаются молча: `tools/check-test-count.ts:244-246` делает `existsSync → continue`. При удалении пакета (прогон e6 без `apps/api`, 2026-11-21) храповик печатает «4 report(s) compared» без единого WARNING: запись `apps/api/reports/vitest.json` не сравнивается, а сверка с merge-base тоже зелёная — сам файл базлайна никто не правил. Храповик слепнет к удалению пакета, вопреки собственному принципу «битый базлайн — WARNING: храповик не имеет права молча ослепнуть» (заголовок того же файла).

## Что сделать

- В `tools/check-test-count.ts` при прогоне без `--affected` (полный прогон, как в job `static` и локально) отсутствующий файл отчёта из базлайна — WARNING: «baseline entry "<path>": report is missing (package deleted or report no longer produced)».
- С `--affected` поведение не менять: отчёт негейтованного пакета отсутствует легально (тот же контракт, что у `check-test-report.ts`).
- Тесты в `tools/test/` по соседям: отчёт есть — зелёный; отчёта нет без `--affected` — WARNING; с `--affected` — тихо.

## Критерии приёмки

- Копия без `apps/api`: `pnpm test:count` печатает WARNING про `apps/api/reports/vitest.json` и суммирует его в счётчик warnings (exit-код по-прежнему 0 — warning-only, статус гейта за человеком, З7).
- Полный workspace без `--affected`: ни одного нового WARNING.
- Прогон с `--affected` и отсутствующим отчётом негейтованного пакета: без WARNING.
