# C4. Логи API в отчёте Playwright при падении E2E

**Проблема.** Агент при падении E2E не видит логов API: причину на стороне сервера приходится угадывать по поведению интерфейса. То, что можно показать детерминированно, не показывается ничем (З11).

## Что сделать

- При падении теста логи API за время сценария прикладываются к отчёту Playwright (attachment). Записи отбираются по идентификатору запроса из C4.1, а не по времени: E2E идут параллельно.
- `pnpm verify --json` при красном шаге `e2e` называет путь к приложенным логам.

## Критерии приёмки

- При падении E2E артефакт отчёта содержит логи API этого сценария и не содержит записей соседних параллельных тестов.
- Канарейка: намеренно падающий сценарий даёт отчёт с непустым вложением логов.

## Журнал

- 2026-11-15: по итогам аудита задача сужена до доставки логов в отчёт. Структурные логи, идентификатор запроса и таксономия ошибок вынесены в C4.1 (свободна для обычного агента). Задача режима обслуживания (`tools/**` и конфиг Playwright под deny): ведёт оператор.
