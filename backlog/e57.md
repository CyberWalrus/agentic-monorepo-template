# E57. Контракт tasks: недостижимый 403 и молчаливая отбраска лишних ключей

**Проблема.** `packages/contracts/src/tasks.ts` (:12 и рядом):

- 403 описан для public-процедур, где он недостижим: public-доступ не требует владельца, `FORBIDDEN` бросать некому. Спека обещает ответ, которого сервер не даёт.
- `:15` `CreateTaskInputSchema = z.object({ title })` — `z.object` молча отбрасывает лишние ключи: клиент, отправивший `{ "title": "x", "extra": 1 }`, получает успех, поле исчезло.

Аудит владельца, 2026-11-23, «Низкие → Контракты». Строк в `docs/escaped-defects.md` нет.

## Что сделать

1. 403 снять с public-процедур; для процедур с проверкой владельца — оставить. Проверка на рантайме (`apps/api/src/router-divergence.test.ts`): у public-процедур 403 не возникает.
2. `CreateTaskInputSchema` → `z.strictObject` (или `.strict()`): лишний ключ — ошибка валидации, одинаково на клиенте и на сервере (одна схема). Это изменение поведения контракта: единственный клиент шаблона — `apps/web`; для проектов-потребителей — миграция по документации.
3. Перегенерировать `openapi.json`. Гейт breaking changes отреагирует на снятие 403 и на `additionalProperties: false` — это его работа: изменение проходит по процессу гейта (явная база или исключение с причиной в PR), а не отключением гейта.
4. Строка в `docs/escaped-defects.md` тем же PR.

## Критерии приёмки

- В `openapi.json` у public-процедур нет 403; у защищённых — есть (тест `openapi-spec.test.ts`).
- Тест контракта: `CreateTaskInputSchema.safeParse({ title: 'x', extra: 1 })` → `success: false`; `{ title: '  x  ' }` → `title: 'x'` (trim сохранён).
- `router-divergence` зелёный; сигнал гейта breaking changes либо отсутствует, либо разобран и оформлен по правилам гейта (запись в «Журнале» и раздел PR).
- pnpm verify зелёный; строка добавлена в `docs/escaped-defects.md`.

## Решение

Контракт описывает только достижимое и отказывает явно: молчаливая отбраска ключей прячет опечатки полей у клиента. Задача сама является изменением контракта — правки web, если понадобятся, зависят от неё. Условие возврата: если strict-режим входа ломает сценарий шаблона (сервер шлёт лишние поля) — сначала поправить отправителя, не возвращая молчаливую отброску.
