# E59. packages/ui: ни порога покрытия, ни мутаций

<!-- 2026-11-24: depends_on: e72 — работа вне доски, волна seed-D7. Задача объявляет docs/architecture.md; пока D7 считает этот путь пересечением (правка — задача e72), такие задачи захватываются по одной. e72 отклонена или остановлена — зависимость снять тем же PR. -->

**Проблема.** `packages/ui/vitest.config.ts`: два проекта (`unit`, `visual`), порога покрытия нет — `packages/ui` единственный пакет без порога. Мутации там невозможны по ADR 0022 (StrykerJS не поддерживает browser mode, `.tsx` вне мутаций). Итог: презентационные компоненты — единственный слой, где регрессию не держит ни один автоматический барьер. Аудит владельца, 2026-11-23, «Средние → Тесты и перф».

## Что сделать

1. Замерить покрытие unit-проекта `packages/ui`: проверить, что провайдер покрытия снимает данные в browser mode; если нет — записать в «Журнале» и выбрать инструмент (новая зависимость — только через `catalog:` в `pnpm-workspace.yaml` и при реальной необходимости).
2. Порог — по правилу раздела «Пороги» ADR 0009: на уровне факта с храповиком, не выше; значения по строкам, функциям и ветвям и их источник — в «Журнале».
3. Порог — в `packages/ui/vitest.config.ts` (deny `**/vitest.config.ts`); назвать в «Журнале» шаг verify, который считает покрытие и красит при снижении.
4. Дополнить ADR 0022: раз мутации для ui невозможны, покрытие — компенсирующий контур, с условием возврата из b19 (browser mode в StrykerJS — возврат к мутациям).

## Критерии приёмки

- Замер и выбранные пороги записаны в «Журнале» со ссылкой на правило ADR 0009.
- Снижение покрытия ниже порога красит соответствующий шаг verify (саботаж — в «Журнале»); на текущем дереве шаг зелёный.
- ADR 0022 дополнен; в `docs/architecture.md` порог отражён.
- pnpm verify зелёный; шаги `tool-class` и `sandbox` зелёные.

## Решение

Порог на уровне факта, а не «поставим 80»: порог выше текущего красит чистую базу и вынуждает либо ослаблять, либо писать тесты ради числа. Условие возврата: если провайдер покрытия в browser mode не запускается — задача закрывается записью «гейт невозможен, потому что …» в «Журнале» и правкой ADR 0022, а не ручной проверкой.

Задача ведёт оператор (задача будет в режиме обслуживания): touches — `**/vitest.config.ts` (deny, пороги покрытия).
