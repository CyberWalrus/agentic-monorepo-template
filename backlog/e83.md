# E83. Мутационный храповик красит собственный PR: тест apply-формата зашивает break=67

**Проблема.** Тест «apply: формат конфига сохраняется — меняется только число, oxfmt --check проходит» (`tools/test/check-mutation-ratchet.test.ts:572`) читает реальный `apps/web/stryker.conf.json` (`:577`; на `main` — `"break": 67`, `apps/web/stryker.conf.json:12`), а значения предложения зашивает литералами: `from: 67, to: 69` (`:591`) и ожидаемую замену `'"break": 67'` (`:605`). На ветке храповика (PR #289, head `4ac29de6`, `break` 69) apply отказывает: `replaceBreakInConfigText` требует ровно одно вхождение `from` (`tools/check-mutation-ratchet.main.ts:183-190`) и падает с «ожидалось ровно одно значение break=67, найдено 0 — конфиг не тронут» (`:187-188`). CLI выходит с 1, тест красный на `:603` (`expect(result.status).toBe(0)` → `AssertionError: expected 1 to be +0`). Следствие: шаги unit и static красные в прогоне 45648941820 на PR храповика (1 тест из 34), PR не проходит CI; после merge такой ветки тест красный и на `main` — у каждого следующего PR и в ночи.

Дефект прошёл все гейты и найден после merge: тест зелёный ровно до тех пор, пока конфиг на `main` равен 67, то есть с PR #142 (b2.4 — на него ссылается комментарий теста, `:574-576`) и правки e82. Нужна строка в `docs/escaped-defects.md` — тем же PR, что и исправление.

Остальные литералы в файле (`grep -n 'from: 67'` по `main@239aa09a`): ещё 16 строк с `from: 67` — `:174`, `:196`, `:229`, `:243`, `:253`, `:273`, `:629`, `:1160`, `:1190`, `:1212`, `:1238`, `:1259`, `:1286`, `:1308`, `:1324`, `:1336` — и две с `'"break": 67'` — `:615`, `:644`. По разбору ночи они работают на фикстурах (на упавшем прогоне красный только тест `:572`), но построчно не сверялись: какие из них читают реальный конфиг, а какие — фикстуру с собственным `break: 67`, неизвестно.

## Решение

- **Чинить тест, а не конфиг и не `apply`.** Конфиг на ветке храповика — порог, который поднимает только храповик (З7); требование «ровно одно вхождение `from`» — защита от чужого конфига (`tools/check-mutation-ratchet.main.ts:178-190`), её не трогать. Ошибка в тесте: он проверяет поведение на реальном файле, а ожидание выводит из числа, верного только на текущем `main`. Условие возврата: не предусмотрено.
- **`to = from + шаг`, а не фиксированное 69.** Значение `to` в тесте не предмет проверки: тест проверяет, что меняется только число и формат сохраняется. Любой шаг больше нуля это доказывает, литерал — снова ломается на следующем поднятии порога. Альтернатива — читать `to` из реального предложения храповика — отклонена: предложение появляется только в ночи, тест не может от него зависеть.
- **Альтернатива — не читать реальный конфиг, держать копию фикстурой в тесте.** Отклонена: тест существует ради формата реального файла (`:574-576`: `JSON.stringify` разворачивал короткие массивы и красил `format:check` PR храповика). Условие возврата: если разобрать фактический `break` реального конфига одной строкой станет нельзя (формат конфига изменится) — фикстура в тесте плюс отдельная проверка формата реального конфига через `oxfmt --check`.

Задачу ведёт оператор (задача будет в режиме обслуживания): `touches` — `tools/test/**`, deny (`tools/protected-paths.json:114`); режим обслуживания по ADR 0009. Условное замыкание в `touches` не объявлено: новых файлов гейт-контура задача не создаёт; понадобится — мини-PR расширения touches. `docs/escaped-defects.md` — общий путь (`SHARED_PATHS`, `tools/backlog-board.ts:281`), в `touches` не указывается. `touches` пересекается с отложенной b19 (`backlog/b19.md:6`) — b19 не в работе, захват не блокирует. Label и merge — поезд по поручению владельца.
