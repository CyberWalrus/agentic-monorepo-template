# D19. Документация: расхождения «цель-vs-реальность»

**Проблема.** (1) docs/vision.md:25 формулирует G2 «merge только через merge queue», а очередь недоступна на тарифе (github-setup.md:21-24, ruleset main.json:2, architecture.md:146,157); vision об этом не говорит ни слова (grep «тариф|недоступ|строг» — 0 совпадений); строгая база ruleset (main.json:29) даёт главный эффект L4, но не полный. (2) AGENTS.md:30 заявляет «~2–5 с тёплым кэшем» против собственных замеров 7.1 с / 7.6–10.4 с (architecture.md:146,153) и свежего прогона 12.2s (в задании, exit 0); доминирующий шаг test:hooks ~10.6s превышает весь заявленный диапазон. (3) З6 (architecture.md:38) перечисляет 2 исключения из «каждый шаг покрыт канарейкой», вайтлист кода содержит третье — tool-class (tools/test/gates-canary.test.ts:25); сообщение инварианта отсылает документировать исключения именно в З6, обоснование третьего живёт в комментарии кода и ADR 0014:49.

## Что сделать

- vision.md G2/L4: переформулировать под реальность («merge блокируется обязательными check'ами на смёрженном состоянии — строгая база ruleset; merge queue — при появлении тарифа») со ссылками на github-setup.md и ruleset.
- AGENTS.md:30 — актуальный диапазон, согласованный с architecture.md 3.1, либо прямая ссылка на 3.1 как единственный источник замеров; дальше держать синхронно.
- З6 — третье исключение tool-class с обоснованием (wiring-канарейка на test:hooks + фикстуры tools/test/check-tool-class, ADR 0014).

## Критерии приёмки

- grep «merge только через merge queue» по docs/vision.md пуст; недоступность очереди упомянута со ссылками.
- Числа AGENTS.md:30 согласованы с architecture.md 3.1; свежий прогон 12.2s попадает в заявленный диапазон.
- З6 перечисляет три исключения с обоснованием третьего; gates-canary.test.ts зелёный.
- pnpm verify зелёный, включая docs-гейт.

## Решение

Выбрано «правда сейчас + ссылки», а не «цель с пометкой»: доки читают агенты как описание системы. Для L4 допустима формулировка цели с оговоркой, в G2 «только через» заменяется. Альтернатива «гейт дрейфа AGENTS↔architecture» отклонена: избыточно для двух чисел. Условие возврата: при повторном дрейфе чисел — канарейка; при появлении merge queue на тарифе вернуть формулировку цели и обновить ruleset.
