# D17. Полнота setup-документации: read-only токен и третий check ruleset

**Проблема.** Два гейта держатся на настройках GitHub, которых нет в setup-документации (аудит 2026-11-20, линза гейтов/CI):

1. Анти-подделка check-run `bundle-delta` (`gate-integrity.yml:195-205` + `tools/check-bundle-gate.ts` выбирают последний завершённый check-run по имени; создать чужой может только токен с `checks: write`) работает, только пока стоит repo-дефолт «Workflow permissions: read-only». Дефолт можно перевернуть на уровне организации — защита молча исчезнет. В `docs/github-setup.md` требования нет.
2. Снимок `.github/rulesets/main.json` содержит два обязательных check из трёх (`gate`, `gate-integrity`): третий, `bundle-approval`, добавляется вручную после создания label (ADR 0013 — окно без блокировки сознательно), но в снимке нет ни комментария, ни шага в чек-листе. Потребитель шаблона «по снимку» тихо недополучает гейт: рост бандла не блокирует merge вообще.

## Что сделать

- `docs/github-setup.md`: обязательный шаг «Default workflow token = read-only» (такая же настройка «один раз после создания проекта», как ruleset) и шаг чек-листа «добавить bundle-approval в required checks после создания label».
- `$comment` в `.github/rulesets/main.json` рядом с `required_status_checks`: «третий check добавляется вручную по github-setup.md».
- Тест-канарейка содержимого: required checks в снимке и чек-лист в github-setup.md согласованы — следующий недокументированный ручной шаг ловится, а не теряется.

## Критерии приёмки

- Свежий `copier copy` + `docs/github-setup.md` доводят проект до полного набора обязательных check без чтения ADR; канарейка согласованности зелёная и красится при расхождении.
