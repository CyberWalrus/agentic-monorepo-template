# E32. Инверсионная канарейка perf не применяет патч — якорь дрейфовал

**Проблема.** Ночь 45013082390 (2026-11-22), джоба «perf canary (200 ms)» упала на шаге «apply 200 ms canary patch»: `tools/perf-canary-patch.ts` печатает «apps/api/src/tasks/repository.ts: якорь create() не найден — патч не применился», exit 1. Рефакторинги репозитория сдвинули/переименовали метод `create()`, якорь текстового патча устарел. Инверсионная канарейка (a6.1: +200 мс → perf обязан покраснеть) ослепла: мониторинг «гейт ловит регресс» не работает, и никто это не заметил бы без ночи.

## Что сделать

1. Обновить якорь(и) в `tools/perf-canary-patch.ts` под текущий `apps/api/src/tasks/repository.ts`; сообщение об ошибке должно называть искомый фрагмент, чтобы следующий дрейф диагностировался без чтения кода.
2. Добавить/обновить тест в `tools/test/`, который прогоняет apply+revert патча на настоящем файле репозитория (канарейка якоря: если файл дрейфовал — тест красный локально, а не только в ночной).
3. Диспетч ночной: шаг apply проходит, инверсионная проверка отрабатывает (perf-джоба в канарейке красная по замыслу, сама джоба канарейки зелёная).

## Решение

Текстовый якорь с внятной ошибкой оставляем (файл маленький, AST-парсер избыточен); тест на apply+revert — тот добавленный барьер, который ловит дрейф при каждом изменении repository.ts. Условие возврата: если якорь будет дрейфовать повторно после этой задачи — тогда переходить на структурный якорь (AST или regex по сигнатуре).

## Критерии приёмки

- apply+revert патча проходит в тесте tools/test/.
- Диспетч ночной: джоба «perf canary (200 ms)» зелёная (внутри неё perf-прогон честно красный).
