Механика. Выход 1 заложен по замыслу: печать действия человека и `commandFailed('gh pr create', …)` (`tools/check-test-count.ts:594-596`, выход — `:610-611`; `tools/check-mutation-ratchet.main.ts:984-986`, выход — `:1003-1007`). В ночи 45646832636 обе джобы храповика красные по этой причине — job 139319977703 и 139325383048 — и ночь красная. При уже открытом PR шаг выходит нулём с «PR #N уже открыт» (`tools/check-test-count.ts:554`, `tools/check-mutation-ratchet.main.ts:943`): красной ночь остаётся от публикации ветки до того, как человек откроет PR. ## Решение

- **Вариант А — по поручению владельца (25.11).** Дословно из чата владельца в ответ на вопрос о двух решениях: «выбери сам решение где от меня действий не нужно и ты сам можешь через браузер (встроенный там залогинен) все сделать что считаешь нужным». Настройка репозитория «Allow GitHub Actions to create and approve pull requests» включена агентом через веб-интерфейс по этому поручению (25.11 17:03Z; `gh api …/actions/permissions/workflow` → `default_workflow_permissions: read`, `can_approve_pull_request_reviews: true`) — отклонение варианта в e40 тем самым снято владельцем. Маршрут внутри задачи: (а) — после create запускать `ci.yml` диспатчем; (б1) — доверенный гейт не расширять, событие человека для `gate-integrity` остаётся; (б2) — отдельная задача на ADR, если остаточное действие станет узким местом (мера та же — чаще одного PR в неделю). Почему не Б: новый секрет и новое доверие (возражение e40 остаётся в силе — секреты за человеком). Почему не В: владелец просил решение, не требующее его действий.
- **Почему не оставить ручное открытие молча.** Мера из e40 — «чаще одного PR в неделю» — превышена за день, и с каждым новым храповиком ручных PR становится больше.
- **Альтернатива — не заводить вопрос вовсе** (продолжать открывать руками): совпадает с вариантом В, но должна быть записанным решением, а не умолчанием. Условие возврата при В: та же мера остаётся — вернуться, если ручное открытие снова станет узким местом (чаще одного PR в неделю).
- **А не свободен от кода и при (б1) делит работу с человеком; Б — по секрету.** У А нет нового секрета, но проверки сами не придут: `ci.yml` нужен диспатч с правом `actions: write` (правка `.github/workflows/nightly.yml`), а `gate-integrity.yml` — доверенный гейт, любое его расширение — предмет отдельного ADR (`docs/adr/0002-gate-integrity.md:36`; запрет в файле безусловный — `.github/workflows/gate-integrity.yml:4-5`). Без такого ADR (маршрут (б1)) А снимает руки с создания PR и запуска `ci.yml`, а `gate-integrity` приходит событием человека: на PR мутационного храповика label и так обязателен, на PR храповика числа тестов остаётся одно действие — synchronize либо закрыть и снова открыть. С ADR (маршрут (б2)) А убирает руки целиком, ценой расширения доверенного гейта — это архитектурная развилка, она идёт через ADR, а не через эту задачу. У Б новый секрет и новое доверие (возражение e40), зато `pull_request`-прогоны идут сами и гейт не трогается; label для deny-путей остаётся действием человека и при Б. Вариант — за владельцем. При А внутри задачи маршрут — (б1): гейт не трогается, остаточное действие то же, что уже названо для push (`tools/check-test-count.ts:54-60`, `tools/check-mutation-ratchet.main.ts:555-566`); (б2) — заводить отдельной задачей на ADR, если остаточное действие станет узким местом (мера та же, что у e40/e82, — чаще одного PR в неделю). Маршрут (а) и правки логики публикации — за исполнителем.
- **Очередность с e83.** Не пересекаются по `touches`; e83 до исправления блокирует merge PR #289, на исход e85 не влияет. При А правки могут пересечься с `touches` e83 (`tools/test/check-mutation-ratchet.test.ts` — канарейка текста шага публикации): браться после закрытия e83.

`touches` — `docs/architecture.md`: правится при А и Б, это мягкий путь, объявлять обязательно (ADR 0023), пересечением не считается. Защищённые пути задача правит и при А, и при Б; в `touches` их нет — добавит мини-PR расширения, когда выбран вариант и известен список файлов. При А: `.github/workflows/nightly.yml` (право `actions: write` и запуск `ci.yml` после create), `.github/workflows/gate-integrity.yml` (только маршрут (б2), после принятия отдельного ADR; при (б1) не правится), логика публикации `tools/check-test-count.ts` и `tools/check-mutation-ratchet.main.ts` с канарейками `tools/test/**` — deny (`tools/protected-paths.json:29`, `:74`, `:58`, `:114`). Условное замыкание в `touches` не объявлено: новых файлов гейт-контура задача заведомо не создаёт, появится — добавит мини-PR расширения. Label и merge — поезд по поручению владельца.
