# E36. Автотест устойчивости check-flaky-rate к отсутствию/битому flake.json

**Проблема.** Задача e31 чинит `tools/check-flaky-rate.ts` (устойчивость к отсутствующему/битому flake.json — сейчас падение стеком в check-flaky-rate.ts:140 на ночи 45013082390), но автотест не вошёл в её PR: путь `tools/test/**` вне touches e31, а гейт branch-scope (D7) читает touches из ссылки main (check-branch-scope.ts:8) — правка touches на ветке задачи не помогает. Fix C в e31 верифицируется ручными прогонами; DoD «новое поведение покрыто тестами» закрывается этой задачей.

## Что сделать

1. Тест `tools/test/check-flaky-rate.test.ts`: классификация трёх состояний — flake.json отсутствует, битый JSON, валидный отчёт. Отсутствие/битый → exit 1 с сообщением, называющим причину и путь (не стек); валидный → обычный путь чекера.
2. Режим обслуживания (tools/test/** — deny): maintenance.json с этой задачей и путём touches, окно включить/выключить по протоколу ADR 0009 с записью времён в «Журнал».
3. pnpm verify зелёный; PR обычным поездом.

## Решение

Отдельный маленький PR вместо расширения touches e31: PR в main по чужой задаче в полёте дал бы конфликт «изменил-vs-удалил» (e31 переносит файл в done/), а split сохраняет «один PR — один смысл». Условие возврата: если e31 ещё не смержена к моменту захвата — взять следующую свободную задачу и вернуться (depends_on это гарантирует).

## Критерии приёмки

- Тест классификации зелёный локально и в CI.
- pnpm verify --full зелёный.
