# E80. Шаг test: отчёты всех пакетов пишутся и при падении одного

**Проблема.**

- Шаг `test` — `turbo run test` без `--continue` (`tools/verify-steps.ts`, `turbo('test')`): после падения первого пакета turbo останавливает остальные, их vitest убит до записи `reports/vitest.json`. Диагностика упавшего шага (`tools/verify-diagnostics.ts`, `fromVitestReports`) видит только отчёты успевших пакетов.
- Канарейка «owner-процедура без строки сценария таблицы» ждёт сообщения теста `apps/api` (`access scenario row for tasks.evilOwnerProbe`) в доказательствах шага `test` (`tools/run-gate-canaries.ts`, `tripped`). Любой тест `packages/contracts`, который падает от зонда раньше, закрывает это сообщение: «test НЕ УПАЛ».
- Три случая за трое суток: 22.11 — флейк импорта TasksPage вытеснил сообщение из хвоста (b9); 24.11 — e57 добавила в `errors.test.ts` список процедур tasks с проверкой доступа, поезд стоял 21:07Z–22:33Z (строка реестра от 2026-11-25, лечение — зонд дописывается в список); 25.11 — e56 добавила в `packages/contracts/scripts/openapi-spec.test.ts` тесты с точными списками операций, та же картина на PR #250.
- Каждый раз канарейку чинят точечной правкой под конкретный тест; следующий тест с точным списком ломает её снова.

Найдено при сопровождении конвейера 25.11.2026 (два останова поезда за сутки).

## Что сделать

1. Сделать доказательства шага `test` независимыми от порядка пакетов. Варианты — выбрать в задаче и записать решение: (а) turbo `--continue` для шага `test` — упавший прогон идёт до конца, отчёты пишут все пакеты; (б) канарейка судит по отчёту своего пакета (`apps/api/reports/vitest.json`), а не по хвосту вывода.
2. Измерить цену: время упавшего прогона `test` до и после; бюджет шага в `verify-budgets.json` — по факту.
3. Закрепить канарейкой на проводку (З6): под мутации канарейки owner-процедуры дополнительно падает тест `packages/contracts` — вердикт канарейки «поймано», в диагностике оба падения. Красная до изменения, зелёная после.
4. Строку реестра от 2026-11-25 дополнить именем добавленного гейта; `docs/architecture.md` — предложение о том, как шаг `test` собирает доказательства.

## Критерии приёмки

- Под мутацией канарейки owner-процедуры с заведомо падающим тестом в другом пакете вердикт канарейки — «поймано», в `diagnostics.findings` шага `test` есть оба сообщения.
- Зелёный прогон `pnpm verify` не замедлился; упавший — не дольше бюджета шага.
- `pnpm verify` зелёный; шаги `tool-class`, `sandbox`, `test:hooks` зелёные.

## Решение

Выбрано: лечить класс, а не очередной тест. Почему: две правки канарейки под конкретные тесты за сутки — показатель, что причина в сборе доказательств. Развилка (а)/(б): (а) проще и помогает диагностике всех падений, цена — упавший прогон идёт до конца (все пакеты); (б) точнее для канарейки, но не чинит диагностику. Начать с (а), если цена упавшего прогона в бюджете; иначе — (б) и отдельная задача о диагностике. Условие возврата: если упавший прогон с `--continue` выходит за бюджет — снять флаг и записать замер.

Задачу ведёт оператор: `touches` — защищённые пути, режим обслуживания по ADR 0009.

## Журнал

- 2026-11-25 — задача заведена по двум остановкам поезда за сутки (e57, e56): канарейка owner-процедуры слепнет, когда тест другого пакета падает раньше.
- 2026-11-25 — выполнена лечением второго останова (PR из `main`, ветка `work/test-continue`; поезд смержил e56 с красной джобой `canaries`, и канарейка сломалась на `main`): вариант (а) — шаг `test` идёт с `turbo --continue` (`tools/verify-steps.ts`); замер под мутацией канарейки на `main` с тестами e56 — до 4,6 с (в доказательствах только падения контрактов), после 9,6 с (есть сообщение таблицы доступа «access scenario row for tasks.evilOwnerProbe is missing»), бюджет шага 90 с; канарейка проводки «шаг test останавливается на первом падении (turbo без --continue)» на `test:hooks` с тестом `tools/test/verify-steps.test.ts` (зелёный, под мутацией красный); строка реестра от 2026-11-25; предложение в З6. **Осталось дорожке:** проверить критерии приёмки по этому диффу и закрыть задачу; если зелёный `pnpm verify` замедлился сверх своего бюджета или упавший `test` вышел за 90 с — вернуть по условию возврата.
