# B2.4. Храповик мутаций для web и контрактов в nightly

**Проблема.** Храповик работает только для `apps/api`; для web и контрактов порог `break` статичен.

## Что сделать

- Расширить nightly-храповик (см. A3) на мутационные счёты web и контрактов: nightly предлагает PR с повышением, когда счёт устойчиво выше порога.
- Человек один раз поднимает `break` до фактического уровня с небольшим запасом, дальше порог движется только вверх.

## Критерии приёмки

- Канарейка: искусственно завышенный порог красит nightly-задачу; предложение PR формируется при устойчивом превышении.
