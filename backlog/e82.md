# E82. Ночной mutation ratchet: push без Chromium и замаскированный отказ create

**Проблема.**

- Джоба «mutation ratchet (b2.4)» (`.github/workflows/nightly.yml:133-219`) при устойчивом превышении порога не публикует предложение. Ночь 45619705671 (25.11, head `258e6e38`, job 139228345491): шаг «PR with raised thresholds» (`:200-219`) записал `apply: web apps/web/stryker.conf.json: break 67 → 69`, закоммитил и упал на `git push` (`:215`) — «error: failed to push some refs», exit 1. `gh pr create` (`:216`) не достигнут, ветки `chore/mutation-ratchet-web-contracts` на remote нет (API 404).

Хук исполняется дважды — на удаление ветки (`:214`) и на push (`:215`) — при `timeout-minutes: 10` (`:137`).

Класс описан в реестре (`docs/escaped-defects.md:51`, e40 — соседняя джоба); что в этой джобе маскировка осталась, записано с e40 (`backlog/done/e40.md:60`, `docs/architecture.md:217`, `docs/escaped-defects.md:68`) — задачи не было.

## Что сделать

Оба пункта — один шаг одного файла (`nightly.yml:200-219`), ведутся одной задачей.

1. **Chromium в джобе.** `:145` — `with: { playwright: 'true' }`, как в соседней джобе (`:297-298`), с комментарием причины. Хук остаётся исполняться дважды (`:214`, `:215`); бюджет `timeout-minutes: 10` (`:137`) сверить с замером — критерий ниже.
2. **Честный красный вместо маскировки — по образцу e40.** Логика публикации (ветка, коммит, push, отличие «PR уже открыт» от иного отказа, действие человека) переезжает из inline-bash в тестируемый вход существующего файла `tools/check-mutation-ratchet.main.ts` — новая подкоманда рядом с `check / fetch-state / decide / apply` (`:280-308`); шаг вызывает её. Убрать `|| true` (`:214`) и `|| echo` (`:219`); ни `continue-on-error`, ни иного глушения. «Уже открыт» узнаётся по `gh pr list --head … --state open` до create и повторной проверкой после отказа; иной отказ create, включая «GitHub Actions is not permitted to create or approve pull requests», — exit 1: причина дословно, состояние ветки по факту, действие человека с готовой командой `gh pr create --base main --head chore/mutation-ratchet-web-contracts …` — как в `tools/check-test-count.ts:594-597` и `:600-612`. Отказы `ls-remote`, `fetch`, push, `gh pr list` — тоже красные. Без force-push: ветка прошлой ночи без PR заменяется коммитом поверх текущего main, удаление — только когда ветка есть; при открытом PR коммит ложится на топ ветки (решения e40 — `backlog/done/e40.md:55-56`). Настройку Actions не включать и токен для джобы не заводить (решение владельца — `:306-311`).

Плюс канарейка проводки: джоба `nightly.yml`, которая делает `git push`, подключает setup с `playwright: 'true'` — иначе класс e31 вернётся со следующей джобой.

## Решение

- **Chromium ставить, хук не обходить.** Из «поставить Chromium либо иначе обеспечить push» выбрано первое: хук — часть контура гейтов (L1/L2, `lefthook.yml:1`), его пропуск в джобе (`LEFTHOOK=0`, `--no-verify`, `core.hooksPath`) AGENTS.md запрещает. Условие возврата: не предусмотрено; если pre-push в джобе станет дороже бюджета — разбирать время хука отдельной задачей.
- **Два push и два прогона pre-push остаются, timeout — от замера.** Ориентир — соседняя джоба «test count ratchet» с теми же delete и push и явным `turbo run test`: 66–133 с на всю джобу по пяти прогонам 23–25.11 (jobs 137664598522, 138197224781, 138466968231, 139187121378, 139224272015 — `startedAt`/`completedAt`); в двух прогонах 25.11 шаг дошёл до create (по разбору ночи), значит оба push с pre-push исполнены — 122 с и 133 с. Против `timeout-minutes: 10` (`nightly.yml:137`; у соседней джобы 20 — `:286`) запас более чем четырёхкратный. Альтернативы: сразу поднять до 20 — отклонена, значение меняется от замера; удалять ветку через API, чтобы хук шёл один раз, — отклонена, расходится с решением e40 (`tools/check-test-count.ts:533`). Условие возврата: замер после правки больше 5 минут — поднять `timeout-minutes` до 20, как у соседней джобы, либо убрать первый прогон хука удалением ветки через API.
- **Логика публикации — в существующем `tools/check-mutation-ratchet.main.ts`, не новым файлом и не inline-bash** (решение e40 — `backlog/done/e40.md:54`): новый файл гейт-контура входит в замыкание, его запись — правка трёх защищённых файлов вне `touches`; inline-bash хрупок — гонка «PR открыли между list и create», цензура токена в выводе. Канарейка читает текст шага из `nightly.yml` и исполняет его — переезд логики проверку не ослабляет. Условие возврата: подкоманде понадобятся экспорты ядра `tools/check-mutation-ratchet.ts` (в `touches` нет) — мини-PR расширения touches до правки.
- **Автоматика PR по-прежнему не открывает.** Включать настройку Actions или заводить PAT/токен App ради одной джобы — отклонено владельцем (e40 — `backlog/done/e40.md:45`). Возврат к вопросу токена — отдельной задачей, если ручное открытие PR храповика станет узким местом (чаще одного PR в неделю).

Задачу ведёт оператор (задача будет в режиме обслуживания): `touches` — защищённые пути — `.github/**` и замыкание гейт-контура `tools/` (`tools/protected-paths.json:29`, `:58`), каталог `tools/test/**` (`:114`); режим обслуживания по ADR 0009; условное замыкание в `touches` не объявлено — понадобится, мини-PR расширения touches. Label и merge — поезд по поручению владельца.
