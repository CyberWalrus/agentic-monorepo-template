# A10. Храповик числа тестов подтягивается сам

**Проблема.** `test-count-baseline.json` хранит число тестов, ниже которого `pnpm verify` предупреждает. Базлайн поднимает только ручной `pnpm test:count:update`, и за четыре дня он отстал: всё, что добавлено сверх базлайна, можно удалить без единого предупреждения.

| Отчёт                                    | Базлайн | Факт на 2026-11-15 | Удаляемо молча |
| ---------------------------------------- | ------- | ------------------ | -------------- |
| `apps/api/reports/vitest.json`           | 43      | 48                 | 5              |
| `apps/web/reports/vitest.json`           | 19      | 26                 | 7              |
| `packages/contracts/reports/vitest.json` | 7       | 7                  | 0              |
| `packages/ui/reports/vitest.json`        | 21      | 21                 | 0              |
| `reports/vitest-hooks.json`              | 273     | 290                | 17             |

Храповик, который не подтягивается, перестаёт быть храповиком: защита от удаления тестов (цель G2) слабеет с каждым PR, добавляющим тесты.

## Что сделать

- Nightly (`nightly.yml`) после зелёного прогона запускает `pnpm test:count:update`; если файл изменился — открывает PR с поднятым базлайном. Понижение команда уже отказывается записывать.
- PR храповика не требует label `gate-change-approved`: `test-count-baseline.json` не входит в защищённые пути, поднятие — ужесточение.
- В `docs/architecture.md` записать правило: числовой храповик поднимает автоматика, а не автор PR.

## Решение (2026-11-15)

- **Поднимает nightly отдельным PR**, а не автор в своём PR. Почему: требование «подними базлайн в том же PR» делает `test-count-baseline.json` «горячим» файлом — каждые два параллельных PR с тестами конфликтуют в нём (З9, задача B7).
- Альтернатива: блокирующая проверка отставания в `pnpm verify`. Отклонена по той же причине, плюс шаг сейчас намеренно warning-only.
- Условие возврата: PR храповика не принимается дольше трёх дней два раза подряд — тогда поднимать в PR автора и решать конфликт стратегией слияния для этого файла.

## Критерии приёмки

- Канарейка: при числе тестов выше базлайна шаг nightly формирует дифф с поднятыми числами; при числе ниже — дифф пуст и прогон сообщает об отказе понижать.
- После первого принятого PR храповика базлайн равен факту.
