# B5. Агентное ревью в CI: безопасность и стоимость

**Проблема.** `agent-review.yml` запускает модель дважды на каждый push (до 40 и до 60 ходов) с правами `pull-requests: write` и `issues: write`, инструментом Bash и выключенными хуками. Инструкции ревьюеров разрешают `pnpm verify`, `pnpm mutation` и запуск тестов, то есть исполнение кода PR рядом с ключом API. Текст и код PR являются недоверенным входом: внедрённая в них инструкция может заставить модель поставить label, выдать ложный вердикт или раскрыть секрет. При 5–50 людях с агентами стоимость растёт вместе с числом push.

## Что сделать

1. Ревьюеры в CI не исполняют код проекта: им доступны чтение и `git diff` / `git log`. Результаты `verify`, мутаций и покрытия они берут из артефактов CI.
2. Запуск по `ready_for_review` и по запросу, а не на каждый push.
3. Сетевой доступ job ограничить. Label одобрения гейтов проверять по автору (A1).
4. Вывод ревьюеров сделать структурированным, чтобы «блокер» можно было сопоставить с гейтом и показать аннотацией.
5. Явно задать модель и предел ходов для каждого ревьюера.

## Критерии приёмки

- Ревьюер в CI не имеет инструмента исполнения кода проекта; его инструкции это запрещают, а не просят «не делать».
- Ревью не запускается на каждый push автоматически.
- «Блокер» в выводе сопоставим с конкретным гейтом и виден аннотацией в PR.
