# A9. L4 без merge queue: проверка на смёрженном состоянии

**Проблема.** Контур L4 из `docs/vision.md` («всё то же на смёрженном состоянии») не работает. Merge queue для репозитория недоступна (пункт тарифа, `docs/template-state.md`), а в снимке `.github/rulesets/main.json` стоит `strict_required_status_checks_policy: false`. PR проверяется на своей базе, а не на текущем `main`: два PR, зелёных по отдельности, вместе могут дать красный `main`, и это увидит только CI после слияния. При параллельной работе агентов (ADR 0007) это не редкий случай, а ожидаемый: 45 PR за четыре дня. Цель G2 при этом заявлена как выполненная строкой L4 в `README.md`.

## Что сделать

- В снимке `.github/rulesets/main.json` включить `strict_required_status_checks_policy: true`: PR сливается только с веткой, обновлённой до текущего `main`, то есть `gate` проходит на смёрженном состоянии.
- Правило `merge_queue` в снимке оставить: оно включится, когда появится тариф. В `docs/github-setup.md` описать оба режима: с очередью (строгая база не нужна) и без неё (строгая база обязательна).
- В `docs/github-setup.md` добавить настройку «Automatically delete head branches»: ветки закрытых задач сейчас остаются в origin (на 2026-11-15 их шесть) и засоряют вычисление статусов доски.
- Строку L4 в `README.md` эта задача не трогает: её правит E5 (один владелец файла).

## Решение (2026-11-15)

- **Строгая база всегда, пока нет merge queue.** Почему: это единственный способ получить L4 без очереди средствами GitHub; цена — обновление ветки перед merge и повторный прогон `gate`, который на демо-домене занимает минуты.
- Альтернатива: оставить `strict: false` и добавить тревогу по красному `main` (issue с label `nightly-failure`). Отклонена: это обнаружение после факта, а цель G2 — не пустить.
- Условие возврата: обновление базы и повторные прогоны отнимают у приёмки больше 30 минут в день три дня подряд. Тогда — merge queue (смена тарифа) или тревога по `main` как временная мера.

## Критерии приёмки

- Снимок ruleset содержит `strict_required_status_checks_policy: true`; `docs/github-setup.md` описывает режимы с очередью и без и авто-удаление веток.
- Применение в интерфейсе GitHub — задача A9.1 (остаётся человеку).

## Журнал
