# D12. Канарейка контура установки: `pnpm install` при `.git`-файле ставит хуки

**Проблема.** D11 (PR #30) починила `prepare`: `lefthook install` ставится и изнутри worktree. Постоянной проверки на этот контур нет — правка `prepare` снова сделает обход `pre-commit`/`pre-push` молчаливой, и это тот же класс бага, что исходный. Все три ревьюера PR #30 (test-quality, security, product-logic) сошлись в одном миноре: регрессию сейчас ловит дисциплина, а не гейт.

**Почему не влезает в таблицу `GateCanary`.** `prepare` — не шаг verify: откат условия в нём не роняет ни один шаг `pnpm verify --only`. Канарейке нужна собственная позитивная проверка в раннере.

## Что сделать

- В `tools/run-gate-canaries.ts` добавить проверку: полный клон репозитория во временный каталог (`git clone --no-hardlinks`) → `git worktree add` → `pnpm install` только в worktree → assert `pre-commit` и `pre-push` в общем `.git/hooks` клона.
- Полный клон обязателен, а не worktree самого раннера: хуки общие на клон, в CI они уже поставлены установкой в корневом чекауте — проверка внутри канареечного worktree даст ложно-зелёный результат (обоснование в журнале `backlog/done/d11.md`).
- Дорого: один клон + install на прогон — подходит для nightly и для триггера на изменение `package.json`/`tools/` (сейчас canaries.yml триггерится на `tools/`/`.claude/`/конфиги гейтов; `package.json` добавить).

Задача режима обслуживания (`tools/**` под deny): начинает человек.

## Критерии приёмки

- Канарейка красная при подмене `prepare` в клоне на откат `[ -d .git ]` и зелёная на текущей версии; проверка проходит в nightly и локально (`pnpm canaries`).

## Журнал

- 2026-11-14: выделено из d11 (PR #30). Фикс сделан и доказан красно-зелёными прогонами в чистом клоне (журнал `backlog/done/d11.md`); канарейка вынесена отдельно: `tools/**` под deny, агенту нужен режим обслуживания.
