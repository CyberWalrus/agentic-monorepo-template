# E64. Версии инструментов: документы врут о «дословно из packageManager»

**Проблема.**

- pnpm `12.16.1` указан дословно в `README.md:27`, `apps/api/Dockerfile:10`, `apps/web/Dockerfile:10`, `docs/adr/0012-production-server.md:24` — против `pnpm@12.21.0` в `package.json:77` (`packageManager`). README и ADR 0012 утверждают «версия — дословно из packageManager»: человек, ставящий по README, получает не ту версию, и `pnpm preflight` отправляет его переустанавливать.
- `.nvmrc:1` — `26`, против `engines.node >= 26.13.0` (`package.json:75`): `nvm use` берёт последнюю установленную 26.x, на машине со старой 26.x минор не гарантирован.

Аудит владельца, 2026-11-23, «Средние → Документация» и «Низкие → Безопасность и стабильность».

## Что сделать

1. Источник правды один — `packageManager` в `package.json`; версию pnpm в README, обоих Dockerfile и ADR 0012 синхронизировать с ним.
2. `.nvmrc` — по решению в «Решении»; если меняется — прогнать `pnpm preflight` на новом значении и записать результат.
3. Пересобрать образы (`apps/api/Dockerfile`, `apps/web/Dockerfile`) с новой версией — команда и результат в «Журнале» (или честно «не запускалось» с причиной).
4. В «Журнале» — объяснение, почему расхождение пока не закрыто тестом (см. «Решение»).

## Критерии приёмки

- `git grep -n "12\.16\.1"` пуст; во всех четырёх местах версия равна `packageManager` (`grep -n packageManager package.json`).
- Решение по `.nvmrc` записано с причиной; `pnpm preflight` зелёный после изменения.
- Сборка Docker-образов с новой версией проверена или честно отмечена как не запущенная.
- pnpm verify зелёный.

## Решение

`.nvmrc` фиксируется на минимуме из `engines` (`26.13.0`): `nvm use` тогда ставит ровно поддерживаемую версию, а `engines` остаётся диапазоном для потребителей. Альтернатива — оставить `26` и проверять минор в preflight — дороже и всё ещё допускает старую установленную версию. Закрепление сверки «документы = packageManager» тестом — новый гейт: если расхождение вернётся, заводится отдельной операторской задачей (продуктовая часть и подключение гейта — два файла задач, ADR 0014). Условие возврата: владельцу нужна плавающая мажор-ветка в `.nvmrc` — вернуть `26` и перенести проверку в preflight.
